# 综合视频分析

综合分析不是把其他模式各写一小段，而是把镜头事实组织成一条可复核的证据链：先回答画面发生了什么，再回答结构如何变化，最后给出候选价值和下一步制作策略。读者往往只有几分钟，导语和段落标题就要交代完主线。

## 执行流程

1. 从用户重点确定这次要帮助谁做什么决定。未说明用途时，以创作者决定下一轮修改为默认；不自行补出平台、受众画像或传播目标。
2. 完整覆盖全片，建立分析分镜时间线；先记录可见事实，再按视觉目标、空间、主体和信息变化识别内容段落，写入 `scenes`。
3. 从具体镜头归纳关键判断。对影响优先级的判断，回看前后段落，寻找反例；有相反证据时收窄措辞。使用本次环境已有的概览、单帧工具核对疑点，不能把未调用的工具或未观察的区间写成已核验。
4. 建立高光与资产候选。只保留能说明用途的候选，不为覆盖所有栏目平均分配；综合结论不能由各专项结论的机械拼接产生。
5. 制作建议按对本次决定的影响排序，写明对象、动作和检查方法；没有成立的修改问题时给出保留或复核建议，不强行制造缺陷。
6. 成稿后只读导语与建议，再逐项核对证据、重复和未知。核心评价或修改建议若适用于任意视频，又没有本片对象、关系或条件的依据，应具体化或删除；必要的证据边界和通用术语保留。最后返回约定 JSON，不返回内部工作笔记。

## 工作边界

- 区分观察、解释、建议三种陈述：解释不得冒充事实，建议不得冒充已经执行的决策。
- 摘要覆盖全片结构，不只复述最醒目的开头或结尾。
- 无法由画面确认的对白、人物身份、因果、外部背景和传播结果不补齐。

## 成稿重点

- `title` 写出全片最核心的判断，例如“前半段靠产品特写建立信任，后半段节奏松散”。
- `summary` 用 2–4 句给出与本次用途有关的判断和依据；有明确修改问题时交代首要行动，没有时说明值得保留的机制与证据边界。不机械凑齐优点、缺点各一项。
- 各段落的 `title` 写成该段完成的事，连起来读就是全片提纲。

证据层级、字段写法、覆盖矩阵和建议优先级见 `references/evidence-synthesis.md`，通用文字要求见《报告写作规范》。
