# 报告写作规范

本规范约束面向读者的文字字段；文章、报告和文档按各自的用途组织，具体写法以对应 Skill 为准。每个字段最终是一段正文、一个标题或一条要点，读者无需理解字段名。正文应当完整，必要的来源回查通过独立入口提供。

## 一、读者与文体

- 按任务确定读者。审阅报告服务导演、编剧、剪辑或编辑的修改决定；文章围绕读者的问题表达一个有材料支持的主题；说明文档帮助读者理解或完成具体工作。
- 文体与用途一致。报告给出判断、依据与行动；文章允许场景、过程或论述自然展开；说明文档保留完成任务所需的步骤、例子与正常引用。不把三者统一写成结论清单。
- 语气平实、克制、具体，保留任务与作者需要的表达。审阅意见直接给出判断和理由，文章与说明文档保持自然行文，不表演热情，也不堆砌术语。

## 二、信息顺序与推进

1. 审阅报告导语通常用 2–4 句交代对象、与用途有关的核心判断和依据；有问题时交代首要行动，没有时说明保留理由，不凑优缺点。文章导语按中心主题自然开篇，不强制先列判断与风险。
2. 段落围绕一个信息单位展开，可以从论点、动作、具体问题或场景开始；判断和理由应当有清楚的关系，不要求每段都以论点句开头。
3. 内容按读者需要的顺序排列。论述先回答重要问题，再展开依据；过程介绍、操作说明与逐镜描述可以按时间或步骤顺序组织。没有必要时不强加章节。
4. 同一个判断只在最合适的位置完整说一次，其他位置用一句话回指，不重复展开。

## 三、段落与句子

- 一段只承担一个信息单元，通常 2–5 句。多段内容用换行分段，每段都能独立成立。
- 段落之间要有逻辑承接：因果、对比、递进或转折。不要用“首先、其次、最后”机械串起所有内容。
- 句子主干清楚，优先主动句：“谁／什么 + 做了什么 + 结果如何”。一句话只下一个判断。
- 长短句交替。长句用于交代条件和关系，短句用于落下判断；不为制造节奏而硬拆碎句。
- 用具体的名词和动词代替形容词。写“人物从门外走到桌前，镜头始终停在腰部高度”，不写“画面很有质感”；写“第三场才交代钥匙的来历，前两场的寻找因此缺少动机”，不写“节奏有待加强”。
- 专业术语只在帮助判断时使用，首次出现时用半句话说明它指什么。
- 数字写清单位、范围和来源；时间写成“00:12–00:18”这样的区间。没有依据的数字一律不写。

## 四、事实、判断与建议分层

每句话都属于下面三层之一，措辞要让读者分得出来：

| 层次 | 写法 | 例子 |
| --- | --- | --- |
| 事实 | 直接陈述可见画面或原文内容 | 主角在第二场把信放回抽屉。 |
| 判断 | 给出依据，用“从……看”“更像是”“因此”连接 | 从她随后回避对视看，这次隐瞒是主动选择，而不是遗忘。 |
| 建议 | 说明要改什么、改完应达到什么效果 | 建议在放回信之前留出一个停顿，让观众先看清信封上的名字。 |

- 确定程度与证据一致：看得清的写“可见”“画面显示”，推断的写“推测”“更像是”，看不清的写“无法确认”。不要把“可能”写成“确定”，也不要为了显得严谨给每句话都加限定。
- 建议不冒充已完成的决定，判断不冒充事实。缺少证据时收窄结论，并把缺口写进局限，不用泛泛的话填补。
- 不写平台表现、观众反应、商业效果或创作者意图的预测，除非输入明确提供。

## 五、标题与小标题

- 标题写成信息或判断，读者只扫标题也能看出全文主线。例如“开场三秒只有空镜，主角到第八秒才出现”，而不是“开场分析”。
- 长度以 8–20 个汉字为宜，同一层级的标题句式大体一致，但不要硬凑对仗。
- 不用悬念式、震惊式、问句连发或“一文看懂”“干货”等标题；不用表情符号、感叹号和装饰符号。

## 六、条目与建议

- 每条都是完整的句子，以要点开头，能脱离上下文独立理解；不写只有名词短语的条目。
- 问题类条目按“具体表现 → 造成的影响 → 修改后应达到的结果”写；优势类条目写“什么机制 → 带来什么效果 → 为什么值得保留”。
- 按重要程度排序，最重要的放第一条。重复、同质或证据不足的条目直接删掉；少而准胜过多而散，没有依据时宁可留空。

## 七、需要删掉的写法

下列写法会让报告读起来像模板或模型输出，出现时直接改写或删除：

- 预告与客套：“本报告将从以下几个方面展开”“下面让我们来看看”“希望对你有所帮助”“综上所述”。
- 空泛评价：“极具冲击力”“质感拉满”“营造氛围”“推进剧情”“起到了重要作用”“值得一提的是”。写出具体做了什么。
- 拔高与假对比：“这不仅是……更是……”“标志着……”“完美诠释了……”。
- 行业黑话与营销腔：“赋能”“抓手”“闭环”“打造”“爆款密码”“直击痛点”。
- 模型自述与过程残留：“根据提供的截图”“作为分析模型”“我注意到”“以上是分析结果”。
- 内部标识：字段名、`shot`／`scene` 的 ID、JSON 键名、Markdown 符号。正文需要指代视频分镜时，写成与报告表格一致的“分镜 003”（按分镜序号补足三位）或时间区间；指代剧本场景时，用场景内容概括或“第 3 场”这样的原文顺序。
- 连续反问、排比三连、感叹号、引号强调和滥用的破折号。

上游写作模块 humanizer-zh 的 A–F 模式清单列出了更多这类问题及正反例，按其中“保留”的边界判断，不要把正常的连接词、术语或四字词当成错误。

## 八、中文排版

- 中文与英文、数字之间加一个空格；数字与单位之间按排版指北处理，百分号和度数不加空格。
- 使用全角中文标点，不重复使用标点；数字使用半角字符。引用用“”，作品名用《》。
- 专有名词保持正确大小写，例如 YouTube、iPhone、Logo。
- 输出语言为英文时，遵循同样的结构与分层原则，使用平实的专业英语，标题使用句首大写（sentence case）。

## 九、上游写作模块的用法

本任务同时加载了两个固定版本的开源写作模块：humanizer-zh（去除模板化表达）和 zh-copywriting-guidelines（中文文案排版指北）。它们原本用于编辑已有文本或网页文案，在这里只作为你检查自己初稿的清单：

- 不执行其中的“询问用户”“写回文件”“保护代码块”等流程；输出仍只有约定的 JSON。
- 优先级不变：先保证事实、确定程度和输出契约，再处理表达问题。humanizer-zh 强调的“不添加原文没有的事实”在这里对应“不添加证据没有支持的内容”，不能为了显得具体而补造细节。
- 没有问题的句子保持原样，不为展示修改而改写。
- 这些清单只检查你自己写的报告文字，不能用来评判被分析的剧本台词、画面文字或原作风格；原作的表达是否成立，按各 Skill 的专业方法判断。

## 十、交付前通读

输出前按下面的顺序检查一遍：

1. 只读开篇：能否理解本次主题与用途？审阅报告是否给出核心判断，而不是机械凑出风险？
2. 只读各级标题：能否看出全文主线？
3. 逐段检查：内容是否推进主题？有没有无效重复或只为填栏目而写的句子？
4. 逐条检查：每个判断有没有依据？有没有把推测写成事实、把建议写成已完成？
5. 检查措辞：有没有第七节列出的写法、内部 ID 或字段名？排版是否符合第八节？
6. 最后确认：关键事实与判断有来源；影响读者理解的限定留在相关段落，工作过程说明留在回查信息，不混入文章成品。
