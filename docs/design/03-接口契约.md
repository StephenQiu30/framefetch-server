# 接口契约

- 唯一链路：路由与 Pydantic 模型 → `/openapi.json` → `@umijs/openapi` → `frontend/src/api/`（生成代码不手改）。App 使用从同一 OpenAPI 冻结的白名单快照。
- Web 业务 JSON 统一 `{code, message, data}`，成功 `code=ok`，保留真实 HTTP 状态；公开错误码由 `core/error_codes.py` 枚举，`api/errors.py` 唯一映射。204、文件流、Range、WebSocket、健康探针与指标遵循各自协议。
- 媒体内部接口按职责直接命名：`/internal/engine-catalog`、`/internal/context`、`/internal/contexts`、`/internal/inspect`、`/internal/download`、`/internal/tasks/{task_id}` 及其 `/cancel`；站点中继使用 `/internal/site-sessions/status`、`/internal/site-sessions/lease`，宿主来源使用同名会话接口与签名的 `/internal/browser/connect`、`/poll`、`/reply`、`/disconnect`。不保留带代际前缀的别名，HMAC 继续绑定实际请求路径，调用方与服务端必须配套发布。
- 独立 App 的 `/api/app/v1/auth/*` 使用直接响应与 Bearer 契约，不套用统一包装。修改需同步 `video-app` 验收。

## 通用解析契约目标（planned）

[设计 17](17-通用解析架构与实施计划.md)定义失败阶段、原因、作用范围和通用动作。IntentResponse 将区分连接来源、登录、人工验证、等待、更新结果与文件导入；当前 next_action 仅有 none/login，不能把目标写成已提供的接口。

目标以任务 action 接口替代仅登录的入口，resume 继续绑定原 authorization_id；服务内人工窗口入口由服务端返回，客户端不拼平台执行参数。实施时配套修改 Pydantic、生成 OpenAPI、Web API、App 白名单快照与生成客户端，旧入口同时删除。后端代码和生成契约是唯一接口定义，不在设计中维护另一份 DTO。
