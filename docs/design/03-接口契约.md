# 接口契约

- 唯一链路：路由与 Pydantic 模型 → `/openapi.json` → `@umijs/openapi` → `frontend/src/api/`（生成代码不手改）。App 使用从同一 OpenAPI 冻结的白名单快照。
- Web 业务 JSON 统一 `{code, message, data}`，成功 `code=ok`，保留真实 HTTP 状态；公开错误码由 `core/error_codes.py` 枚举，`api/errors.py` 唯一映射。204、文件流、Range、WebSocket、健康探针与指标遵循各自协议。
- 媒体内部接口保留 `/internal/engine-catalog`、`/internal/inspect`、`/internal/download`、`/internal/tasks/{task_id}` 及其取消／制品资源。HMAC 绑定实际请求路径，调用方与服务端配套发布，不保留旧别名。
- 独立 App 的 `/api/app/v1/auth/*` 使用直接响应与 Bearer 契约，不套用统一包装。修改需同步 `video-app` 验收。

## 解析契约

解析使用设计 17 第 3.6–3.7 节的 ExecutionContext 与失败分类；每个失败包含 layer、stage、gate、结构化 evidence 和诊断摘要。Pydantic → OpenAPI → Web 自动生成客户端；App 按自己的白名单冻结快照并生成客户端，禁止手改生成代码。
