# 解析意图

解析不在 HTTP 内同步等待，持久的 `download_intent` 是唯一入口。执行由 Temporal 负责（见[工作流编排](13-工作流编排.md)），解析规则见[解析引擎](14-解析引擎.md)。

## 生命周期

- **接单**：`public_input` 从分享文案中提取恰好一个 HTTP(S) URL，多个 URL 拒绝。规范化输入加密存储，与 owner 配额、Outbox 同事务提交，返回 `202`。`(owner, idempotency_key)` 唯一；重放只返回原意图，不重置截止时间。
- **状态机**：`queued → resolving → ready → handed_off`。取消或超期先进入 `cancelling`，确认 Runner 清理后才进入终态 `cancelled` 或 `expired`；其他失败为 `failed`。
- **截止**：每个 generation 120 秒，持久化在意图上；自动恢复与 Worker 重启不重置。
- **防迟到**：generation 与当前状态拒绝取消后、刷新后或已完成记录的迟到结果。
- **结果**：inspection、formats 与 `ready` 同事务提交。格式推荐顺序由后端规则决定（优先保留音轨，再按分辨率、容器、编码、帧率稳定排序）。只有 `access_decision=downloadable` 可确认下载；确认后经 `POST /api/downloads` 交接，同一 inspection 只能交接一次。
- **刷新**：inspection 过期后 `refresh` 保留原意图并递增 generation；重解析须核对平台内容标识与媒体类别，格式变化须用户重新确认，不自动下载，不复用失效直链。
- **来源发现**：微信公众号文章先做多候选发现，用户显式选择后再解析。

## 恢复与历史

- 客户端响应丢失时以同一幂等键只读查询，不重发 POST。
- 账号绑定的意图历史使用游标分页（单页最多 50），用于跨设备找回；不返回原始输入或幂等键。
- **个人处理记录**：`GET /api/download-intents/history/records` 对解析意图、视频分析、剧本文档解析与剧本分析做 owner 范围的联合查询。排序 `created_at DESC, id DESC, record_type DESC`，过滤先于 LIMIT，不做 COUNT，不建万能任务表。来源与结果可用性分别标注 `available`、`unavailable`、`unknown`、`not_applicable`；详情与写操作重新校验权限。Web 入口 `/history/activity`。
- **操作日志**：`operation_logs` 记录写请求生命周期（路由执行前写 started，完成后写一次结果）以及由 SQL 触发器在业务事务中写入的任务状态事件；不持有用户外键，不记录完整 payload。管理员入口 `/admin/operation-logs`。
