# 平台会话（复用当前 Chrome）

本页描述当前 Chrome 来源与既有会话设计；全平台目标新增的服务侧持久浏览器上下文见[设计 17](17-通用解析架构与实施计划.md)，尚未实施。公开账号平台首先匿名解析；元数据阶段的明确登录/挑战可以沿已批准路线读取当前 Chrome 对应站点会话，模糊 Cookie 提示和媒体探测失败不触发升级。策略选择的持久化按设计 17 后续阶段收敛。固定公开平台始终不读取账号材料；优酷、腾讯视频沿用已确认的个人权益线路。访问方式由 Registry 的 Profile 声明，没有第二份平台名单，也不因限流、网络失败、私有内容或 PO Token 错误切换到账号。

## 来源与传递

```text
当前 Chrome / MV3 扩展 → Python Native Messaging → source_app
                                                   ↓ 直接密封给 Runner
session-runner ← session-broker ←───────────────────┘
```

- 扩展使用 Chrome 官方 Cookie API，不读取 Cookie 数据库、钥匙串或复制 Profile。宿主安装从 Registry 生成站点权限与固定扩展身份；首次由用户加载，之后无需重复登录另一个浏览器。
- Native Messaging 注册只允许这个扩展的固定 origin。现有 Python 程序验证调用 origin 和有大小上限的原生消息帧，使用来源专用 HMAC 对 loopback RPC 签名。扩展没有业务、数据库、AI 或 HMAC 密钥，没有 content script、外部消息入口或任意网页触发导出入口。
- 来源只允许一个活跃 Chrome 连接，按任务请求单个站点，没有后台 Cookie 扫描、保活或持久材料缓存。请求有上限、时限和关联标识；断连、取消和过期回复被清理或拒绝。原生连接保持 MV3 运行，来源重启后重连。
- 来源再次检查域名、Cookie 必要字段、有效期和控制字符；外域材料被过滤。扩展保留 HttpOnly，通过普通 Cookie jar 无法表达的 partitioned Cookie 不导出。
- 会话代绑定来源启动、Chrome 连接和必要认证 Cookie 的 HMAC 摘要。普通分析 Cookie 变化不影响代；重新连接或认证 Cookie 变化保守地使旧上下文失效。它不是已验证的平台账号 ID。
- source_app 向 Runner 临时公钥密封材料，绑定任务、站点、会话代与截止时间。中继仅签名转发。Runner 在一次操作的 tmpfs 私有文件内使用，完成、失败、取消后清理。材料不进入业务数据库、队列、Temporal、API、日志或 AI。
- 视频号元宝适配器在当前 Chrome 已打开的元宝页中取得原有页面请求头方法的结果；不持有任意脚本入口，不复制 localStorage。未打开页面或页面不能生成有效请求头时明确失败。

## 解析与下载

公共账号 Profile 的 initial_access_mode 由已声明能力派生。匿名阶段不调用来源；明确认证失败才尝试 Profile 批准的公开账号能力。结果冻结最终执行上下文，后续下载按照该访问方式和会话代校验，不能临时换账号。个人权益不经过隐式升级；内容权益校验仍在实际提取之后执行。

Chrome 未连接返回 provider_session_not_ready，已连接但缺少认证材料返回 credential_required。需要人工处理时沿 PostgreSQL / Outbox / Temporal 保留的原任务等待和恢复；“在 Chrome 中打开平台”由扩展打开 Registry 固定地址，随后继续原任务。等待不占媒体执行资源，点击继续不等于平台接受登录。

限流保留 429 与既有冷却；网络、提取器或验证故障保留真实原因。不得将其改写为重新登录，也不保证有 Cookie 就能通过平台风控。

## 安装与验证边界

命令和首次加载扩展步骤见[根 README](../../README.md)。应用不需要新增数据库或前端框架，宿主继续使用已有 Python；浏览器扩展是新增产品组件。

健康接口仅证明来源服务就绪。传递、密封、断连与模拟材料测试只能证明技术链路；真实平台需单独验证 metadata、完整文件、重复使用和重启。没有实际登录与文件证据时不宣称无感解析已经通过所有平台验收。

## 自部署持久浏览器目标（planned）

部署端允许保存浏览器原生 Profile，Browser Runtime 负责页面状态、账号登录、人工验证和互斥。匿名浏览器使用临时上下文，批准的账号路线使用所选持久 Profile；每个平台注册 managed_browser 或 chrome_source 中的一个来源，变更来源使旧解析结果失效，不自动混用。

该目标扩展了当前只读 Cookie 的能力，并重新引入固定 Playwright/Chromium 的实际页面执行；不会读取或复制用户日常 Chrome 数据库。服务侧 Profile 不是第二套业务数据库，不保存任务。真实页面可用、媒体能移交和完整下载分别验证；有上下文绑定要求时必须由支持该要求的媒体路径执行，不能仅导出 Cookie 后宣称环境一致。

现有 Chrome 接入与密封传递按当前实现保留；managed_browser 不以桌面 Chrome 在线为前提，也不新增隐私审查或会话分发平台。平台正常登录/验证由部署者在服务端人工窗口完成，原任务沿共用 action/resume 契约恢复；完整生命周期、预算和实施条件见设计 17。
