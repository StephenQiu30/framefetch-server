# 平台会话（专用持久浏览器）

帧取使用已有 Playwright browser 依赖组，为每个已登记账号站点维护独立 Chromium Profile。用户在专用浏览器首次登录，随后通过 Playwright API 按需读取该站点材料；不读取日常 Chrome 的 Cookie 数据库或钥匙串，不复制用户 Chrome Profile，不新增应用 SQLite、Cookie 数据库或任务账本。公开平台不请求来源、不打开账号浏览器。

## 拓扑与职责

```text
session-runner → session-broker → source_app / BrowserSource → 站点专用 Profile
容器内网          签名转发桥        宿主机 127.0.0.1:19250
```

- `BrowserSource` 持有 Profile 的独占锁，使用固定 Playwright Chromium，保留 Chromium 自身沙箱。来源进程由 macOS LaunchAgent 管理；只接收来源专用配置，浏览器子进程不接收 RPC、业务数据库或 AI 密钥。站点与 Cookie 域沿用 Provider Registry，不接受任意 URL、脚本或 Profile 路径的 RPC。
- `session-broker` 是必要的网络边界桥。它只持有两段 HMAC 密钥，转发状态、登录控制和密封租约，不解密 Cookie，不连接数据库，不保存材料，不扫描或保活。移除中继会使当前隔离 Runner 无法访问宿主来源。
- 租约由来源直接密封给 Runner 的临时公钥，绑定任务、站点、来源代和时效。Runner 校验这些绑定，只在一次操作的 tmpfs 中使用 `0600` 临时材料，成功、失败与取消均清理。Cookie 不进入 API、业务库、Temporal、RabbitMQ、日志或 AI Worker。
- 媒体执行继续留在已有容器隔离边界，经 egress proxy 强制出网。macOS 外层网络沙箱与 Chromium 自身沙箱的组合验证失败，因此不把整个执行器移到宿主。登录浏览器配置同一出口代理、关闭 loopback 代理绕行及非代理 WebRTC；这是专用登录来源，不能将它宣称为与容器相同的强制网络沙箱，也不在其中执行通用媒体下载。

## 登录、等待与恢复

网页上的“打开平台登录”只对当前用户拥有、正在等待的原任务生效，打开对应平台专用浏览器。完成登录后点击“已处理，继续解析”；后端沿原任务经 Outbox / Temporal Update 恢复，再读取来源并实际解析，不把按钮点击当作登录成功。

每站点串行访问 Profile，最多同时打开三个登录窗口，闲置登录窗口 15 分钟关闭；普通读取只在操作期间启动无头浏览器并关闭。等待用户不占解析 Activity、媒体进程或账号执行锁。退出来源时关闭浏览器；再次启动复用 Profile。来源目录独占锁防止第二个进程并行操作同一组 Profile。

`source_generation` 由当前来源实例、站点与授权 Cookie 内容的 HMAC 摘要产生，不使用固定的 `1`。分析类 Cookie 轮换不改变来源代；授权材料改变或来源进程重启时保守失效旧解析上下文，要求重新解析。这个标记不是经平台验证的账号 ID；没有可靠主体检查时，不声称账号连续性已获证明。来源目录不是任务状态来源。

原任务最多等待 24 小时，共享剩余的 180 秒实际执行预算；重复恢复不延长期限。历史记录可找回待处理任务。取消与过期受业务 generation、fence 和等待 ID 保护。详细事务规则见[工作流目标](15-工作流与平台下载目标.md)。

## 页面状态

视频号现有元宝适配器需要页面生成的请求头。现在在同一个专用 Profile 内打开页面，复用其 Cookie 与 localStorage，再调用页面已有的请求头方法；不再新建临时 Profile、注入从日常 Chrome 读取的 Cookie。请求头单独密封，User-Agent 与现有适配器一致。平台接口漂移、验证挑战或无法确认完整非 DRM 文件时，仍必须如实失败。

## 错误和证据

| 情况 | 业务结果 |
| --- | --- |
| 未登录 | `provider_auth_required`，原任务等待处理 |
| 来源离线、浏览器启动失败或 Profile 被占用 | `provider_session_not_ready`，原任务等待处理 |
| 账号材料变化或已被平台拒绝 | `provider_session_expired`，旧上下文失效 |
| 平台挑战、受限内容、DRM 或链接失效 | 按平台实际原因报告，不循环换账号、出口或访问范围 |

来源 `/health` 和桥 `/health/ready` 只反映进程资源就绪。`source_cli check` 只证明来源可读，不证明平台接受会话。专用 Profile 的持久化、独占访问、重启失效已有受控验证；23 平台的真实 metadata、完整文件和生命周期须逐项验收，不能由模拟 Cookie 或 CI 替代。

安装、检查、首次登录与卸载命令统一见[根 README](../../README.md)。协议直接使用 `/internal/site-sessions/status`、`/lease`、`/login`，无旧路径别名。来源、桥、Runner、API 与 Worker 必须配套更新；已删除的 Chrome 读取实现不保留备用入口。
