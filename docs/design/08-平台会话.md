# 平台会话（现读本机 Chrome）

帧取是个人工作站。当前需要登录的平台从部署者本机 Chrome 按需读取登录态，操作结束后清理临时材料，不在数据库维护另一份平台会话。Chrome 接入是当前实现，不是不可替换的产品约束。

最新目标是复用已安装技术栈中的 Playwright，为平台建立专用持久 Profile，由采集运行时按需使用；不引入浏览器扩展、Native Messaging、SQLite 或第二份 Cookie／任务数据库。账号站点与材料要求已经统一收进 Provider Profile；浏览器来源替换尚未实施，下文描述当前仍在执行的链路。来源代、账号切换、首次授权与冷启动约束见[工作流与平台下载目标](15-工作流与平台下载目标.md)。

## 为什么这样设计

- 不维护数据库副本、保活浏览器和回写链，减少持久化故障与状态冲突。
- Cookie 来源由宿主机接入组件负责；broker 不猜测平台是否仍接受账号，Runner 的实际调用返回平台结果。
- 重新登录后的材料会在短期缓存过期后重新读取。读取成功仍不保证解析或下载成功；共享浏览器来源也不能消除平台轮换、挑战或账号失效。
- 来源故障只影响依赖该来源的操作，不通过预热或扫描阻塞 broker 进程启动。

## 拓扑

```
session-runner ──签名 RPC──▶ session-broker ──签名 RPC──▶ chrome_agent（宿主机 127.0.0.1:19250）──▶ Chrome Cookie 库 + 钥匙串
   (内网, 无出网直连)            (app_net + runner_rpc_net)      (LaunchAgent, KeepAlive)
```

- `chrome_agent`：宿主机进程，安装为 LaunchAgent（用户登录后自启、崩溃自动重启），命令统一见[根 README](../../README.md)。按站点 allowlist 的 Cookie 域读取唯一已登录的 Profile，多个 Profile 同时登录时拒绝猜测，需在 `SITE_SESSION_SOURCE_PROFILES` 指定。结果按请求方临时公钥密封返回；读取结果有 20 秒内存缓存。
- `session-broker`：无状态中继，不连数据库，不保存 Cookie 或会话解密私钥；持有两段 RPC 所需的 HMAC 密钥。仅提供状态查询和单任务密封租约，不接收 Cookie 轮换或失败上报，不运行后台扫描与预热计时器。
- `session-runner`：每次操作把租约写入 tmpfs（`0600`），结束即删。Cookie 不进入 API、RabbitMQ、日志、响应或 AI Worker。

## 页面签名请求头（视频号）

视频号分享通过腾讯元宝的官方解析接口 `get_parse_result` 取得非加密播放地址。该接口要求元宝登录身份（`hy_user`/`hy_token`）和元宝页面脚本（QIMEI SDK）按请求生成的签名头（`X-HY92`/`X-HY93`/`X-HY106` 等），无法离线计算。

- 仅在租约请求时生成，状态查询不生成。`chrome_agent` 用 Playwright 启动本机已安装的 Chrome（`channel=chrome`、无头、每次新建临时 Profile，从不使用你的默认 Profile），注入刚从你 Chrome 读出的元宝 Cookie，打开元宝页面，调用页面自己的 `getYbCommonHeaders` 与 `setContextualRequestHeaders`，随即关闭并删除临时 Profile。单次约 2 秒。
- 关闭自动化标记（`navigator.webdriver`），使页面上报的 `X-webdriver` 与普通 Chrome 一致；User-Agent 与 Runner 的视频号提取器一致。
- 请求头与 Cookie 分别密封，Runner 按既有 allowlist 过滤后使用。
- 不采用拦截 PC 版微信流量并解密视频的方案：它需要拦截网络流量和解密受保护媒体，超出项目边界。

## 错误语义

| 情况 | agent | Runner/API | 用户看到 |
| --- | --- | --- | --- |
| Chrome 未登录该站点、多个 Profile 未指定、或元宝页面拿不到登录身份 | 409 `credential_required` / `chrome_profile_ambiguous` | `provider_configuration_missing`，立即失败 | 请先在 Chrome 登录后重新解析 |
| 缺少完全磁盘访问或钥匙串授权 | 403 `chrome_permission_required` | `provider_session_not_ready`，在任务期限内重试 | 暂时读不到本机 Chrome 登录状态 |
| agent 未运行 | 连接失败 | 同上 | 同上 |
| 平台拒绝已登录会话 | — | `provider_session_expired` 等 | 请在 Chrome 重新登录 |

`chrome_agent check` 逐站点按 agent 的同一逻辑读取一次，打印来源状态和需要授权的程序路径；它不会验证平台接受会话。运行方法见[根 README](../../README.md)。

## 就绪与故障边界

- broker `/health/ready` 只表示中继资源已初始化；来源不可达或未登录在状态查询、租约请求时明确返回错误。
- 来源可读、平台接受会话、metadata 可解析、完整媒体文件可交付是不同证据，不能相互替代。
- `seed_revision=1` 是当前协议的固定来源标记，不是 Cookie 版本、账号指纹或账号切换检测。状态查询和租约之间仍需验证任务、站点、时效及密封上下文。
- Runner 取得租约后，不再为回写 Cookie 或上报失败联系 broker。原始业务异常直接向调用方传播，临时材料在成功和异常时均清理。
- 删除的内部协议字段与路由不保留兼容层，broker 和 Runner 必须配套重建发布。

## 边界

- 当前自动接入仅适用于 Chrome 所在的这台 Mac，依赖用户登录、磁盘读取与钥匙串权限；不承诺登录系统前即可执行账号任务。
- 浏览器扩展、Native Messaging、其他操作系统及其他凭据来源均未在本轮实现。替换来源时需独立验证安装、重启、权限变化和失效恢复。
- Cookie 存在不代表媒体可用；平台 challenge 仍可能让有效登录态无法解析，结果以真实文件为准。
