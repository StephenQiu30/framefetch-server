# 046 容器自持平台会话设计

日期：2026-09-29。当前实现与验收状态由 [Plan](../plan/046-容器自持平台会话Plan.md) 记录；需求编号见 [PRD](../prd/046-容器自持平台会话PRD.md)。本设计取代 044 中匿名／访客准备和宿主持续维护路线。

## 1. 设计原则

在线解析只使用部署会话，没有匿名／访客回退或兼容开关。本地视频和文档功能保持独立。一次导入后的正常 Cookie 轮换由容器维护；无法承诺永久免登录，验证码、撤销和真实登出需要部署者处理。Cookie 存在、HTTP 200、进程健康都不等于平台媒体可用。

## 2. 拓扑

- API／下载 Worker／Canary → `session-runner` → 单任务租约 → `session-broker`。
- broker 是容器中数据库会话密钥唯一持有者，通过签名 RPC 调用 `session-browser`，不访问外网。
- browser 使用 `site_session_profiles` 中每站点独立 Profile，没有数据库、密钥和队列权限。
- broker 与 Runner 共用 Redis 站点锁；浏览器、Runner 与 YouTube POT 使用受控出口。
- `media-runner`、`provider-guest`、`provider-guest-init`、`douyin-guest-runner` 已从开发与生产 Compose 移除。

默认部署单 broker。多 broker 的调度协调与租约返回状态持久化尚未实现，不能横向扩容 broker。Runner 可共享站点锁扩容，但同站点仍单并发。

## 3. 站点和准入

### 3.1 标识

已知平台复用 ProviderProfile 的主机与 Cookie allowlist；视频号用 `weixin.qq.com`，腾讯视频用 `v.qq.com`。PSL 只用于识别，不能把未知站点自动提升为支持的平台。IP、私网和公共后缀不能作为会话站点。

### 3.2 登录探针

YouTube 检查 `ytcfg.LOGGED_IN` 的明确布尔结果；抖音调用当前页面同源的 profile/self 接口并检查有效用户身份；元宝沿用页面身份及动态头插件，真实验收单独记录。其余仅有 Cookie 规则的站点不能进入 ready，需后续增加实际登录探针。未知、页面未完成初始化或无法判定，返回临时不可用而非登出。

### 3.3 内容权益

默认仅公开、免费、非 DRM 媒体；腾讯视频和优酷仍保持 032 的单视频权益边界。会话机制不扩大内容授权。

### 3.4 路由

静态站点规则选择 `operator_public` 或 `personal_entitled`，原解析意图在联网前持久化。执行时检查状态：没有会话、revoked、reseed_required 返回配置缺失；seeded／verifying／degraded 返回会话等待；ready 还必须通过 broker 当前运行期准入。显式 public／public_session 请求拒绝；历史数据中的策略值只用于记录原事实，不作为执行兼容路线。

等待不生成第二个意图、不重复预留配额。确认尚未调用媒体执行前的等待不消耗尝试数；180 s 绝对期限仍计时。已经进入 Runner 的执行失败仍受最多 3 次尝试限制。

## 4. 持久化

唯一结构源是 `backend/sql/schema.sql`，ORM 为 `SiteSessionRow`，不在本文复制 SQL。`seed_revision` 标识导入身份，`jar_version` 标识轮换，`next_check_at` 保存正常检查和故障退避时间；`state_changed_at` 只在状态变化时更新。API 只读取非秘密列。

新导入、轮换发布和撤销均条件写入，旧修订不能覆盖新导入或复活墓碑。密文绑定 site、seed_revision、jar_version。Profile 丢失时由最新加密 jar 重建；Profile 存在时重启先 keepalive，不把初始种子覆盖回去。

## 5. 状态与调度

`seeded → verifying → ready`；临时故障进入 degraded；明确登出、解密失败或连续认证失败进入 reseed_required；撤销进入 revoked。

- 普通检查：30 min 加 0～5 min 正向抖动，绝不提前到 25 min。
- 临时故障：60 s 起步退避，最大 30 min；429 最少 5 min。退避写入数据库，重启不绕过冷却。
- 网络、浏览器不可达、403／bot challenge 不增加认证失败次数；只有明确的 credential_expired／credential_rejected 计入连续 3 次或认证降级 24 h 门限。
- broker 启动不信任持久 ready：立即校验该站点；浏览器进程公钥是运行期身份，每次扫描及发放租约前核对，改变或不可达立即清空运行期准入。
- 开始维护即阻止新租约；等待现有媒体释放站点锁后才维护。锁键为站点而非导入修订，重新导入也不会产生两条并发身份通道。

全站浏览器操作并发 2，每操作最多 60 s；单次扫描最多 180 s。健康检查反映扫描是否有界运行，不等于所有平台已通过验证。

进入 reseed_required 时仅胜出写入输出一次脱敏 WARNING；后台持久显示状态及恢复指引。目前没有邮件／即时通讯通知服务。

## 6. 租约与 Cookie 轮换

### 6.1 初次导入

本机统一入口 `./start` 依次应用唯一当前态 SQL、自动接入、安装 LaunchAgent、启动业务 Compose，并在 broker 容器中通过签名 status RPC 等待真实运行期准入。未就绪返回非零，不把数据库旧 ready 当作验证结果。每次启动以唯一请求号要求真实 LaunchAgent 校验来源权限；检查结果只属于本次请求，不能用旧报告或交互终端权限替代。后台权限未就绪同样返回非零，即使当前持久会话仍可解析。

`session.source` 默认只处理已有真实登录探针的 YouTube、抖音；配置由 Settings 的 `SITE_SESSION_SOURCE_SITES`、`SITE_SESSION_SOURCE_PROFILES`、`SITE_SESSION_SOURCE_INTERVAL_SECONDS` 管理。每 60 秒执行一轮，每站点独立子进程最多 60 秒，超时终止进程组；launchd 在用户登录时启动并防止自身重叠执行。后台只输出脱敏状态到用户私有目录的 source-status.json。

只有缺失或 reseed_required 才读取宿主 Chrome。单一已登录 Profile 自动选定并持久绑定；多个候选要求一次指定。source_profile 和认证 Cookie 的 HMAC 指纹与 seed_revision 原子保存，指纹不进入公开 API。相同被拒登录材料不再次导入，跟踪 Cookie 或单纯有效期变化不触发重试。新认证材料自动导入后仍须浏览器探针验证。

自动写入必须同时满足修订未改变、当前仍为 reseed_required、指纹不同；缺失行用冲突不写入。并发导入只允许一个成功，撤销与恢复健康均阻止迟到写入。正常 Cookie 轮换由容器维护，不覆盖来源指纹。人工管理用 seed CLI 可显式替换账号或恢复已撤销会话。

后台接入停止不会让已有会话因来源 TTL 失效；容器可独立恢复和保活。它只影响首次接入或真失效后的重新获取。macOS 隐私／钥匙串权限、首次平台登录和真实验证码不能由系统凭空生成。Linux 纯容器部署恢复已有会话，不具备本机 Chrome 自动获取能力。

### 6.2 任务租约

Runner 为每次操作生成独立 ID 和解密密钥。broker 返回绑定操作、站点、修订和到期时间的封装 Cookie；Runner 校验后只写 tmpfs，结束删除。站点 Redis 锁有 TTL、续租和失锁取消，broker 维护使用同一锁。

### 6.3 返回轮换

Runner Cookie 文件发生变化时，按站点 allowlist 校验后封装给该租约专属的 broker 公钥。broker 最多保存 1024 个待返回租约，返回窗口 7500 s 覆盖现有 7200 s 媒体任务预算；新领取仍使用短租约到期检查。返回只接受一次，校验操作、站点、seed_revision、jar_version、浏览器身份和时限，然后用浏览器验证新 jar，只有 verified 才条件发布。broker 重启会失去未完成返回的临时密钥，该任务可能需要重试，但旧返回不能覆盖新运行期状态。

### 6.4 出口

三方共同使用既有 `RUNNER_PROVIDER_EGRESS_PROXIES`；browser 默认 `SITE_SESSION_EGRESS_PROXY` 与 Runner 默认出口都指向 egress-proxy。改变映射需同时重建 browser、Runner、POT，browser 身份变化触发复验。配置相同不等于实际出口 IP 已验证，三方出口实测仍是独立验收项。

## 7. 接口和界面

`/admin/provider-runtime` 返回脱敏会话状态、站点、验证时间、next_check_at 和原因；`Cache-Control: no-store`。后台平台目录下展示会话，15 s 前台轮询；持久 ready 但当前 Runner 未准入显示“等待运行环境验证”。普通用户的原解析通知显示等待或联系管理员，不要求其管理 Cookie。

内部 status／lease／failures／rotation 只接受签名 RPC；browser 用独立 HMAC 密钥。生成客户端只由 OpenAPI 产生，不手改类型。

## 8. 发布与验收

先对既有数据库幂等应用 schema.sql，再配套发布 API／Worker／broker／browser／Runner 与 Web；停止移除的匿名／访客服务，保留会话与文件卷。当前态 SQL 与空隔离 schema 都必须验证。默认无旧执行协议兼容。

静态、数据库集成、真实浏览器与完整媒体文件分别记录。实际 platform challenge 仍可能使有效登录态无法解析；不得用服务 healthy、metadata 成功或 mock 替代媒体下载成功。真实样本、重启与 7 天观察以 Plan 中证据为准。
