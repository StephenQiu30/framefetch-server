# 解析中心与持久意图

本页描述当前实现。解析已迁入 Temporal，保留持久业务意图与 API 幂等语义，执行重试与恢复由 Workflow 负责；不得同时保留两套任务执行所有者。工作流分工见[设计 15](15-工作流与平台下载目标.md)，全平台解析架构与新实施顺序见[设计 17](17-通用解析架构与实施计划.md)。

解析不在 HTTP 内同步等待，而是以持久的 `download_intent` 为唯一入口：

- **接单**：输入规范化（`public_input` 从分享文案提取恰好一个 HTTP(S) URL，多个 URL 拒绝）、加密存储、owner 配额与 Outbox 在同一事务提交，返回 `202`。`(owner, idempotency_key)` 唯一；重放只返回原意图，不重置 180 秒截止与预算。
- **状态机**：`queued → resolving → ready → handed_off`；可恢复故障进入 `retry_wait`；账号来源未就绪或会话问题可进入 `action_required`，原等待身份的登录打开/恢复入口已实施，通用验证动作及 App 接入尚未完成；`preparing` 保留既有语义。终态 `cancelled / expired / failed`。提交检查 generation、operation、fencing token 与 state version，迟到结果不能覆盖。最多 3 次尝试，等待用户选择格式不消耗执行预算。
- **执行**：worker 进程内的 `ff-inspect` Temporal 队列保留两个独立解析 Activity 槽；数据库不再扫描解析任务来决定重跑。工作流 ID 固定为意图 ID 加 generation，Outbox 确认丢失只核对既有绑定；取消事务递增 fence 并持久投递取消命令，Runner 在断连时传播取消到进程组终止与工作目录清理。
- **结果**：inspection、formats 与 `ready` 在同一事务提交。格式推荐顺序是后端规则（优先保留音轨，再按分辨率、容器、编码、帧率稳定排序），投影与探针一致。仅 `access_decision=downloadable` 可确认下载；确认后由既有 `POST /api/downloads` 交接，同一 inspection 唯一交接。
- **过期与刷新**：inspection 过期后 `refresh` 保留原意图并递增 generation，重解析必须核对平台内容标识与媒体类别，格式变化须用户重新确认，不自动下载；不复用失效直链。
- **来源发现**：微信公众号文章先做多候选发现，用户显式选择后再解析。
- **恢复**：客户端响应丢失时以同一幂等键只读查询（不重发 POST）；账号绑定的历史列表（游标分页，单页最多 50）用于跨设备找回，不返回原始输入或幂等键。
- **个人处理记录**：`GET /api/download-intents/history/records` 对解析意图、视频 AI、剧本基础解析、剧本 AI 做 owner 范围联合查询（排序 `created_at DESC, id DESC, record_type DESC`，过滤先于 LIMIT，无 COUNT），不新增万能任务表；来源与结果可用性分别标注 `available/unavailable/unknown/not_applicable`；详情与写操作重新校验权限。
- **管理员操作日志**：`operation_logs` 记录写请求生命周期（路由执行前 started、完成后一次结果写入）与由 SQL 触发器在业务事务中写入的任务状态事件；不持有用户外键、不记录完整 payload；入口 `/admin/operation-logs`。个人记录入口 `/history/activity`。

## 通用解析与恢复目标（planned）

意图在平台 I/O 前持久化一份 resolution_plan，每次策略执行写 resolution_attempts 子记录；这些记录属于现有 downloads 域，服务于预算和路线决策，不复刻 Temporal History。Activity 一次执行一条策略，Runner 删除内部隐式业务回退；策略转换、网络重试与人工恢复共同使用原 generation 的 180 秒有效时间和最多 3 次实际调用。

失败保留 code/phase/scope/evidence。人工验证、连接来源和登录分别表达动作；原任务等待、恢复、取消与过期继续使用 authorization_id、Outbox 和 Workflow，最多 24 小时且不因点击延长。ready 需要可执行格式和必要媒体探测，metadata 成功不单独成为可下载结果；完整规范与 P01–P09 见设计 17。
