# 解析引擎

本文定义解析引擎的目标、分层、执行规则、失败分类、执行上下文、平台声明与验收方法。意图生命周期见[解析意图](06-解析意图.md)，编排见[工作流编排](13-工作流编排.md)，平台账号材料见[平台身份](15-平台身份.md)。

## 1. 目标与边界

目标是**冷启动可用**：业务服务刚启动、没有热缓存或预热时，用户粘贴链接即可经正式 API 获得完整文件。

- 匿名平台不依赖任何登录态。
- 登录平台复用部署者日常 Chrome 中已登录的身份。就绪条件：Chrome 正在运行且已登录，身份扩展已加载并连接到 cookie-source。
- 内容范围与身份策略是两个独立维度：
  - `public`（默认）：只处理能正向证明为公开、免费、非 DRM 的内容。带着 Cookie 也不扩张到 private、follow-only、付费或地域受限内容。
  - `personal_full`：只适用于腾讯视频与优酷，处理账号可访问的完整非 DRM 单视频，必须保留原始完整时长。
  - `official_share`：只适用于视频号，交付本次分享链接对应的微信官方非加密文件。核对匿名分享、元宝响应与官方 feed 的标题、作者、封面来源与路径，拒绝明确的限制或保护。平台未提供的公开免费标签、独立原长与原作品完整性不作已证实声明。
- 不解密平台加密媒体、不取得内容密钥、不转换 DRM 流（视频号加密视频、红果 CENC 流、腾讯与优酷 DRM 格式均属此类）。遇到时返回 `content_protected` 并提示使用文件导入。
- 单人自用：不建设账号池、准入审批、运营金丝雀或多租户隔离。

## 2. 三道关口

三道关口是诊断维度，不与错误码一一对应。同一信号（如 LOGIN_REQUIRED、403、空 JSON）在不同平台与阶段可能来自不同关口，分类结合平台、阶段与结构化证据判断。

| 关口 | 平台检查 | 常见信号 | 对应层 |
| --- | --- | --- | --- |
| ① 网络身份 | 出口 IP 信誉与地区 | YouTube `Sign in to confirm you're not a bot`、机房 IP 的 LOGIN_REQUIRED | 出口层 |
| ② 客户端证明 | 是否执行过平台 JS、携带签名或令牌 | 空 JSON、`Fresh cookies needed`、JS 挑战页、PO Token 错误 | 证明层 |
| ③ 账号身份 | 内容是否要求登录或权益 | 明确的登录要求、年龄限制 | 身份层 |

分类使用本次任务实际记录的 `egress_class`、`egress_observed_ip`、`resolved_layer`、`client`、`identity_used` 与结构化限制证据，不把路由名、单次机器人墙或元数据成功推广为平台结论。关口是否解除，只由同一出口、客户端与身份上下文中的正式完整文件证明。

## 3. 架构

```text
链接 → 识别平台 → 平台阶梯（Registry 声明）
                 L1 HTTP 提取（yt-dlp / 薄插件）
                 L2 HTTP + 证明（PO Token、EJS、访客初始化）
                 L3 浏览器（真实页面执行 JS，观察响应或调用平台限定的第一方接口）
        RunContext（仅在 Runner 内存与私有 tmpfs）：出口、UA、Referer、Cookie、必要账号材料、浏览器 context
        ExecutionContext（无秘密，写入业务库）：见第 9 节
        成功 → 作品身份 + 语义下载规格 → 下载前核对 ExecutionContext → 同层重新取直链 → 下载 → 校验 → 发布
```

## 4. 出口层

- 每个平台声明固定出口 `egress_route`：`cn_residential` 或 `global_residential`。squid 按路由把流量交给 Clash 的对应上游，Runner 只认路由名。
- 路由名不代表实际住宅出口。配置了住宅上游时记录 `egress_class=residential`；境外未配置住宅上游时复用现有境外节点并标记 `datacenter`；国内直连未声明固定住宅上游时标记 `unknown`。
- 同一任务的解析与下载走同一路由与同一出口节点。路由配置修订（`egress_revision`）与观测出口 IP（缓存 10 分钟）写入执行上下文与诊断。
- 在同一个被封锁的出口下切换层级不算解决关口 ①；诊断如实记录出口类别。

## 5. 证明层

- 签名与令牌只来自两类组件：执行平台自身 JS 的组件（浏览器、BotGuard 运行时），或上游维护的官方求解器（如 yt-dlp TikTok 提取器自带的挑战求解）。仓库内不实现逆向签名算法。
- **YouTube**
  - yt-dlp、EJS、JS 运行时、bgutil 服务端与插件成对升级；不校验发行身份。
  - L2 客户端链依次尝试，如 `mweb`+bgutil PO → `tv` → yt-dlp 默认；每一步记录实际 `client`。
  - L3 使用 [yt-dlp-getpot-wpc](https://github.com/coletdjnz/yt-dlp-getpot-wpc)。它是 PO Token 提供者，不是页面解析器：自行启动浏览器（nodriver，`headless=False`，容器内需要 Xvfb），取得令牌后仍由 yt-dlp 解析与下载。它与第 6 节的 Playwright 浏览器层相互独立，使用同一出口路由；令牌与视频 ID、出口的绑定规则以上游为准。
  - 某客户端只返回 DRM 或 SABR 格式时，仅说明该客户端不可用，继续尝试链上其他客户端；所有声明客户端都只有 DRM 格式时才判定 `content_protected`。
- **快手、微博**：L2 准备步骤按平台声明请求首页或 `passport` 访客接口，取得访客 Cookie 后再调用 yt-dlp。
- **抖音、小红书**：访客初始化与签名由 L3 浏览器完成。

## 6. 浏览器层（L3）

- 基于 `browser_runtime`（Playwright + Chromium），懒启动。
- **匿名 context**：每个平台一个常驻 persistent context（`browser_profiles` 卷），永远不注入账号材料，空闲 10 分钟关闭。同一平台的匿名 context 同一时刻只由一个任务占用；并发请求排队，排队时间计入解析时限。
- **登录 context**：需要身份的任务使用独立的临时 context，创建在私有 tmpfs 中，绑定任务、站点与登录材料摘要；任务成功、失败或取消后销毁，匿名任务不复用。
- **流程**：打开平台首页完成访客初始化 → 打开作品页，按平台声明的 URL 模式拦截页面自身发出的接口响应（如抖音 `aweme/detail`、小红书 `feed` 或 `__INITIAL_STATE__`）→ 平台薄解析函数转成统一的 `ResolvedMedia`。
- **视频号**使用专属流程，见[平台身份第 6 节](15-平台身份.md#6-视频号元宝解析)：它主动调用已声明的精确第一方接口；请求目标、方法、请求体与响应来源由平台实现固定，不开放任意 URL、脚本或接口代理。
- **下载交接**：把 context 的 Cookie、UA、Referer 放入 RunContext，由 HTTP 或 yt-dlp 下载。媒体直链绑定在浏览器上时，在同一 context 内下载到 workspace，文件保存完成后才关闭 context。

## 7. 阶梯执行

Registry 为每个平台声明 `ladder`（有序层级）、`egress_route`、`identity`、`content_scope`、L3 拦截规则与 L2 准备步骤。

| 失败类别 | 下一步 | 次数上限（作用域） |
| --- | --- | --- |
| `network_blocked` | 下一层（诊断标注出口类别） | 每层 1 次 |
| `challenge` | 下一层 | 每层 1 次 |
| `extractor_broken` | 下一层 | 每层 1 次 |
| `format_unavailable` | 下一层；已是最后一层则终止 | 每层 1 次 |
| `login_required` | 已注入身份或 identity 为 `none`：终止；`prefer` 未取得身份：终止 | — |
| `identity_unavailable` | `required`：终止；`prefer` 在解析开始时读取失败：匿名继续；解析时用了身份而下载时取不到：`context_changed` | 每个任务读取 1 次 |
| `rate_limited` | 遵守 `Retry-After`；等待时间在剩余预算内则同层重试一次，否则终止 | 每个任务 1 次 |
| `transient` | 同层重试 | 每层 1 次 |
| `runtime_unavailable` | 同层重试；再次失败即终止，不切换层掩盖本机故障 | 每个任务 1 次 |
| `content_unavailable`、`content_protected`、`invalid_input` | 终止 | — |

- **预算**：每个 generation 120 秒，截止时间持久化在意图上；所有层、重试、排队与身份读取共享剩余时间。自动恢复或 Worker 重启不重置截止；只有用户显式 refresh 才开启新 generation。下载、校验与发布另有有限时限；下载时为取直链而重新解析的耗时计入下载时限。
- 超时或取消时终止整个子进程组与浏览器 context，确认清理完成后才写终态。
- 解析成功后记录作品身份、语义下载规格与执行上下文。
- **下载前核对**：未变化则同层重新取直链，取到后再次核对实际客户端、作品身份与语义规格。出口节点或修订、客户端、引擎修订、登录材料摘要任一变化即为 `context_changed`，要求重新解析并重新确认规格，不静默更换。

## 8. 失败分类

十三类：`network_blocked`、`challenge`、`login_required`、`identity_unavailable`、`rate_limited`、`content_unavailable`、`content_protected`、`extractor_broken`、`format_unavailable`、`transient`、`runtime_unavailable`、`invalid_input`、`context_changed`。

- 每个失败记录 `layer`、`stage`（resolve／download／validate／publish）、`gate`（①／②／③／none）、`evidence`（结构化子因，不含原始 stderr）与一句摘要。
- 分类优先级：先判断明确的内容限制或删除，再依次判断限流、登录、挑战、网络、结构与格式；只有模糊提示时归为 `extractor_broken` 并保留证据。
- TLS 连接意外 EOF 归为 `transient`，沿用同层一次重试与原截止时间；明确的内容删除或保护证据仍优先。
- Runner 的本地最终文件校验失败在下载状态中投影为 `media_validation_failed`；保留十三类执行失败的分类与阶段，不显示为平台页面结构变化。
- 同一任务的多层失败全部保留，最终摘要指出停止原因。

## 9. 执行上下文

`ExecutionContext` 持久化、无秘密，贯穿意图、检查结果、下载 Job 与制品元数据。

| 字段 | 说明 |
| --- | --- |
| `provider_key`、`registry_revision` | 平台与 Registry 声明修订 |
| `resolved_layer`、`client` | 成功的层级；精确的提取器客户端（如 `youtube:mweb`） |
| `engine_revision` | yt-dlp、插件、EJS、bgutil、WPC、浏览器版本的组合摘要 |
| `egress_route`、`egress_revision`、`egress_class`、`egress_observed_ip` | 出口路由、配置修订、住宅或机房类别、观测 IP（可为空） |
| `identity_used`、`identity_digest` | 是否注入身份；登录材料的稳定摘要（不含 Cookie 值） |
| `browser_context_kind` | `none`／`anonymous`／`authenticated` |

身份不可用时 `identity_used=false`、`identity_digest=null`，子因写入失败记录的 `evidence`；字段集合始终是上述十二个。`InspectionResponse` 与 `DownloadResponse` 提供只读的 `execution_context`。

## 10. 模块接口

修改 Registry、`schema.sql`、OpenAPI 或本节接口时同步更新本文；公开契约变化时重新生成 Web 与 App 客户端。路径相对于 `backend/app/`。

| 接口 | 位置 | 约定 |
| --- | --- | --- |
| Registry | `workers/runner/provider_registry.py` 的 `ProviderProfile`；共享枚举与值类型在 `services/provider_types.py` | `ladder: tuple[Layer, ...]`、`egress_route`、`identity`、`identity_source: cookies / yuanbao_http`、`identity_origin: str \| None`、`content_scope`、`l2_prepare: PrepareSpec \| None`、`l3_rules: BrowserRules \| None`；`yuanbao_http` 只能由视频号声明 |
| `RunContext` | `workers/runner/engine/run_context.py` | 不可变：`egress`、`user_agent`、`referer`、`cookie_file`、`identity`、`browser`、`deadline`；只存在于 Runner 进程内；元宝身份只含摘要，不伴随 Cookie 文件 |
| `EgressBinding` | `workers/runner/engine/egress.py` | `resolve_egress(profile) -> EgressBinding(route, proxy_url, revision, egress_class, observed_ip)` |
| `Layer` | `workers/runner/engine/layers/base.py` | `async resolve(source, ctx) -> ResolvedMedia`；失败抛出 `LayerFailure(failure_class, gate, evidence, retry_after=None)` |
| `ResolvedMedia` | `workers/runner/engine/resolved.py` | 作品身份、媒体类别、候选流（`CandidateStream`）、缩略图、`client`、`handoff`（http／browser）；可返回 `run_context` 材料副本（仅 Runner 内存） |
| 阶梯执行器 | `workers/runner/engine/ladder.py` | `async run_ladder(source, profile, deadline) -> Resolution(media, execution_context, failures, run_context)`，按第 7 节执行 |
| L1／L2 | `workers/runner/engine/layers/http.py`、`prepared.py` | 包装 yt-dlp 命令；L2 先执行 `l2_prepare` |
| L3 | `workers/runner/engine/layers/browser.py` 与 `engine/browser/<platform>.py` | 已实现的平台提供拦截规则与响应解析函数；缺少解析器时明确失败，不以占位文件声明可用 |
| 身份 | Runner 侧 `workers/runner/engine/identity.py`；宿主侧 `workers/identity/cookie_source.py` | 见[平台身份](15-平台身份.md) |
| 冷启动矩阵 | `backend/scripts/coldstart_matrix.py`、`backend/scripts/fixtures/coldstart_cases.json` | 只调用正式 HTTP API，不导入 Runner 内部模块 |

调用约束：

- `RunContext.egress.proxy_url` 是 Runner 内媒体出站的唯一代理来源，yt-dlp、媒体 HTTP、FFmpeg、`browser_runtime` 与缩略图请求都从它读取。
- `run_ladder` 返回的 `Resolution.execution_context` 是解析结果的唯一来源，原样持久化；下载开工前与重新解析得到的上下文按第 7 节核对，持久上下文经 `ResolutionSource.expected_context` 传入。
- `ladder.py` 按 `profile.ladder` 通过层表 `{L1: HttpLayer, L2: PreparedLayer, L3: BrowserLayer}` 依次执行。
- yt-dlp 只接受 `/tmp/framefetch-identity/<operation>/<file>` 下的 Cookie 文件（目录 0700、文件 0600、当前用户所有、无符号链接），其他路径一律拒绝。
- `BrowserHandle` 提供 `cookies()`、`user_agent`、`async download(url, dest)` 与 `async close()`。`handoff == "browser"` 时经 `BrowserHandle.download` 下载，保存完成后才关闭。`RunContext.with_material(...)` 返回带新材料的副本，由 service 持有到交接结束；任何材料都不序列化。
- `workers/runner/version.py` 的 `engine_revision()` 按 yt-dlp、插件、EJS、bgutil、WPC、浏览器版本及 Runner 的候选生成、文件校验和共享下载规则等本地实现计算；规则变化使旧规格失效并要求重新解析。

平台规则：

- **视频号**：见[平台身份第 6 节](15-平台身份.md#6-视频号元宝解析)。扫码、封面、业务成功码或空 `decodeKey` 不证明媒体可交付。
- **红果**：只允许匿名公开 clear 分享流。在暴露媒体地址前拒绝明确的 DRM、加密或付费标记；访客 Cookie 不作为账号身份。
- **腾讯视频**：保留原始完整时长，拒绝保护流。访客初始化保留 `video_guid`；账号必要材料为 `v_vuserid`／`v_vusession`。独立时长查询只带访客标识，播放请求使用账号 Cookie。API 包装的 `proxyhttp.enc=1` 不等于媒体 DRM。
- **优酷**：L3 读取播放器的 `ups.youku.com/ups/get.json`，按原请求 vid 绑定作品，核对原时长与完整 segment 覆盖。L1 使用已有 `cna`。身份门禁接受有效 `P_sck`，或有效 `P_pck_rm` 加上 URL 解码后含非空、非 `NA` 账号标记的 `P_gck`；拒绝坏百分号编码、非法 UTF-8、控制字符、过期与游客材料。材料存在不等于会员认证。L1／L3 共用 `encrypted_playlist` 判定，在原生解析或分片探测前拒绝 KEY／SESSION-KEY 前缀及其大小写与异常分隔变体。High/avc1 末尾独立的 type=37 MVC-nesting SEI-only 包，只在有限包边界与精确位置、大小核验后 copy remux，保留画面、嵌入 SEI 与音频，不忽略解码错误。
- **Dailymotion**：匿名 L1 只接收精确长短链，其他子域在 Generic 前拒绝。薄插件先核实公开作品元数据，再绑定同作品的 GraphQL／player 响应、原长与保护字段。master 与 variant 都检查保护标签，相对 URI 基于最终响应地址；拒绝 Key／Session Key、MAP、BYTERANGE、LL-HLS、I-frame、GAP／SKIP；Dailymotion 请求带 `X-Request-Origin:https://www.dailymotion.com`；下载使用 `--abort-on-unavailable-fragments`。格式 ID 允许官方帧率后缀 `@60`，逐档探测实际帧率，不能将顶层选中档位的 fps 用于其他档位；不声明 DASH。清单 HTTP 403 记为 `network_blocked`，不改写为内容保护。
- **X**：HLS 未提供有效平均帧率时，不把 `r_frame_rate` 的时间戳基数当作实测帧率；候选采用可核实的平均帧率或上游逐档帧率。明确未知的逐档 fps 不继承其他档位的顶层 fps；未知候选不进入下载规格，保留已验证的同画质 MP4。不改变最终文件的帧率档位校验或转码降帧。
  - HLS 候选采用有界清晰 VOD 头部探测：清单最多 2 MB，初始化文件和首分段前缀各最多 256 KiB；初始化文件与媒体前缀合并后取得音视频编码、尺寸与平均帧率。拒绝密钥标签、跨主机媒体地址、直播、字节范围清单及缺失分段标记；样本时长与大小不补成完整作品事实。
  - 在同一解析上下文和确认规格内，优先选择已通过上述探测的 HLS 音视频组合；组合无法匹配完整规格时保留原有选择。下载并发分段数为 4，缺失分段即终止；原始时长、各轨时长及完整解码仍是发布门槛。
- **公众号文章**：需求见[公众号视频下载 PRD](../prd/PRD-公众号视频下载.md)。入口 `POST /api/source-discoveries`；用户选择后向 `POST /api/download-intents` 提交 `source.kind=discovered_item`、discovery 与 item 引用。服务端验证 owner 与 TTL，原生视频使用文章 URL 加非敏感身份哈希选择符进入匿名 cn L1；裸文章不能进入 Generic 或自动选择视频。静态解析有界读取 `video_page_info`／`video_page_infos` 的原生身份、删除／禁止标记与 `mp_video_trans_info` 档位，禁止执行 JavaScript；只请求同一 `mpvideo.qpic.cn` 主机的 TLS MP4，重新解析与最终文件核对完整时长。签名 URL 不进入 API、队列、History 或数据库。腾讯视频外链重新绑定当前候选后沿用腾讯 Provider；视频号仅在存在有效官方分享 URL 时沿用视频号 Provider，否则引导导入。声明 `single_video` 与下载能力不代表验收通过，发现成功也不计为视频交付。

## 12. 冷启动矩阵

`backend/scripts/coldstart_matrix.py` 读取 `backend/scripts/fixtures/coldstart_cases.json`：

- `--platforms a,b`：只运行指定平台，并检查每个平台至少两条正例；用于平台专项验证。
- `--all`：平台集合必须等于 Registry 的全部平台，缺少即报错；完整验收只用此模式。未覆盖的平台不能记为通过。

样本要求：

- 每条样本声明平台、URL、预期作品 ID、独立来源的完整时长（不得取自被测流本身）、最低规格、`content_scope` 与类型（正例／受保护负例）。`official_share` 样本改为核对官方候选文件时长，并在报告中注明来源与“原作品完整性未证实”。
- 每个平台至少两条不同作品的正例。

执行：

- 冷启动范围：重启 api、worker、session-runner 与 cookie-source；清空 Runner 临时目录与 yt-dlp 缓存；使用独立的验收浏览器卷；共享基础服务保持运行。
- 每条样本走正式链路：API 创建意图 → Temporal 解析 → 确认规格 → RabbitMQ 下载 → Artifact 发布 → 取回文件 → ffprobe → 完整解码。核对作品 ID、完整时长与规格，记录实际时长、大小与 SHA-256。时长核对同时覆盖容器与每条音视频轨，长音轨不能掩盖截断的视频轨。
- 输出 Markdown 与 JSON 到 `artifacts/coldstart/`（不入库）：平台、样本、结果（通过／失败／阻塞／受保护负例）、成功层级与客户端、出口类别与观测 IP、是否使用身份、耗时、失败类别与证据。
- 平台通过条件：两条正例都完整交付。受保护负例只验证识别是否正确，不计入通过；未登录或能力阻塞记为“阻塞”。负例必须核实预期限制，challenge 或网络拒绝不算保护识别通过。

候选探测只补齐缺失的时长，不覆盖已经取得的原始完整时长。下载请求携带确认时持久化的时长；重新解析的时长发生实质变化时要求重新解析，最终容器与各音视频轨均对照确认时长校验。已有可用规格仍需在探测预算内补齐其他未知画质；一次解析共用最多 12 次远程候选探测（并发 4）与 8 次有界文件探测，优先高画质，首个无可用视频的样本不能终止后续候选。

候选与最终文件共用帧率判定，先核对 `avg_frame_rate` 的档位。远程容器的平均帧率超过标称帧率并跨档、且缺少下述精确帧数证据时，以有界文件探测取得实际平均帧率，不按平台近似修正。复制封装后的平均帧率跨档时，只有 `r_frame_rate` 仍匹配确认档位、`nb_frames` 与 `avg_frame_rate × duration_ts × time_base` 精确相等，且轨道时长仅比完整标称帧数短不足一帧，才接受标称帧率；字段缺失、无效或帧数不一致均拒绝，不转码或放宽全局档位阈值。

所有平台的单视频及视频合集每个成员均在发布前完整解码全部音视频轨；只有元数据通过不能交付。解码保留输入时间基与原始帧时间，不因可变帧率的输出时间量化产生假错误；失败归为本地校验，不能据本地 stderr 判定上游 HTTP 限制。

清晰分片的视频头探测最多读取 256 KiB，容纳音频先于视频头的情况；只有明确解出视频编码和正数宽高时，才允许在平均帧率缺失的有界头部探测中使用标称帧率。缺少有效视频头时，时间基准不能补成下载规格的帧率。

回归测试保留：解析中取消、Worker 在原截止时间内重启、旧 Runner 仍在运行、迟到结果拒绝、取消确认应答丢失；制品校验覆盖容器与各音视频轨时长、完整解码、大小与 SHA-256。
