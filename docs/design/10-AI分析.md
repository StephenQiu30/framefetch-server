# AI 分析

本页只记录尚未清退的 Worker 执行方式。新影视 Skill 的产品目标、方法选型、证据、人工校订和验收以[全新 PRD](PRD-影视Skill体系.md)为准；这些目标尚未实施。分析运行由宿主 AI Worker 上的 `SkillWorkflow`（`ff-skill` 队列）调度：Outbox 直接启动 Workflow，重试等待由 Workflow 计时器负责，每次模型调用写入步骤日志，中断后已完成的块直接复用、结果不明的调用以 `analysis_outcome_unknown` 终止而不自动重调。报告 Markdown／DOCX 发布仍由 RabbitMQ 报告 Worker 执行。分析失败继续与下载成功隔离。详细契约、Provider 冻结与未知计费边界见[工作流与平台下载目标](15-工作流与平台下载目标.md)。

## 任务模型

`analysis_jobs`（视频 `video` 与剧本 `screenplay` 两种受控输入）、`analysis_runs`（多次运行、`run_no` 单调）、报告版本与制品、artifact／document 保留锁。共享状态机、取消、重试、幂等与执行 fence，使用不同工作区、工具权限、Prompt 与结果契约。分析失败不改变下载成功状态。

## 执行器（策略 + 适配器 + 注册工厂）

三个端口：`VideoAnalyzer`、`ScreenplayAnalyzer`、`ScreenplayRewriteAnalyzer`。适配器：

- **CLI（宿主机）**：Codex App Server（默认，`local-codex`，复用宿主机 OAuth 登录）与 Claude CLI；受限工作区、最小环境、严格工具权限、无浏览器；AI Worker 是可信宿主机进程，`host_login` 只在登录用户的系统账户下运行。
- **API**：DeepSeek（LangChain，视频先转为有界、按时间排序的 JPEG 证据）、OpenRouter（固定地址，读取公开模型目录并在发送媒体前检查图像输入、文本输出、`structured_outputs` 能力，`require_parameters=true`、`strict` JSON Schema、关闭内部重试与跨供应商 fallback）、OpenAI Chat Completions 兼容线路（`json_object`）。API 响应体与结果大小有上限、不跟随重定向，密钥仅在 Worker 内存中出现。
- **配置**：`ai_provider_profiles` 由管理员维护（`engine`、`auth_mode`、`base_url`、`model`、Fernet 密文、`is_active` 部分唯一索引），Worker 每任务解析一次活动线路；`local-codex` 保护规则只允许改显示名与模型。`analysis_worker_heartbeats` 提供在线诊断，不阻断 API。注册工厂按 engine 显式选择构造函数，未知引擎拒绝。
- 普通用户不能选择 Provider、模型、系统 Prompt、CLI 参数或路径；只能选择 Skill、输出语言并编辑受系统 Prompt 约束的分析重点（≤ 4000 字）。

## Skill 与结果边界

旧任务分类、结果大包、固定写作流水线、视觉切分规则和来源模块不再作为有效产品规格，也不在本页保留另一套新目标。旧代码仍运行不代表新方案已经实现；完整清退按[PRD 第 8 节](PRD-影视Skill体系.md#82-旧代码清退要求)执行。

本次未改变现存模型线路或执行代码，未新增 ASR、镜头检测、人工修改接口或字幕导出。新 PRD 将这些能力按明确用户任务重新定义，实施时同步服务端契约、工具权限、导出与客户端，不能仅修改 Skill 文本后宣称完成。

通用边界继续成立：分析失败与素材获取成功分开；每次外部模型调用有期限和预算；未知付费调用不能自动重发；工具和材料隔离；结构校验不等于影视结论正确；完整 Prompt、原始响应、凭据和用户媒体不进入普通日志。
