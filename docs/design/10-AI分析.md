# AI 分析

本页描述现有 Worker 执行方式。分析运行由宿主 AI Worker 上的 `SkillWorkflow`（`ff-skill` 队列）调度：Outbox 直接启动 Workflow，重试等待由 Workflow 计时器负责，每次模型调用写入步骤日志，中断后已完成的块直接复用、结果不明的调用以 `analysis_outcome_unknown` 终止而不自动重调。报告 Markdown／DOCX 发布仍由 RabbitMQ 报告 Worker 执行。分析失败继续与下载成功隔离。详细契约、Provider 冻结与未知计费边界见[工作流与平台下载目标](15-工作流与平台下载目标.md)。

## 任务模型

`analysis_jobs`（视频 `video` 与剧本 `screenplay` 两种受控输入）、`analysis_runs`（多次运行、`run_no` 单调）、报告版本与制品、artifact／document 保留锁。共享状态机、取消、重试、幂等与执行 fence，使用不同工作区、工具权限、Prompt 与结果契约。分析失败不改变下载成功状态。

## 执行器（策略 + 适配器 + 注册工厂）

三个端口：`VideoAnalyzer`、`ScreenplayAnalyzer`、`ScreenplayRewriteAnalyzer`。适配器：

- **CLI（宿主机）**：Codex App Server（默认，`local-codex`，复用宿主机 OAuth 登录）与 Claude CLI；受限工作区、最小环境、严格工具权限、无浏览器；AI Worker 是可信宿主机进程，`host_login` 只在登录用户的系统账户下运行。
- **API**：DeepSeek（LangChain，视频先转为有界、按时间排序的 JPEG 证据）、OpenRouter（固定地址，读取公开模型目录并在发送媒体前检查图像输入、文本输出、`structured_outputs` 能力，`require_parameters=true`、`strict` JSON Schema、关闭内部重试与跨供应商 fallback）、OpenAI Chat Completions 兼容线路（`json_object`）。API 响应体与结果大小有上限、不跟随重定向，密钥仅在 Worker 内存中出现。
- **配置**：`ai_provider_profiles` 由管理员维护（`engine`、`auth_mode`、`base_url`、`model`、Fernet 密文、`is_active` 部分唯一索引），Worker 每任务解析一次活动线路；`local-codex` 保护规则只允许改显示名与模型。`analysis_worker_heartbeats` 提供在线诊断，不阻断 API。注册工厂按 engine 显式选择构造函数，未知引擎拒绝。
- 普通用户不能选择 Provider、模型、系统 Prompt、CLI 参数或路径；只能选择 Skill、输出语言并编辑受系统 Prompt 约束的分析重点（≤ 4000 字）。

## Skill 与结果

当前七个产品任务与六种结果契约，当前方法、工具、执行与验收见[内容能力、Skill 与执行 Harness](16-Skill体系与结果契约.md)。
- 动态 Skill 目录只提供成片审阅、视频写作、素材拆解、传播策划、剧本审阅、剧本改写和文字写作。专项关注项在任务中组合；方法保存完整来源与不可变快照。四种视频任务与文字写作执行 Plan → Draft → Review → 可选 Revise／Verify，通常 3 次、最多 5 次应用模型调用；剧本保留已验证的场景分块及改写执行器。
- 视频分析以“Cut + 连续节拍”生成分镜：不按固定秒数切片；超过 10 秒仍单项时必须复核并带 `segmentation:single-unit-verified`；剧本 `source_scene_id` 始终是规范化文本场景，不推断镜头。
- 结果为严格判别联合契约（视觉分析：摘要、场景、分镜、高光、资产；视频文章：导语、章节、要点、结语、局限；通用结构化报告：摘要、章节、候选条目、时间证据、局限；剧本：故事概览、结构、人物、场景、对白、修改建议；剧本改写：目标语言文本候选与术语表），持久化前严格校验；历史报告按原始结果读取。报告导出仅提供 Markdown／DOCX；错误只展示归类后的可行动信息，不暴露 Prompt、Provider 原始输出、Token 或私有地址。
- 普通内容结果为有限正文块、任务内引用与私有审校记录；输入固定材料和 brief，只读报告历史及重新生成规则见设计 16。
- 防护：视频证据只来自完整视频制品，Prompt Injection 防护、工作区隔离、输出与超时上限；AI 只做视觉／文本证据判断，不做 ASR，不引入应用侧镜头检测算法。
