# 工作流与平台下载

本文维护 Temporal、RabbitMQ 与 PostgreSQL 的职责分工。解析引擎的全部目标、平台范围和 R0–R6 实施验收统一在[设计 17](17-解析引擎重建.md)维护。

## 执行所有者

| 链路 | 执行者 | 业务事实与恢复 |
| --- | --- | --- |
| 解析意图 | Temporal InspectionWorkflow | 一个 resolve Activity，120 秒总期限、取消；PG 保存意图、结果与十二字段 ExecutionContext |
| Skill 分析 | Temporal 分析 Workflow | AnalysisJob／Run／Step、固定来源／方法、执行所有权；结果未知不自动再次调用 |
| 下载、导入、报告发布 | RabbitMQ Worker | 幂等消费者、PostgreSQL lease/heartbeat、有限排空与 DLQ |
| 实时状态 | RabbitMQ fan-out | PostgreSQL 状态及版本是事实来源 |

API 在同一事务保存业务记录、配额与 Outbox；dispatcher 按确定 Workflow ID 直接启动 Temporal，不经 RabbitMQ 中转。下载与分析独立，AI 失败不会改变下载成功状态。

## 解析与取消

`InspectionWorkflow` ID 为 `inspect/<intent_id>/<generation>`；resolve Activity 查询业务记录、按设计 17 的 Registry 阶梯执行，并原子保存 inspection/formats 与 ready。业务 generation/fence、持久截止时间与取消确认保留。客户端以意图 ID 查询、取消、刷新与交接；HTTP 不暴露 Temporal Run ID。inspection 过期后显式刷新新 generation，迟到旧结果不能覆盖新任务或已取消任务。

取消或超期在业务事务写 `cancelling` 与 Outbox；确认 Temporal 取消及稳定任务 ID 对应的 Runner 清理后，才写 `cancelled` 或 `expired`。取消确认失败保留待确认状态并由原 Outbox 重投；不增加操作账本。resolve Activity 的基础设施恢复仍使用原截止时间，当前版本拒绝旧执行的迟到结果。Runner 终止整个进程组；队列和子进程均有期限。下载 lease/heartbeat 与重试仍由原 RabbitMQ 链路管理。

微信公众号多候选发现由用户选择后进入解析。本地视频、剧本文档导入与成功后的 Skill 分析复用原链路。

## Skill 执行与断点

内置 Skill 复用现有分析任务与 Outbox，由 dispatcher 直接启动 Temporal 分析 Workflow，不经 RabbitMQ 中转。模型调用前写 Step 日志，回执未知禁止自动重发；取消与执行者丢失保持真实状态，迟到结果由执行所有权和当前状态拒绝。活动 CreationWorkflow 与 creation 写能力清退，具体实现与注册证据见执行计划。

固定源快照、任务、执行步骤和报告是 PostgreSQL 事实，临时工作区不是恢复账本。报告导出使用已保存结果，失败单独重做，不重新调用模型；不增加作品、材料、母稿或版本确认域。当前结构与工具边界见[AI 分析](10-AI分析.md)，任务和验证见[PRD](../prd/PRD-内置Skill能力整合.md)与[PLAN](../plan/PLAN-内置Skill能力整合.md)。

## 部署与业务幂等

Temporal 直接复用已有服务，容器 Worker 通过 `TEMPORAL_HOST`／`TEMPORAL_PORT` 连接，宿主 Worker 通过 `TEMPORAL_ADDRESS` 连接；存储与结构由已有服务管理，项目 schema.sql 只维护业务当前态。Task Queue `ff-inspect` 与宿主 `ff-skill` 保留各自受限并发；它们不是额外容器。

媒体 Worker 同时监督 Outbox、下载、导入与报告循环。独立 session-runner 执行媒体工具，egress-proxy 保留网络边界；宿主 AI Worker 保留官方 CLI 登录，不挂载认证目录到容器。平台身份与材料清理见设计 17 第 3.4 节。

启动确认丢失时查询相同 Workflow ID并核对业务绑定，运行中 ID 冲突不创建第二个执行。PostgreSQL 唯一约束与当前状态控制业务幂等；完成、取消和已刷新记录拒绝迟到结果。分析调用保留其持久步骤日志与执行所有权，解析清理不能删除分析的不确定调用保护。

发布前暂停新接单并排空或取消旧媒体操作，幂等应用 schema.sql 后配套替换 API、Worker、Runner 与生成客户端。业务记录与成功制品保留；升级和回退需要匹配的结构备份。

## 验证边界

确定性检查覆盖单 Activity、取消、幂等、十三类失败、ExecutionContext 与 OpenAPI；当前态 SQL在空隔离数据库及已有当前态数据库重复应用。真实平台按设计 17 验证解析、下载、ffprobe、完整解码、大小和 SHA-256。健康检查、平台登记、fixture 与模型模拟不替代真实文件或真实模型验收。

Temporal History、heartbeat 与日志仅包含 ID、状态和必要版本，不保存 URL、Cookie、Key、完整 Prompt、媒体或原始模型输出。未知调用占用不因取消或失败而删除。
