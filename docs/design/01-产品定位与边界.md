# 产品定位与边界

帧取是自行部署、仅供部署者使用的个人视频工作站，不计划上线为互联网服务：解析视频链接、选择格式、异步下载并交付授权制品，导入本地 MP4 与剧本文档，并对视频与剧本做结构化 AI 分析和报告导出。Web 与独立的 Flutter App（`video-app`）共用同一后端。

设计优先级是可靠启动、任务可恢复、配置与凭据来源清晰、减少日常维护。已有多用户、队列和容器结构是当前实现，不是必须保留的产品要求；重构以完整使用流程和故障恢复验证为依据，不为多租户、高可用集群或未来扩展预留空转机制。

内置 Skill 按[PRD](../prd/PRD-内置Skill能力整合.md)优化，保留原页面及表单，重点改进调用、专业方法和产出内容，覆盖影视分析与已有文章／公众号／小红书文档整理。恢复及真实验收见[执行计划](../plan/PLAN-内置Skill能力整合.md)。

平台解析作为服务级能力统一设计，覆盖全部已登记 Provider；自部署允许持久保存平台浏览器上下文，不引入互联网服务运营机制。解析架构、内容范围与验收统一见[设计 17](17-解析引擎重建.md)。

**做什么**

- 公开或部署者有权访问的视频链接：来源发现、解析、格式选择、下载、制品校验。
- 本地 MP4 与剧本文档（DOCX、可提取文字的 PDF、TXT、Markdown、Fountain）导入。
- 影视研读与文章／公众号／小红书文档整理：在现有来源直接调用内置 Skill，阅读并导出报告。
- 管理端：用户、文件、平台目录、AI 服务、下载分析、系统操作日志。

**不做什么**

- 内容范围按设计 17 的 public／personal_full／official_share 声明执行，不解密 DRM 媒体；不做账号密码、验证码、2FA 自动化；不使用公共解析站、公共代理或 MITM。
- 不开放任意 yt-dlp／gallery-dl 参数、输出模板、Shell 或文件路径；不接受用户上传自定义 Skill。
- 不提供直播录制、无限播放列表、频道归档、OCR、图片型 PDF、批量文件任务、在线协作编辑、内容写作、剪辑、图卡制作或账号发布。
- 普通业务请求不携带原始平台 Cookie；凭据接入通过独立受控通道完成。当前身份来源为普通 Chrome 中的扩展，接入方式见[设计 17 第 3.4 节](17-解析引擎重建.md#34-身份层)。

**判定原则**：URL 已登记、extractor 存在、metadata 成功、整文件下载成功、AI 分析成功是五个相互独立的状态，任何一个都不能推断另一个。
