# 内容能力、Skill 与执行 Harness

本页是帧取 AI 内容能力的重建规格。目标是从用户已有材料交付可直接使用、能够继续修改的文章、帖子、文档与专业审阅结果。Skill 提供方法，Harness 负责材料、计划、工具、审校、版本与恢复。产品入口和结果契约按任务重设计，现有二十个 Skill 与五种契约不作为必须保留的目标结构。

本文区分已实现、此次方法接入和待实现目标。现有执行事实见[AI 分析](10-AI分析.md)；Temporal／RabbitMQ 所有权与恢复规范见[工作流](15-工作流与平台下载目标.md)；成品包与公众号交接见[内容创作与发布](11-内容创作与发布.md)。系统设计只在这些主题文档维护。

## 1. 产品决策与证据

### 优先交付的工作

首批用户是已有视频、笔记或草稿、需要在公众号表达内容的部署者本人。第一条重建用例为“已有文字材料 → 公众号文章 → 编辑与回查 → 渠道成品包”。视频可以成为材料之一，但画面观察不能替代语音内容。短帖和说明文档共用材料与版本能力，专业视频／剧本任务按自己的用途保留。

选文字材料作为首批入口，是为了先验证写作与交付，避免让 ASR、图片和平台账号接入同时决定首条用例是否成功。可靠转写、配图和公众号草稿交接逐步接入。首批不扩张为互联网写作平台，不引入协作编辑或通用 Agent 工作台。

这项优先级来自本次用户反馈和代码约束，尚无使用频率、访谈或商业需求数据。“更多 Skill 就会改善成稿”是待验证假设，方法数量不作为产品指标。

### 已核对的实现问题

“AI 感重”具体拆为：信息空泛、无依据推断、模板栏目、无效重复、编辑过程残留、作者声音被统一。它们可通过材料、稿件和用户修改核对；不使用 AI 概率检测器判定质量。

### PM 方法与研究边界

本地 pm-toolkit 2.1.0 可用的相关方法是 grammar-check：先确定目的、读者与语气，再按位置、问题、修正、理由检查逻辑和行文。该包不提供战略规划、写作引擎或 Temporal 编排。产品取舍补充采用已安装的 pm-product-strategy:product-strategy、pm-product-discovery:opportunity-solution-tree／identify-assumptions-existing，需求组织参考 pm-execution:create-prd。自部署个人工具不套用销售增长、市场份额与护城河结论。

## 2. 用户任务与方法库

用户先选要完成的工作，再选必要的用途和关注项。领域方法在后台组合，普通用户不用理解二十个方法名。管理员维护固定版本的方法包，用户不能上传脚本或任意 Skill。

| 一级任务 | 主要交付 | 原 Skill 的处置 |
| --- | --- | --- |
| 写文章与文档 | 公众号文章、说明文档、教程；正文与回查独立 | video-to-article 整体重写为多材料写作；视频仅为一种来源 |
| 制作传播内容 | 短帖、开头、标题和候选片段组成对应方案 | 合并 highlights、opening-hook-review、short-video-packaging 的入口；方法按需保留 |
| 审阅成片 | 核心判断、需要修改的地方、保留理由与源位置 | comprehensive 重写；director-breakdown、narrative-structure-review、editing-rhythm-review、continuity-quality-review 成为关注项 |
| 拆解与整理素材 | 分镜表、场景表或资产目录 | 合并 visual-shots、scene-extraction、asset-catalog 的入口，按所选交付物独立返回 |
| 审阅剧本 | 优先修改与逐场定位，可选人物／对白／结构等专项 | screenplay-analysis、drama、character、scene、dialogue、structure、continuity 七项合并入口；保留专业方法 |
| 改写与翻译 | 可编辑文本候选、源版本对照、术语一致性 | 保留 screenplay-rewrite 的用途，重建 brief 和验收 |

这是目标入口，当前 API／客户端仍提供二十个 Skill。不能只改显示名或添加六个按钮就宣称迁移完成。文章、帖子和说明文档也不会按一个通用长文模板输出。

方法包按职责分为材料观察、领域判断、写作、审校、视觉策划和渠道排版。领域研究保留有用方法，淘汰重复的全文常驻指令；Humanizer 只提供审校线索，不强制所有句子“口语化”。作者提供的自有范文用于表达偏好，不允许据此虚构亲历或借用他人的身份。

## 4. 材料、brief 与成品版本（目标）

### 正式输入

材料集合绑定本任务，每份材料固定来源类型、权威版本、摘要和允许用途：

| 类型 | 处理方式 | 可支持的内容 |
| --- | --- | --- |
| 用户正文／笔记／草稿 | 保存原文版本与段落／字符定位 | 原文事实、作者立场和已有表达；作者声称的外部事实不自动变成已核验事实 |
| 规范化剧本文本 | 沿用现有文档导入与源场顺序 | 场景、人物动作、对白与文本结构 |
| 视频制品 | 沿用完整制品、权威时长与有界视觉读取 | 可见事件、画面文字和状态；抽样覆盖缺口单列 |
| 字幕／转写 | 后续作为独立来源，保留生成方式、修订、覆盖与时间定位 | 可读语义；不能把未校正转写作为确定身份或精确引语 |
| 用户确认的参考页面／文档 | 首批上传或粘贴；后续按明确研究范围受控采集并固定快照 | 正常引用与补充资料，保留来源与获取日期 |
| 作者范文／视觉资产 | 单独标明表达偏好或插图用途 | 范文不授权借用事实与亲历；生成图不充当实拍证据 |

网页采集是独立授权的资料获取能力，不能因为“写文章”就自动遍历网络。不可读扫描件、OCR 和 ASR 未实现时明确拒绝或请用户提供可读材料，不由模型补全。

### 最小 brief

用户需要确定交付类型和材料。系统提供可编辑的读者、目的、中心问题、表达偏好、长度意图、渠道与允许来源；可选项采用默认值，并记录用户值和推断值的区别。作者提供的必须保留内容、禁止改动范围和自有范文同样固定。

不要求用户配置 Prompt、模型、阶段或 Token。短稿默认按信息量决定篇幅；用户锁定长文而材料不足时，给出具体缺口或请求允许收窄，不静默把目标改为另一类成品。一般文章不强制每次确认选题、提纲或标题；复杂材料先形成可编辑提纲，用户请求先看提纲时才等待。

### 有限成品模型

重建内容契约支持文章、短帖和说明文档。最小结构为：

- document_type、title（文体需要时可为空）、受控内容 blocks、语言和不可变 source_set_ref。
- block 为段落、小标题、列表、引用、表格、代码或图片占位；每种有独立严格 Schema。首批先支持段落、小标题、列表、引用，随后逐项加入表格／代码／资产。
- lead、closing、key_points 不再作为所有文体必填字段；正文自然形成开篇和结尾。短帖可以只有一段，说明文档按读者任务组织。
- evidence_index 单独记录关键陈述与材料位置；review_findings、coverage 和制作状态独立保存，不拼进正文。
- 资产通过本任务资产 ID 引用，不接受任意路径、HTML、脚本或模型填写的远程图片 URL。真实资料图和生成插画分开标识。
- 读者需要的普通引语、参考资料和来源链接可以正常出现在正文；编辑日志、时码清单、字段释义和生成说明不属于成品。

这不是支持任意富文本的超级 AST。新增 block 必须有对应编辑、校验、三端显示和导出用例，不能只加一种 JSON 值。

### 其余任务的结果边界

目标由下面的职责界定，不要求固定沿用五种旧契约。具体公开 kind、严格 Schema 和字段上限在相应用例实现时一起定稿：

| 结果职责 | 最小内容 | 不再强制的内容 |
| --- | --- | --- |
| 内容文稿 | document_type、有限 blocks、材料版本、独立证据索引 | 每章视频时码、导语／结尾／要点栏、固定章节数 |
| 审阅结果 | 核心判断、带位置与依据的 findings、保留项、优先行动；视频／剧本按专业 profile 组织 | 全量分镜、高光与资产，以及无依据的修改项 |
| 分镜／场景拆解 | 有序单元、权威范围、边界类型、内容与关系 | 传播包装、制作建议与叙事长文 |
| 资产目录 | 候选身份、可见特征、状态、出现／变化位置与归并依据 | 完整视频审阅报告；未知真实身份的补全 |
| 传播候选 | 候选片段与对应标题／开头／文案、适用条件和比较理由 | 预测点击／留存／转化；把未拍内容写成已出现内容 |
| 改写／翻译候选 | 源版本和选定范围、对应文本候选、变化说明及需要时的术语表 | 全套审稿报告、未选区域的重写、固定扩写 |

中间 findings、覆盖说明和最终读者正文各自存储。共享引用与错误规则，不把全部任务重新塞进一个可任意加字段的通用报告。

目标示意，尚未登记到模型 Schema 或 OpenAPI：

~~~json
{
  "kind": "content_document",
  "document_type": "post",
  "title": null,
  "language": "zh-CN",
  "source_set_ref": "sources-cup-demo",
  "blocks": [
    {
      "id": "paragraph-1",
      "type": "paragraph",
      "text": "杯盖旋紧后，杯子短暂倒置，桌面没有出现可见水滴。长时间携带时的表现，还不能由这次演示判断。"
    }
  ]
}
~~~

证据、来源集合、brief、计划和审校数据按关联记录保存，不在正文内重复。这一杯子示意是人工构造校准材料；真实文章样例应来自信息更充分的文字或多份材料。

### 编辑与派生

用户修改保存新文稿版本，原版和材料不变。局部改写只处理选定块及必需上下文，返回修改候选和差异；接受后形成新版本。需核对的关键事实重新审校，原稿中未经改动的已核对事实可以按摘要复用；用户手动修改不自动标记为“审校通过”。

成品文稿、HTML／Markdown／DOCX、封面与公众号包分别记录各自绑定的内容版本。正文修改会使旧渠道包失效，已有已下载文件仍按原哈希保存。导出失败只恢复导出，不重写正文。

## 5. 受控执行 Harness（目标）

### 职责

| 层 | 主要职责 | 不应承担 |
| --- | --- | --- |
| 产品任务 | 明确交付、材料、读者和允许改动 | 把二十个方法名交给用户猜 |
| 方法包 | 领域标准、写法、局部正反例和审校准则 | 账号配置、文件系统流程与无限代理调用 |
| 执行计划 | 选定有限阶段、能力、预算、停止条件 | 模型自行增权、改预算或改变用户目标 |
| 工具 | 有界读取本任务材料、按批准流程制作资产 | 任意 Shell、路径、外网访问和平台写入 |
| 审校 | 对照材料、brief、作者表达定位问题 | 自动扩写缺失事实、以自评分代替人验收 |
| 版本与交付 | 保存成品、独立回查、生成用途对应的制品 | 把中间工作记录塞进成品 |

采用 [Agent Skills 的分层资源方法](https://agentskills.io/specification)组织阶段上下文。完整来源与方法快照固定，阶段只读取需要的片段；每个阶段摘要包括 brief、材料版本、片段选择、Prompt、Schema、Provider 与审校规则。字符长度仅作成本诊断，不据此断言效果。

### 根据任务选择阶段

| 路径 | 应用级付费阶段起始上限 | 跳过条件 |
| --- | --- | --- |
| 短帖／已有成熟短稿 | draft 或 edit → review；有重大问题再 revise → verify，最多 4 次 | 已有稿件仅排版时不生成正文；确定性整理可零模型调用 |
| 公众号文章／说明文档 | draft → review；一次 revise → verify，最多 4 次；复杂材料增加 outline，上限 5 次 | 简单材料跳过提纲；审校通过跳过修订与复核 |
| 视频参与写作 | 额外一个 journaled observe 阶段，起始总上限 6 次 | 已有可复用观察证据则不再次观察；不把抽帧本身都做成模型调用 |
| 长剧本／长文 | 按权威分块数、汇总和必要全局核对计算 | 首次付费前确定块数和上限，不能先做一半再临时扩预算 |

这些是起始试点预算，不是已生效配置。每条计划同时固定总期限、工具调用数、字节上限、模型阶段数和修订次数；CLI 内部模型轮次不可见时，只承诺应用级请求、工具和墙钟约束，不承诺精确 Token 或费用封顶。

材料检查先做确定性可读性、类型、大小和所选能力检查。材料能否支持命题属于语义判断，可包含在首次已预算的提纲／成稿阶段；不能声称一切材料不足都能在付费前识别。需新材料则返回具体缺口，等待用户补充后以新材料版本创建新运行。

### 独立审校

审校阶段不读生成者自评；读取稿件、材料、brief、作者表达和本任务准则。按 pm-toolkit 的位置、问题、修正和理由给出 findings，先处理事实、推断和任务偏离，再处理重复与表达。只保留作者会据此修改的问题，不为凑数润色合理短句、口语或术语。

finding 具有 block_id／field_path、类别、严重度、源位置、问题与局部修正目标。位置必须属于草稿，源引用必须属于本任务；“整体再自然一点”不能触发自动全文重写。blocking／major 未解决不得将稿件标成审校通过。minor 不强制触发额外付费。

独立调用同一模型仍可能有共同盲点。严格解析只证明结构正确，位置引用只证明位置存在；关键主张支持与反例需要内容核对，最终效果需要真人评审。

## 6. Function call 与应用操作（目标）

依据 [OpenAI function calling 文档](https://developers.openai.com/api/docs/guides/function-calling)，函数声明只约束请求格式；实际权限、来源绑定、大小与预算由应用执行函数再次校验。Claude／Codex 按各自正式协议适配，不把某一 JSON 格式直接装进 loader。

| 操作 | 参数与返回 | 当前状态、调用者与副作用 |
| --- | --- | --- |
| probe_video | 无自由参数 → 本制品技术元数据 | 已有；模型可请求，只读 |
| inspect_video_overview | start_ms、end_ms → 本制品 16 帧区间概览 | 已有 CLI 工具；区间、时长与帧大小受限 |
| inspect_video_frame | timestamp_ms → 本制品附近单帧 | 已有 CLI 工具；不接受路径 |
| read_material | material_id、segment_id → 有界文本、定位与摘要 | 待实现；模型读取本任务授权版本 |
| read_source_span | citation_id → 原文／观察定位与上下文 | 待实现；只回查 evidence_index 中有效引用 |
| list_material_segments | material_id、cursor → 本材料段落目录 | 待实现；按页限制数量、文本与游标 |
| 可靠转写／资料采集 | 固定材料 ID／已批准资料候选 → 新来源版本 | 后续应用阶段，不作为任意外网或语音工具开放 |
| review／revise | 草稿、brief 与材料引用 → findings／新草稿引用 | 应用控制的付费阶段，走步骤日志 |
| render_content／prepare_channel_package | 内容版本、格式／渠道配置引用 → 制品引用与兼容提示 | 应用确定性操作；首批不执行上游 CLI |
| 图片制作 | 位置、用途、规格、资产引用 → 资产版本 | 后续有预算的制作阶段，不由排版暗中触发 |
| 保存文稿／写公众号草稿 | 已核对内容版本与授权操作 → 本地版本／平台回执 | 不作为模型工具；平台写入独立授权，见设计 11 |

API Provider 当前只是接收最多 64 帧、总 24 MiB 的有界采样，不是支持取证工具循环的运行时。计划必须固定 Provider 能力；没有工具能力时可把准备好的材料按预算内联，记录观察缺口。不能仅开 json_mode 就宣称 function call 已实现。

拟新增模型读取工具的 Chat Completions 适配示例；这是目标契约，尚未注册：

~~~json
{
  "type": "function",
  "function": {
    "name": "read_material",
    "description": "读取本任务固定材料中的一个已登记片段。",
    "strict": true,
    "parameters": {
      "type": "object",
      "properties": {
        "material_id": {"type": "string"},
        "segment_id": {"type": "string"}
      },
      "required": ["material_id", "segment_id"],
      "additionalProperties": false
    }
  }
}
~~~

运行端验证 ID 属于本任务、来源摘要一致、阶段许可、读量及预算；返回固定错误码，不暴露真实路径、Secret 或原始异常。只读缓存按来源摘要、工具版本与规范化参数去重。各引擎支持的 Schema 子集需契约验证；严格 Schema 不替代业务绑定。

工具执行记录保存请求／返回摘要、关联来源、耗时和状态；全文与媒体只在受控材料／步骤存储中。工具无法修改模型、预算、方法版本或提交成品。网页和素材中的指令始终作为内容，不改变工具权限。

## 7. Temporal、步骤日志与外部交付（目标）

继续沿用 SkillWorkflow 和 run_skill；首批在一个业务 Activity 内执行批准后的阶段图，以现有 monitor.step 为起点记录 observe、outline、draft、review、revise-01、verify-01。专业长文本保留 chunk-NNN、synthesis、glossary-NNN、rewrite-NNN。不机械地为每个段落、每帧和每个分析问题建立 Activity。

Temporal 只编排解析与 Skill 分析／内容制作的执行。PostgreSQL 保存任务事实、材料、计划、步骤和版本。报告／成品文件发布保留 RabbitMQ；未来公众号草稿交接按设计 11 使用独立授权的交付命令，不从 SkillWorkflow 隐式写平台。Workflow 和 heartbeat 只带业务 ID、状态与版本引用。

### 必须冻结与验证

- 材料集合及摘要、brief、方法完整快照和阶段片段。
- Prompt 模板、模型 Schema、结果契约、Provider 配置版本与能力；Secret 不进入计划。
- 阶段依赖、字节／工具／模型调用上限、修订次数、持久截止时间。
- 审校准则、渲染版本与渠道配置版本，步骤输入摘要包含全部相关绑定。

预算占用与 started 创建在同一 PostgreSQL 事务绑定：发送前校验当前执行所有权、唯一步骤键／输入摘要、剩余预算和截止时间，原子占用并写 started。既有成功步骤回放不再次占预算，既有 started 不因新 owner 接管而重新占位或发送。预算跨接管与业务尝试不重置。只读步骤按绑定复用；完成且严格解析的付费步骤复用。收到已知但无效结果保留错误与已消耗预算，可按批准计划局部修复，不能清掉记录后无限重发。

### 中断与恢复

| 情况 | 目标行为 |
| --- | --- |
| 请求尚未发出，能证明无外部执行 | 可恢复同一步；预算退还必须有确定证据 |
| 返回且已保存成功步骤后进程退出 | 接管复用结果，不再次计费 |
| 请求已发出，结果未保存，超时／连接中断／Worker 崩溃 | 无幂等查询能力则 outcome_unknown，终止自动重调；普通 TimeoutError 返回不代表供应商未执行 |
| 审校确认缺少材料或存在不可修问题 | 业务终止或 needs_material，Temporal 不靠基础设施重试修内容 |
| 用户取消，旧 owner 随后返回 | 终止工具／模型会话；旧所有权拒绝迟到写入 |
| 内容已保存，DOCX／HTML 制品失败 | 只恢复制品，不重新生成正文 |
| Provider 配置更新或被禁用 | 当前运行使用冻结配置；不可用则归类失败，新运行才用新配置 |
| 公众号写入超时 | 与本地导出不同；先核对平台回执，未知结果不自动重写 |

Activity 可能至少执行一次，[Temporal 官方错误处理](https://docs.temporal.io/develop/python/best-practices/error-handling)要求结合业务幂等处理重试。Temporal 不保证供应商模型或平台写入恰好一次；上述未知保护是项目自己的业务机制。重放、取消、心跳与故障演练见设计 15。

目前 Provider／上层 Prompt／Schema／预算未全部冻结，普通模型超时也未全面改为未知结果分类。必须先完成这些前置项，再上线新增多阶段调用。此文没有改变当前运行代码或完成 Temporal 服务验收。

## 8. 成品与验收

### 文体各自成立

| 成品 | 读者能获得什么 | 不应出现 |
| --- | --- | --- |
| 公众号文章 | 可独立阅读的主题、叙述或论证，必要时有自然小标题与配图 | 编辑摘要、时码清单、生成解释、发布前删除提醒 |
| 短帖 | 一个清楚且被材料支持的完整表达 | 把长文截断、强制标题导语结尾、虚构人设 |
| 说明文档／教程 | 明确对象、步骤或机制、必要例子与正常参考 | 所有段落写成营销稿、省略关键操作、无依据效果承诺 |
| 审阅报告 | 定位问题、保留理由、修改目标与检查方法 | 为完整栏目硬凑优缺点、把事实复述当分析 |
| 时间线／资产目录 | 有序可回查的数据与身份／状态关系 | 无关散文、未经支持的真实身份 |

文章 Markdown／DOCX 与 Web 正文分离已在 a46f8f3f 落地。现有文章仍受旧纯文本字段与视频来源限制。旧文件不覆盖，App／Electron 未同步；新有限内容模型、编辑、多材料、HTML 和渠道包均待实现。

### 必须通过的产品场景

1. 信息充分的用户稿件可完整阅读、复制和导出，无需删除工作说明。
2. 极短视频保持所选文体、按信息量缩短篇幅；改成帖子须用户接受。锁定长稿且材料不足时明确缺口，不补品牌、体验或效果。
3. 作者口语、必要术语、有意短句得到保留；去模板检查不能制造统一声音。
4. 正常引语、表格、代码和资料链接保留为读者内容，工作记录独立。
5. 用户局部改写保持未选段与源版本；新包绑定新版本，旧文件哈希不变。
6. 无音频、矛盾材料、无问题原稿、中英文和跨材料引用有明确处理。
7. Web／App／Electron 依相同契约显示完整成品；390px、明暗主题、复制与实际 Word／公众号编辑器分别验收。

### 评估与指标

先收集有授权的真实材料，首批文章、短帖和说明文档各准备校准样本与独立留出材料；建议总计 30 份作为起始试点，具体数量、读者与预算在试点启动时固定。相同作品的剪短版不横跨两组。当前未完成收集或模型效果基线。

首批文字材料不能在当前 video-article 上直接运行。新材料与内容契约实施后，建立“复用旧方法的单阶段写作”作为对照路径；再分别比较选定 baoyu 方法、相同方法加独立审校／修订、以及同一正文的渠道排版。新对照路径不是现有全文字能力，也不是已经取得的基线。方法、取证、模型和排版分别比较，避免同时替换后无法归因。评审随机隐藏版本；部署者的采用决定与对应读者的专业评价分开记录。

核心指标为实际任务中“本人接受为可继续使用成品”的比例，并分别统计放弃、失败与待补材料；测试夹具和人工写样不计入。记录达到采用前的编辑时间、重大事实修正和结构重写原因，不以机器字符差比例替代用户判断。自部署工具不拟定用户增长或收入指标。

拟定放行门槛：工作说明清理次数为零；留出材料零已知关键事实错误；自然、连贯、用途匹配由读者逐项给理由；采用偏好与编辑时间至少改善一项且其余不出现重要退步。试点启动前固定采用判据、评分锚点、编辑时间统计口径与不可接受退步范围，不能事后解释标准。报告真实分母、平局与分歧，不把小样本百分比宣称为稳定效果。

工程检查独立覆盖绑定、解析、恢复、预算、取消、Provider 漂移、导出失败与渠道未知回执。任何静态、单元或合成样例结果都不代表模型成稿、Office 排版或公众号真实交付已经验收。

替换契约是完整业务变更，不建立 /v2、平行旧 API 或长期兼容执行器。停止新接单并排空旧运行、旧报告 Outbox／RabbitMQ 投递、发布中的制品与恢复任务，再切换契约和渲染器。只有所有旧操作均已完成或明确终止，才能删除旧执行路径；不能把“分析运行结束”当成导出链路已经排空。

按当前态 SQL 与业务转换验证现有记录；旧文章字段可确定性转为正文 blocks，时码转为独立证据，已有文件仍保留原字节与哈希。不得把历史稿件自动标记为新增独立审校通过。不可确定转换的记录明确为仅保留原制品的状态，供可读／可下载，不再传给已删除的旧 parser 或执行器，不重新调用模型修历史数据。

每次结构变化同时验证空隔离库和已有当前态测试库、重复应用 SQL、源绑定、历史制品下载与新任务全链路。生产库不在本次规划中改动。目标结构、当前 API 和新方案的区别在发布验收前明确检查，不能仅更新 Skill Markdown 就宣布完成迁移。
