# 内容成品与公众号交接

本页定义文章、帖子和文档的成品包、渲染与公众号交接目标。写作材料、Skill、审校、function call 和 Temporal 计划统一见[内容能力与 Harness](16-Skill体系与结果契约.md)。当前普通文字材料创作、独立审校、只读结果、报告历史及 Markdown／DOCX 已实现。资产、完整渠道包与平台连接器仍是待实施规格。

## 用户完整流程

用户选择要交付的内容，提交已有材料，填写最小 brief；系统按材料与用途起草、自动审校并按预算修订，保存只读分析结果。用户阅读成品、回查关键事实并导出。材料或要求变更时新建任务；小范围文稿编辑在导出的 Markdown／DOCX 或公众号编辑器中完成。创建公众号草稿是独立操作，需要用户针对确定的账号和内容版本发起。

默认操作顺序是阅读与回查、复制／导出、准备公众号包、按需写入账号草稿。无需平台账号也应能完成前三步。工具配置、来源快照、生成过程和校验日志保存在工作区，成品里不附“发布前删除”说明。

用户需要的正常引语、资料引用、教程步骤和技术代码属于正文；内部时码清单、Prompt、工具调用和核验日志不属于正文。封面、摘要是渠道元数据，不能为它们把文章的结尾改成编辑报告。

## 内容版本与渠道包

| 记录 | 保存内容 | 更新规则 |
| --- | --- | --- |
| 生成报告 | 有限内容结构、固定材料集合、brief 与自动审校记录 | 新任务或显式重跑保存新的分析结果，不覆盖已交付文件 |
| 资产版本 | 来源、资料图／生成插画类别、用途、裁切与文件摘要 | 绑定内容位置；修改不覆盖已引用资产 |
| 渠道包 | 文稿版本、账号／渠道配置版本、正文、标题、摘要、封面和制品清单 | 原文或相关配置改变后重新准备，不复用过时包 |
| 平台交接记录 | 已授权包、账号引用、步骤状态与平台回执 | 外部执行前保存 started；未知结果先核对，不直接重发 |

生成结果复用 analysis_jobs、analysis_runs 与现有报告存储。站内没有正文编辑器、人工修订写接口或作者版本管理；历史保存稿只读回查，保留来源身份和文件。未完成新报告发布时继续显示上一可用结果。资产、渠道包与平台交接仍是业务记录概念，尚未新增表或 HTTP DTO。实现时同步唯一当前态 schema.sql、ORM、删除规则、配额、OpenAPI 与客户端。成品文件复用现有私有对象存储、大小与哈希验证。

源材料与已生成报告被引用时保留；删除文章、包或资产通过既有锁与保留政策处理，不意外清理被其他版本引用的对象。用户删除或取消阻止新的写入；已经产生的平台草稿需准确说明其存在，不把取消本地任务当作远端草稿已经删除。

## 格式与阅读

成品格式只保留 Markdown／DOCX，提供完整正文与独立回查；不提供 HTML 文件导出。公众号编辑器交接按真实连接器需要规划，再按用途接入表格、代码、图片、图表与账号主题。

| 格式 | 必须成立的行为 |
| --- | --- |
| Markdown | 从标题到结尾完整可读；引用与正文层级自然，没有编辑附录 |
| DOCX | 可编辑正文，合理标题与段落；不含分析报告页眉／页脚、生成提示词或伪造作者署名 |
| 短帖 | 直接得到短内容，元数据与备选表达独立；不强制套长文的开篇、小标题、总结 |
| 说明文档 | 保留完成工作需要的步骤、代码、表格和参考；排版不为了营销效果隐藏关键细节 |

渲染器根据有限内容结构生成格式，正文语义版本保持一致。图片在富文本转换后仍能定位，标题不重复，引用不失真，代码与中英文排版正常。公众号复制结果必须在真实编辑器中验证；网页看起来正常不证明粘贴、上传后仍正常。

不直接执行 baoyu 的 Markdown／图表 CLI。先实现只涉及本地内容的确定性转换；需要 Mermaid／SVG 时由受控转换器处理，经大小、时间、网络和输出检查。没有已验收转换能力时给出明确不支持项，不把格式化失败送回写作模型扩写。

## 配图与封面

吸收 baoyu-cover-image 与 article-illustrator 的“用途先于图”方法。图片只在解释概念、展示真实资料、比较信息或辅助步骤时加入；允许零图，不以章节数量决定配图数量。

制作规格包含内容版本、块位置、图片目的、尺寸意图、品牌配置、文字和来源。真实视频截图、用户资料图、生成插画分别标记。没有图像工具或预算时保留图片位置建议，不显示成已生成资产；生成插画不作为产品测试、真实人物或事件的证据。

采用新的生成报告时，相关图片与渠道包需重新检查，不自动重做所有图片。实际图片生成是单独付费步骤，固定模型、规格和预算，遵循与文本生成同样的未知调用保护。首次真实调用前需要相应工具、凭据和使用范围；引用 Skill 不自动获得这些能力。

## 公众号草稿连接器（后置目标）

采用独立项目连接器，不把 baoyu-post-to-wechat 的浏览器、Home 配置或发布脚本嵌进 Skill 执行器。本地包预览、素材上传、创建草稿、公开发布四件事分别建模。

首个连接器目标只做到“写入用户授权账号的草稿”。公开发布不在首个实现范围，不能用接口草稿成功提示“文章已发布”。用户对本轮设计的授权不等于对任何账号写入的授权；有可审阅成品和已连接账号后，用户明确触发写入。

采用官方 API 作为首选候选，是否可用于具体账号由权限和真实回执验证决定。不预先承诺账号资格、API 配额或公开发布能力；这些条件在实现时查阅微信官方文档，并以账号实际权限确认。浏览器自动化只有 API 不满足已明确用例时才另行设计。

### 写入前

- 展示完整预览、账号、标题、摘要、封面、正文版本与写入类型。
- 检查包绑定的内容版本和账号配置，阻止旧包写入。
- 凭据保存在项目受控的连接配置中，按已有密文与脱敏机制管理；不读取上游 .env，不放进 Prompt、Workflow History 或客户端。
- 保存授权操作和摘要后再执行外部请求。用户请求写入同一包的重复提交复用同一个本地操作，不能生成第二个自动操作。

### 执行与回执

每次素材上传和草稿创建前，都重新核对操作所有权／lease、取消状态、授权绑定和包／账号配置版本。旧 owner 或取消后已经发生的外部副作用，其确定回执仍补记到原操作；只能记录该请求的结果，不能将它算成新版本成功或改变已取消状态。不能丢弃回执后再盲目重试。请求已被平台接受后，本地取消不保证阻止平台完成处理。

| 步骤 | 记录与重复处理 |
| --- | --- |
| 上传正文图片／封面 | 每个资产先记录 started，返回素材 ID 后保存；成功结果按资产摘要和账号复用 |
| 创建公众号草稿 | 请求前固定操作、包与账号；保存明确返回的 draft ID 与状态 |
| 请求超时／返回丢失 | 记录 outcome_unknown；可查询并核对则核对，无可靠识别能力则停止自动重发，提示核对 |
| 已创建，回执保存后 Worker 退出 | 复用已保存回执，不再次创建草稿 |
| 用户选择新报告／切换账号 | 生成新包，原授权不用于新内容或新账号 |
| 部分素材已上传后取消 | 停止后续草稿写入；记录已有素材，不自动删除可能被引用的远端对象 |

平台未提供可用幂等键／确定查询能力时，不承诺恰好一次。依靠本地唯一操作避免重复提交，依靠未知结果停止与回执核对避免盲目重试；这仍不消除全部外部重复风险。

公众号交付命令通过 PostgreSQL 与 Outbox 事务进入现有 Worker 的独立监督组件，transport 复用 RabbitMQ 的幂等／租约边界。它不同于当前报告 Worker 上传私有 Markdown／DOCX，也不是新增 Temporal 第三条编排或第二调度器。只有独立凭据边界确有必要时再决定进程／容器拆分，不能为一个 Skill 新建一套运行平台。

## 实施与验收

顺序与设计 16 的实际边界一致：普通文字材料、只读报告与离线导出先交付，随后扩展图片／语义材料和渠道包，最后接入账号草稿交接。不得因末端连接器未实现，阻塞用户阅读、回查和导出成品。

验收至少包含：

1. 同一文稿在 Web、App、Electron、Markdown、DOCX 中正文完整，回查信息独立。
2. 正文在 390px、明暗主题下可用；公众号编辑器交接另行验证正常引用、图片位置、代码与中文不丢失。
3. 结果页没有正文修改／保存操作，人工修订接口不存在；历史生成报告和已有人工稿可只读回查，旧文件哈希不变。
4. 账号、包或封面变更时旧授权不可复用。
5. 素材上传、草稿创建、取消、超时、Worker 重启、明确回执与未知回执分别验证。
6. 实际账号中的草稿与本地包标题、正文和资产匹配，成功提示仅描述已完成的草稿操作。
7. 未连接公众号也可以完成生成、阅读、复制与导出，模型故障不改变原视频下载结果。

本轮已在现有本地服务应用规范 SQL 的增量结构、部署后端与 Web，并使用现有 AI Agent 完成真实文字任务；没有安装上游脚本、调用图像工具、连接公众号、写入草稿或公开发布。目标是否可用必须通过相应工程与真实渠道验收，文档、单元测试和生成样例均不能替代。
