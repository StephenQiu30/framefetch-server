# 可靠性与运行

## 故障隔离

- API readiness 只检查 PostgreSQL 结构、MinIO、RabbitMQ 与 Redis，不探测 Runner 或平台。平台故障以稳定错误码与任务结果表达。
- `worker` 不等待平台健康；每个后台组件独立监督，单个组件失败按退避重启，不影响其他组件。
- 进程健康不证明平台可用；出口信誉与平台要求以实际任务验证。

## 停止与恢复

| 链路 | 恢复方式 |
| --- | --- |
| 解析 | Temporal 持久调度；120 秒截止不因恢复重置；当前 generation 与状态拒绝迟到提交；取消经同事务 Outbox 传递 |
| Skill 分析 | Temporal 调度；替补 Activity 以新的执行者 fence 接管；取消由数据库标记并经心跳感知；步骤日志防止中断的模型调用被自动重发 |
| 下载、导入、报告 | RabbitMQ 消费者 + PostgreSQL 租约；下载有限排空 60 秒，容器停止宽限 90 秒；sweeper 与 DLQ 兜底 |

RabbitMQ 队列为 `video.download`、`video.import`、`video.analysis-report`、`video.events` 及各自的 `.dead` 队列，按角色授予最小权限。宿主 AI Worker 不需要 RabbitMQ 账号。

## Temporal

复用已运行的 Temporal 服务，History 与 visibility 的持久化、备份和启动方式由该服务管理。项目只维护连接参数与业务命名空间：首次连接时幂等创建命名空间，保留 7 天。容器默认连接 `host.docker.internal:7233`，宿主 Worker 默认连接 `127.0.0.1:7233`。API 读取历史不依赖 Temporal 在线。

## 发布

本地代码开发使用 `docker compose up --build --watch`；已有本地业务容器使用 `docker compose watch --no-up` 启用监听。本地与 CI 使用 Docker Compose 5.5.1，覆盖 `initial_sync` 与可选 `env_file` 的配置解析；CI 通过契约测试检查专用身份环境文件的注入范围，不启动业务容器。前端使用独立的 development 镜像阶段，源码同步触发 Next.js 热重载，宿主 `node_modules`、构建产物与环境文件不进入容器。API 与 worker 同步 Python 源码后按各自停止宽限重启进程；依赖清单与锁文件变化重建镜像。Runner 保留只读媒体沙箱，源码变化自动重建该服务；代码更新可能中断在途操作，恢复规则见[停止与恢复](#停止与恢复)。

只维护两份 Compose：`docker-compose.yml` 完整定义业务服务，按角色显式注入连接参数、密钥与常用部署选项，队列及死信绑定由消息模块幂等声明，重试规则由下载与分析业务模块维护，均不接受环境变量覆盖；超时等应用默认值由 Settings 维护；`docker-compose-env.yml` 独立提供 PostgreSQL、RabbitMQ、Redis、MinIO，仅在缺少现成服务的环境显式启动。业务 schema 仅由业务入口的 `migrate` 服务应用，基础设施入口不重复迁移。Temporal 单独提供。本机默认 `APP_ENV=development`、`FRONTEND_BUILD_TARGET=development`；生产使用同一业务文件，设置 `APP_ENV=production`、`FRONTEND_BUILD_TARGET=runtime`，通过 `--env-file .env.prod` 选择生产配置，并配置实际 `SITE_URL` 与生产密钥。前端的 `NODE_ENV`、工作目录与启动命令由所选 Dockerfile 阶段提供；生产不启用 `--watch`。文档在 `docs/` 中通过 Obsidian 或文本编辑器直接维护，使用 Git 管理，规则见 [文档工作区](../../PROJECT.md#31-文档工作区)。数据库结构与环境配置不自动应用；修改 `schema.sql` 或 `.env` 后执行对应的发布步骤。

1. 暂停新接单，排空或取消在途媒体操作。
2. 对现有库幂等应用 `schema.sql`。
3. 配套更新 API、worker、Runner、Web 与生成客户端；配置变化用 `docker compose up -d --build`，不以 `restart` 代替。

Runner 内部协议变化须同时重建调用方与 Runner；接口破坏性变更同步 Web 与 App。不保留两阶段兼容或旧访问路线。业务记录与成功制品保留；升级与回退需要匹配的结构备份。

## 密钥

- 生产配置校验只要求当前角色需要的密钥：Import、Report、Outbox 不接收 URL 解密密钥；worker 不接收 JWT、管理初始化与指标访问密钥。
- `URL_ENCRYPTION_KEY` 必须稳定，并与数据库备份分开保管。媒体 RPC 使用签名密钥。
- 宿主 AI Worker 与业务容器显式选择同一环境配置；已有配置不得在启动时被覆盖或重新生成。

## 可观测性

日志、指标与诊断摘要不记录输入、凭据、上游错误文本或媒体 URL。系统操作日志见[解析意图](06-解析意图.md#恢复与历史)。

## CI

- `Backend tests`：uv frozen、Ruff、strict mypy、pytest（PostgreSQL 隔离 schema、Redis 租约、FFmpeg 视频观察证明、本地 Temporal 测试服务）。
- `Frontend tests`：pnpm frozen、OpenAPI 生成无漂移、Biome、tsc、Vitest、Next.js build。
- `Docs`：身份扩展测试与文档链接、锚点检查。
- 依赖缓存不替代安装或质量检查；main 每个推送 SHA 独立运行，PR 新提交取消旧运行。推送后的逐提交验证规则见 [贡献指南](../../CONTRIBUTING.md#ci)。
- CI 不证明目标部署或真实平台可用；`main` 未设分支保护，CI 不是合并门禁。
