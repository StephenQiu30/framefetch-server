# 可靠性与运行

- **故障隔离**：API readiness 只检查 PostgreSQL 结构、MinIO、RabbitMQ、Redis，不探测 Runner；Provider 故障由稳定错误与探针表达；worker 不等待所有 Provider；其中每个后台组件独立监督，单个组件失败按退避重启，不影响其他组件。
- **停止与恢复**：解析由 Temporal 持久调度，单 resolve Activity 使用 120 秒期限，当前 generation 与状态拒绝迟到提交，取消通过同事务 Outbox 传递。Skill 分析同样由 Temporal 调度，替补 Activity 以新的执行者 fence 接管运行，取消沿用数据库标记并由心跳感知；步骤日志保证中断的模型调用不被自动重发。下载仍为 60 秒有限排空和 PostgreSQL 租约恢复，容器停止宽限 90 秒；下载与导入按职责长期保留 RabbitMQ 的 sweeper／DLQ。RabbitMQ 中 `video.download`、`video.import`、`video.analysis-report`、`video.events` 及其 `.dead` 队列仍需相应受限角色权限；解析与分析队列已退出声明与消费，宿主 AI Worker 不再需要 RabbitMQ 账号。
- **可移植性**：业务 Compose 复用已有基础服务；浏览器与宿主身份按设计 17 隔离。出口信誉与平台要求由实际任务验证，进程健康不证明完整下载。

- **自部署更新**：先对现有库幂等应用 `schema.sql`，再配套更新 API／Worker／Runner／Web，配置变化用 `up -d --build`，不以 `restart` 代替；更新前排空在途任务，不保留两阶段兼容或旧访问路线。Runner 内部协议变化须同时重建调用方与 Runner；接口破坏性变更同步 Web 与 App。
- **密钥**：生产密钥检查只要求当前角色所需密钥；Import／Report／Outbox 不接收 URL 解密密钥，Worker 不接收 JWT、管理初始化及指标访问密钥。持久数据使用的 `URL_ENCRYPTION_KEY` 必须稳定并与数据库备份分开保管；媒体 RPC 使用签名密钥，平台 Cookie 不进入业务数据库。宿主机 agent 与业务容器必须显式选择同一环境配置；已有配置不得在启动时覆盖或重新生成。
- **可观测性**：日志不记录输入、凭据或上游错误文本；日志、指标、诊断摘要不含媒体 URL；系统操作日志见 [解析中心](06-解析中心.md)。
- **CI**：`Backend tests`（uv frozen、Ruff、strict MyPy、pytest、PostgreSQL 隔离 schema、Redis 租约）与 `Frontend tests`（pnpm frozen、Biome、tsc、Vitest、Next.js build）；OpenAPI 生成产物无漂移；CI 不能证明目标部署与真实平台可用，也不是强制合并门禁（当前 `main` 无分支保护）。

Temporal 复用已运行的服务，History／visibility 的持久化、备份与启动方式由该服务配置管理；项目只维护连接参数和业务命名空间，首次连接时幂等创建命名空间，保留 7 天。容器默认连接 `host.docker.internal:7233`，宿主 Worker 默认连接 `127.0.0.1:7233`。API 历史读取不依赖 Temporal 在线，积压仍受业务配额和解析截止时间限制。
