# 可靠性与运行

- **故障隔离**：API readiness 只检查 PostgreSQL 结构、MinIO、RabbitMQ、Redis，不探测 Runner；Provider 故障由稳定错误与探针表达；Worker／Canary 不等待所有 Provider。
- **停止与恢复**：下载 Worker 60 秒有限排空，容器停止宽限 90 秒；租约过期后由 PostgreSQL 回收与 Outbox 重投；sweeper 覆盖 queued／lease／retry 三层恢复；死信队列有审计重放。RabbitMQ 中 `video.download`、`video.download-intent`、`video.events` 及其 `.dead` 队列需为对应受限角色授予 configure／write／read（及 topic permission 的 routing key），Worker 不获管理员权限。
- **可移植性**：业务 Compose 依赖已有基础服务；固定公开平台不依赖 Chrome 登录态，其余平台还依赖已安装并获授权的宿主机 agent。来源故障不阻止 broker 进程就绪，但会使对应操作明确失败。登录态、验证码、出口信誉与账号权益由第三方平台控制，不能由仓库恢复，也不承诺任意出口通过风控。
- **发布**：先对现有库幂等应用 `schema.sql`，再配套发布 API／Worker／broker／Runner／Web，配置变化用 `up -d --build`，不以 `restart` 代替；发布前排空在途任务，不保留两阶段兼容或旧访问路线。内部会话协议变化须同时重建 broker 与 Runner；公开契约破坏性变更同步 Web 与 App 发布门禁。
- **密钥**：生产密钥检查只要求当前角色所需密钥；Import／Report／Outbox 不接收 URL 解密密钥，Worker 不接收 JWT、管理初始化及指标访问密钥。持久数据使用的 `URL_ENCRYPTION_KEY` 必须稳定并与数据库备份分开保管；会话中继使用 RPC 签名密钥，不再有平台 Cookie 数据库加密密钥。宿主机 agent 与业务容器必须显式选择同一环境配置；已有配置不得在启动时覆盖或重新生成。
- **可观测性**：日志不记录输入、凭据或上游错误文本；日志、指标、Provider 状态证据不含媒体 URL；系统操作日志见 [解析中心](06-解析中心.md)。
- **CI**：`Backend tests`（uv frozen、Ruff、strict MyPy、pytest、PostgreSQL 隔离 schema、Redis 租约）与 `Frontend tests`（pnpm frozen、Biome、tsc、Vitest、Next.js build）；OpenAPI 生成产物无漂移；CI 不能证明目标部署与真实平台可用，也不是强制合并门禁（当前 `main` 无分支保护）。
