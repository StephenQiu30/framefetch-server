# 影视 Skill 接入执行计划

## 1. 目标与执行规则

依据唯一[接入 PRD](../prd/PRD-影视Skill接入.md)，交付实测拉片、公众号成稿和剧本拆解三个核心任务，再按独立门槛交付翻译与 Codex 配图。[选型调研](../prd/PRD-AI分析Skill选型.md)是证据来源，不是已安装能力清单。

用户已启动实现。按依赖顺序验证完整上游包和核心最小链路，再推进正式任务与三端。计划命令本身不构成发布内容或改写用户数据的授权。

执行者每次领取一个满足前置条件的工作包，先核对最新代码和真实环境，再做最小充分变更。PRD 定义产品要求；Design 定义技术规则；本计划维护执行状态与证据。发现冲突时指出具体段落，不凭计划中的建议另建第二套实现。

### 1.1 读取顺序

1. 工作区及目标仓库 `AGENTS.md`；跨仓分别读取，不套用一个仓库的规则。
2. [PRD](../prd/PRD-影视Skill接入.md)及当前工作包对应的 FR／NFR／AC。
3. [AI 分析](../design/09-AI分析.md)、[报告导出](../design/10-报告导出.md)、[工作流编排](../design/13-工作流编排.md)、[产品边界](../design/01-产品定位与边界.md)和[唯一视觉标准](../../design.md)。
4. [固定上游来源](../prd/PRD-AI分析Skill选型.md#11-固定源码与许可)、相邻实现、测试与模块 README。
5. 当前工作区差异、运行配置、服务及凭据是否就绪；不得把旧记录当实时状态。

### 1.2 不可越过的条件

- 只保留一个正式执行链路；复用 AnalysisJob／Run／Step／Report、Temporal、宿主 Codex 与已有存储。
- 不私改上游包，不截取几段方法冒充整包，不把允许工具声明直接变成全局 shell／网络权限。
- 不覆盖 `.env`、基础服务或用户数据；不把 CLI 认证挂载进容器；不自动重发回执未知的调用。
- 不默认删除旧 Skill 入口或历史。目录切换、历史读取与数据清理是不同动作；存量删除须另有明确授权。
- 没有真实模型、浏览器、设备或微信环境证据时写 blocked；不能用 Mock、静态检查或同一次生成的自评替代。
- 工作区中的并行改动保持；只提交本工作包的文件。提交、推送和发布分别遵循会话授权，不从本计划推断许可。

## 2. 容量、批次与关键路径

规划假设为一位熟悉项目的实现者，不假定有固定可用时数、团队速度或额外并行代理。没有历史速度，不编故事点或确定发布日期；预留 20% 缓冲用于依赖、模型质量、浏览器和原生验收问题。

## 4. 各工作包执行要求

### 4.1 WP-00：规格与系统设计

- 核对当前产品与 PRD 的差距，更新产品边界、AI 分析、报告导出、Web 体验和编排主题，不另建重复规格。
- 明确上游原生加载与受控脚本的职责。项目只负责适配，不重新写分析／写作方法；未证明可用前不要承诺某种 Codex 生图方式。
- 定义产物 manifest、owner／来源／选段／版本绑定、HTML 隔离、对象存储、导出、清理、取消、失败与等待确认；不要把图片或 HTML 内联进普通任务 JSON。
- 冻结正式 API 与阶段语义。明确哪些现有枚举／结果联合可复用，哪些必须变更；不先写 DTO 再从页面反推契约。
- 完成条件：每项 FR／NFR 都能找到唯一技术落点，现有 MD／DOCX-only 规格与新 HTML／图片要求不再冲突；文档检查通过。

可能涉及：`docs/design/01-产品定位与边界.md`、`09-AI分析.md`、`10-报告导出.md`、`11-Web体验.md`、`13-工作流编排.md`。此列表是定位入口，不是授权改写其他主题。

### 4.2 WP-01：最小验证与基线

- 使用固定上游源码及已运行基础服务；在隔离任务目录中验证 Node、FFmpeg／FFprobe、Bun、完整引用包与 Codex 路线。
- 在正式产品接线前跑通短视频原生拉片、文章写稿／排版和单份剧本审稿的最小链路。产生真实原生产物，记录实际调用、时长、限制和失败。
- 建立第 6 节的样本索引与人工基线。只用自制、公开授权或用户授权的素材；不把私有原文、完整 Prompt 和凭据提交到仓库。
- 对 A-01～08 分别给结论；默认视频范围、篇幅、配图数量和预算依据实测填写。图片和微信缺环境可独立 blocked，但不能阻塞已可验证的其他工作。
- 完成条件：核心三任务最小链路有真实证据；依赖与范围明确；未成立的假设已有具体降范围或暂停功能的处理，未伪造成功。

### 4.3 WP-02：固定上游与依赖

- 从调研固定来源表提取 commit，保存 SK-01～08 实际所需完整目录、同级引用闭包、脚本、assets、LICENSE 和适用 NOTICE。
- manifest 保存仓库、commit、路径、文件哈希、许可和依赖版本。对原样包增删改做一致性检查；中文名称、输入／产物说明和配置适配放包外。
- 预装所需运行依赖并固定版本；生产阶段不执行临时 `npx -y`、`pip install` 或联网装包。包管理器生成锁文件，人工不改锁。
- 完成条件：AC-01；缺失引用、被改动文件和未安装依赖均有明确不可执行状态；没有只拷贝 SKILL.md 的假接入。

定位入口：`backend/app/services/analysis/skills/{registry,loader,models}.py`、`modules/manifest.json`、`backend/app/integrations/analysis_skill_catalog.py`。新包目录与加载方案由 WP-00 冻结。

### 4.4 WP-03：执行与成果契约

- 把机器步骤、模型步骤、用户等待、验证和发布映射到现有 Job／Run／Step／Report，保存当前成果与来源版本。
- 外部脚本使用固定命令、参数与工作目录；限制输入、选段、镜数、帧数、字节、超时与网络，取消结束整个进程组。
- 每次模型调用前登记 Step；响应先持久化再解析；未知调用不能被当作已知失败重跑。下游失败只从安全可恢复阶段继续。
- 发布前验证成果类型、字节／哈希与 owner；提供原生 JSON／HTML／图片的取回与展示索引，普通响应只带必要 metadata。
- 完成条件：AC-07／09，NFR-01～05；恶意路径、软链、超限、未知、取消、迟到、部分发布和越权均有回归证据。

定位入口：`backend/app/workers/analysis/{main,skill_activities,skill_workflow}.py`、`backend/app/services/analysis_execution/monitor.py`、`backend/app/integrations/ai_cli/`、`backend/app/repositories/analysis/`、`backend/app/workers/report/`、`backend/sql/schema.sql`。

### 4.5 WP-04：实测拉片

- 按上游完整流程执行 seed、首尾关键帧、联系表、视觉填写、必要 recut、validate 和 render；机器字段与视觉字段分开管理。
- 保存源范围及其相对原视频的偏移；表格、关键帧、证据与播放器跳转使用一致的源时间。不可确认的声音、人物身份及转场保持未知。
- 与人工镜头表比较漏切／多切／边界误差；质量门跳过与失败分开记录。实测不等于所有景别／运镜判断正确。
- 完成条件：AC-02／08 的 Server 成果部分；可以打开原生报告、回看片段、读取 JSON；没有模型估时或随机等分补结果。

### 4.6 WP-05：文章初稿

- 来源只使用已验证、同指纹的拉片材料及本次可用画面。传入读者、目的、篇幅、语言；默认文风不假定 brand-voice 已接入。
- 按 ECC 原样方法写稿；正文、来源回查和审校分开。缺音频时产出视听解读，不编造完整剧情、台词、数据或作者经历。
- 写稿和模型修订是付费步骤；失败或解析错误不能悄悄再调。保存初稿使用户能够看见失败前的成果。
- 完成条件：AC-03；3 篇真实稿件事实逐项对回素材，正文完整、非模板填空；独立审校交给 WP-08。

### 4.7 WP-06：文章整理与 HTML

- 使用 baoyu 原样整理／排版资源，核对事实、数字、链接、代码、引用与表格；排版不得以新内容替换原文。
- 保存真实 HTML、相关图片资源及 manifest；微信预览和离线打开分别记录。Mermaid 及图片缺依赖时拒绝该路径或说明未支持，不伪造图。
- 预览／复制／文件导出读取已保存成果，不再调模型。微信真实粘贴测试停留在编辑器和草稿预览，不发布。
- 完成条件：AC-04；普通稿与复杂格式稿可读，资源交接明确，活动 HTML 与应用身份隔离。

定位入口：`backend/app/services/analysis/export_report.py`、`backend/app/workers/report/`、`frontend/src/components/analysis/`；依赖处理不得写进上游目录中的源码。

### 4.8 WP-07：剧本拆解

- 接完整 screenwriting 方法与 drama 审稿资源，按用户关注项选用，不机械套幕数、页码或评分模板。
- 继续使用权威全文、源单元分块、顺序与引用验证。长文本做跨块回查，不能只收集各块的局部指摘。
- 结论包含具体问题、可定位的原文、影响和修订目标，也保留成立的创作机制。缺少前后文时缩小结论范围。
- 完成条件：AC-05；三类样本完整覆盖且原文引用准确；跨块因果、延迟揭示和后文反证经人工复核。

定位入口：`backend/app/services/analysis_execution/{screenplay_executor,screenplay_analysis_plan,screenplay_source_validation}.py`、`backend/app/integrations/ai_cli/{screenplay_prompt,codex_screenplay}.py`。

### 4.9 WP-08：独立审校与定点修订

- 审校调用用独立上下文重新核对来源；记录审查方式、范围、位置、证据、影响、修订目标和确定程度。
- 检查文章事实与文风、剧本因果与误报。模型不同调用不是独立模型的证明，人工复核也不能记作模型自动审校。
- 只对重大且已证实的问题做定点修订；复审检查问题是否解决及是否引入新事实。不能用整篇重写掩盖差异。
- 完成条件：AC-06；第 6 节控制集的命中／漏报／误报和修订前后差异有证据，待核查问题不被写成通过。

定位入口：`backend/app/services/analysis_execution/{video_editorial,editorial_plan}.py`、结果契约及审校显示组件；不把初稿自评当独立审查。

### 4.10 WP-09：三端接线

- 先完成 Server OpenAPI 与 Frontend；Electron 只运行同步脚本；App 用正式白名单更新快照并重新生成，不手改生成代码。
- 保留原视频／文档入口、语言、默认要求、恢复默认和历史。用户任务入口清楚，正文优先；版本、限制、证据和审校可以展开。
- Web／Electron 对齐原生报告的首尾关键帧、镜头表、过滤、时间跳转及文章预览；App 用原生镜头表、文章和图片，文件交接按设计实施。
- 完成条件：AC-08、NFR-06／07；真实浏览器和原生设备／模拟器各有证据；下载／保存不重新推理，旧结果没有空白或被改型。

仓库顺序：`framefetch-server` → 其 `frontend` → `framefetch-electron` 同步／`framefetch-app` 白名单。三个仓库分别验证、分别交付，不在父目录提交。

### 4.11 WP-10：内容对照与 agent-browser 审查

- 先冻结样本、比较条件与评分表；同一素材跑上游原生流程与帧取适配，不拿不同视频或不同模型结果横向下结论。
- 使用用户指定 agent-browser 的已安装 CLI 工作流。登录使用已有授权的 auth vault 或用户提供的登录方式，凭据不出现在命令参数、报告或截图中。
- 通过页面完成任务创建、等待、结果回查、镜头跳转、展开审校、复制和导出；记录实际任务／报告版本。截图好看不代表内容质量合格。
- 覆盖桌面与 390px、明暗主题、键盘焦点、溢出、失败及取消；Electron 和 App 的原生行为另验，不用浏览器夹具替代。

## 8. AI 可执行的领取与交付格式

AI 读取本计划时遵守以下步骤：

1. 读取当前用户授权；用户已启动实现。当前会话要求先推送已有改动，再按本计划展开实现。后续执行仍须核对最新指令。
2. 开始实现时检查工作包依赖。依赖未通过时先处理其具体问题，不跳到后续 UI 宣称完整。
3. 记录工作区基线和已有差异；声明本包涉及的仓库／文件，公共配置按顺序修改。
4. 从对应 FR／NFR／AC 取得完成条件，先定义可复现测试，再实现。
5. 完成后检查真实结果与证据，更新状态；有 failed／blocked 项就保留事实及下一动作。
6. 只在完成条件满足且必要证据齐全时写 passed；源码检查与产品验收分开报告。

每包交付记录使用下列字段，直接放在本计划的对应工作包下，不另建聊天日志：

```yaml
work_package: WP-04
status: not_started
requirements: [FR-02, FR-08, FR-09]
acceptance: [AC-02, AC-08, AC-09]
dependencies: [WP-01, WP-03]
repositories: [framefetch-server]
changed_files: []
checks: []
real_samples: []
evidence: []
limitations: []
next_action: 按依赖顺序执行
```

此示例是记录格式，不是实施证据。`checks` 填命令及真实结论，`real_samples` 填样本及任务／成果 ID，`evidence` 填脱敏摘要或授权的私有证据引用；无值时保持空，不用示例 ID 伪装真任务。
