## 2. 真实样本证据

所有本机媒体、模型、日志与环境均位于忽略的 `backend/artifacts/watermark-evaluation/` 和 `backend/artifacts/watermark-runtime/`，不提交 Git。复现实验脚本为 [benchmark_watermark.py](../../backend/scripts/benchmark_watermark.py)，产品执行器为 [process_watermark.py](../../backend/scripts/process_watermark.py)。

### 2.1 抖音

用户分享视频通过正式 API 下载，任务 `5134c091-4201-4669-82e3-6abe8ef67fa8`；1440×1080 H264/AAC，64.100 秒，1816 帧，8,357,420 字节；原片 SHA-256 `2e5f7cf1d9852f1f83f24d3ad237cacc52dd75520ee17783afda5deef1697708`。

右下角有贴边 `ttCounter` 烧录标记。8–12 秒相同输入、同一矩形对照，115 帧：VSR STTN MPS 48.357 秒、CPU 148.728 秒；FFmpeg delogo 1.38 秒、removelogo 74.20 秒。本机 macOS arm64、24 GB，VSR 进程峰值 RSS 约 1.44/5.62 GB，不能替代完整统一内存峰值或通用性能承诺。

VSR 片段擦除了标记，局部仍存在修补纹理；delogo 贴边处出现黑色渐变，removelogo 出现异常色块。三者视频帧 PTS 相同，VSR 解码音频 SHA-256 与输入一致。

固定区域 VSR 全片运行 772.932 秒、峰值 RSS 约 1.54 GB；1816 帧 PTS、画幅、全部音频哈希、完整解码和原片哈希校验通过。输出 SHA-256 `bdd0c223405cd1316a1a362f9992c7713e71bed38b3bfcbe986f730ea129528a`，24,497,914 字节。证据 `vsr-full-verification.json`；这证明修补与媒体保持链路，不等于自动检测验收。

### 2.2 B 站

用户视频 `BV1Lkh467ETw` 的正式下载任务 `3f33ea85-292f-4c80-ab33-93d577102799`：1920×1080 H264/AAC，46.806 秒，1170 帧，11,437,155 字节，原片 SHA-256 `f5e3a3b139f06393fbc1af97cd11a425ea6cddbb45c23a3930a3c81c8703ddf1`。

17.5、18.5、19.5 秒右上角可见作者名和 bilibili 标记，属于原视频画面，不是网页播放器覆盖。证据 `bilibili-watermark-17_5s.png` 等。17–18 秒片段：VSR MPS 37.52 秒（有并发负载），去除标记但发丝细节变软；delogo 约 3 秒，区域明显模糊。没有据此得出所有视频的算法排名。

固定区域产品执行器处理完整文件，通过 1170 帧时间轴、音轨哈希与解码校验；仅处理 17–18 秒不代表全片去水印。旧人工任务 `399b6189-16ea-46ef-a559-c052577aef1d` 已发布处理版，原片仍可取回。当前产品不再提供人工区域设置。

自动检测 + STTN 完整 1080p 输出 `bilibili-auto.mp4`，SHA-256 `70aca9aa1d9d5587127f0f954b029d2046f1187718961e0b5248292300ae4d54`，33,115,029 字节；1170 帧时间轴、尺寸、完整解码及音频哈希均通过。17.5 / 18.5 秒人工检查中角标已修补，普通字幕仍保留。

从首页重新解析同一 URL、选择 720p 下载，正式任务 `f3b454cd-b136-48a9-854d-c908a72fb1a4` 自动生成处理任务 `0fa55dc3-b2f6-42c2-a17d-3d04534e8a6d` 并成功发布，无人工选区或额外处理按钮。原片 SHA-256 `7057c5dac33a81fa0f0788e2fbac61325ba6f216321a613f373cbefaacbed7d8`，处理版 SHA-256 `2554e0b1328491940ed217044e3a6c905a797d91cd8a90c51cfac7e4448b12d0`，16,923,328 字节。两者从正式对象存储取回，再次通过 1170 帧 PTS、尺寸、音频哈希与完整解码校验。页面显示“处理版已就绪”和两个保存入口。浏览器实际保存调用超时，未把服务端取回文件当作浏览器下载成功。

### 2.3 自动检测对照

Microsoft Florence-2 base-ft（不作为生产依赖）、large-ft、large 的开放词汇/grounding 与角落裁片实验出现正常字幕和场景品牌误报，未接入产品。准确模型 revision 保存在忽略的运行时下载记录；本实验不评定其他权重或所有 Florence 实现。

RapidOCR 3.4.2 在相同帧中检测出 B 站角标、相邻作者名及贴边 `ttCounter`；15 秒正常字幕画面未产生品牌水印候选。此为少量样本观察，不是通用准确率。B 站完整自动处理已通过；跳角标记、未知纯图形、低透明度、复杂背景与字幕提及品牌的负例仍需分别验收。

## 3. 验证记录

- 源优选和 Runner/插件：174 项相关回归通过。
- 自动触发、重复完成、普通导入不处理、专用上传处理、原片保留、额度不足、租约、取消子进程与存储 PUT 取消等待：48 项相关测试通过。
- Frontend 自动状态/无人工表单/双文件保存/无参数重试/不支持规格提示与首页 Tab：6 项测试通过；TypeScript 检查通过。
- 数据库 schema 已幂等应用到本机现有项目库两次；没有重建基础服务。
- 正式 URL 自动处理 passed；首页桌面与 390px、明暗主题检查 passed，390px 无水平溢出。
- 浏览器上传 blocked：Chrome 扩展未开启文件 URL 访问权限；浏览器处理版保存调用超时。服务端发布和对象存储文件复核通过，不代表浏览器文件操作已通过。
- Electron 同步 304 个上游文件，类型检查、静态检查、42 项测试、构建和上游一致性检查通过；实际 Electron 文件操作未验收。
- 本机开发前端曾发生 Turbopack 缓存 panic，自动重启后清除损坏缓存并恢复，重新打开正式任务可看到处理版。

## 4. 未完成项与限制

- 扩充真实正负例，单独评估移动、纯图形及低透明度水印；当前识别有意不处理无法确认的文字。

- App 原生上传和双版本播放保存体验未验收。
- 自动处理受支持规格和运行时资源限制；不能承诺所有平台、所有视频、任意水印无残留。
