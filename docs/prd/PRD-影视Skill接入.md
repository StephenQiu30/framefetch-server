# 影视 Skill 接入 PRD

## 1. 摘要

帧取需要把成熟的开源 Skill 接入实际分析流程，让用户从自己的视频获得可回看的逐镜拉片、可用于公众号排版和导出的成稿，从自己的剧本获得有原文依据的结构、人物、场景和对白诊断。上游方法及资源按固定版本原样保存，项目负责素材、执行、阶段衔接、成果保存和三端展示。

本文是本能力的唯一产品需求。选型依据见[调研报告](PRD-AI分析Skill选型.md)，工作包与执行证据见[接入计划](../plan/PLAN-影视Skill接入.md)；本次只整理文档，接入尚未实现。文中的目标、产物和验收条件均是待实施要求，不表示现有产品已经支持。

## 2. 参与人

| 角色 | 负责人 | 职责 |
| --- | --- | --- |

## 3. 背景与依据

### 3.1 当前问题

现有目录提供成片审阅、素材拆解、剧本审阅及文章／公众号／小红书整理入口，但完整上游 Skill 运行尚有缺口：方法多为编译的片段，脚本与资产不能直接加载；逐镜时间主要依赖模型观察；公众号入口偏向整理已有文档；成果以项目 JSON、Markdown 和 DOCX 为主。

因此，“目录里能选 Skill”不能作为接入完成的依据。完整接入需要证明：执行了对应的完整方法和脚本，使用了实际来源，保留了可交付产物，结果经原文或原画面对照后有用。

### 3.2 可复用基础

复用已有下载／上传、文档导入与全文分块、FFmpeg、宿主 AI Worker、Codex、Temporal、AnalysisJob／Run／Step／Report、幂等与未知回执保护、对象存储、鉴权、历史与 MD／DOCX 导出。不另建模型网关、业务队列或第二套任务状态。

宿主运行依赖就绪、上游脚本自测与合成视频切点试跑已有有限证据，见[调研验证记录](PRD-AI分析Skill选型.md#10-本轮验证记录)；真实影片质量、中文成稿、配图和新产物三端展示仍未验证。

### 3.3 选型与对照原则

采用[调研推荐](PRD-AI分析Skill选型.md#5-第一批推荐的具体适配)：实测拉片用 reelbench，文章初稿用 ECC，整理／HTML／翻译／配图用 baoyu，剧本诊断用 screenwriting 与 drama。

成熟度依据流程、资源、脚本检查、维护和依赖，不按星数推断质量。对照必须用同一材料、输出语言、用户目标和模型条件；先记录基线，再评价帧取的适配是否损失方法或阅读效果。

## 4. 目标与成功标准

目标是让用户少切工具，并得到能核对、能使用的内容。实施期间按下表建立验收集；正式开启对应能力前满足其条件，不用固定交付日期替代质量门槛。

| 目标 | 可测条件 | 对应验收 |
| --- | --- | --- |
| 镜头时间可信 | 机器字段完整保留；硬切样本对照人工镜头表；上游质量门无未解释失败或跳过 | AC-02 |
| 公众号正文可用 | 至少 3 条真实视频各产生完整文章；事实及引语逐项可追溯，无新增无依据事实；微信预览检查通过 | AC-03／04 |
| 审稿有具体价值 | 短剧、电影节选、跨块长剧本均有完整覆盖；重要问题有位置、依据、影响和修订目标，误报有记录 | AC-05 |
| 能恢复且不重复付费调用 | 已知失败与未知回执分别处理；取消、失去所有权、迟到结果均不破坏当前成果 | AC-07 |
| 三端可读可保存 | 同一结果在 Web、Electron 和 App 均可阅读；实际导出的文件与保存制品一致 | AC-08 |
| 接入可维护 | 上游版本、资源、许可、依赖及成果指纹可核对；升级重跑相同样本 | AC-01／09 |

审稿质量与文章质量由人工对照判断；自动 schema、哈希、覆盖率只能证明结构和对应关系。记录人工修改时间、问题采纳情况、漏报和误报，不提前承诺提升百分比。

## 5. 用户与使用任务

| 使用任务 | 输入 | 用户要得到什么 | 约束 |
| --- | --- | --- | --- |
| 分析已完成的视频 | 已下载或自己上传的视频，全片或明确选段 | 镜头表、关键帧、节奏与分布、可回看的位置 | 不生成未来拍摄分镜，不估造切点 |
| 根据视频出公众号文档 | 视频、文章目的、读者、篇幅与语言 | 可读正文、来源回查、公众号 HTML 和文件 | 默认是画面／视听解读；声音未核验时不补台词 |
| 分析已有剧本 | 导入的完整剧本或明确节选 | 结构、人物、场景功能、对白和优先修改 | 不代写故事，不以节选推断未提供全文 |
| 整理与翻译文章 | 已保存文章或导入正文 | 保留事实、限定、链接和格式的整理稿／译文 | 不使用别人的身份或经历写作 |
| 给文章配图 | 已保存正文及用户选择的配图目标 | 对应提示词、生成图片和放置建议 | 只走验证过的 Codex 路线，单独计量 |

使用者是单人自托管用户。范围不包括账号池、团队审批、多租户或商业营销系统。

## 6. 用户价值

拉片减少手工记录时间位置；公众号流程减少重复传文件；剧本诊断让用户知道问题在哪里、为什么有影响、应该恢复什么效果。已有工具擅长各自环节，帧取的价值是利用现有素材与任务系统把它们连接起来，并且保留依据与原生产物。

结果正文优先服务阅读，证据、审校、版本、用量按需展开。用户不需要了解包目录、模型协议或内部状态字段才能完成任务。缺材料和不确定性出现在相关结论旁，不能被“审校通过”掩盖。

## 7. 方案与需求

### 7.1 用户流程

**拉片：** 视频详情 → 选择拉片与范围 → 检查运行条件 → 实测切点和运动 → 看首尾关键帧并填视觉判断 → 复核候选边界 → 质量检查 → 镜头表／交互报告 → 回看与导出。

**公众号：** 视频详情 → 选择“根据视频写公众号文章” → 填目的、读者、篇幅和语言 → 复用同来源的有效拉片或先拉片 → 写初稿 → 独立审校 → 必要的定点修订与复审 → 整理 Markdown → 公众号 HTML → 正文预览、复制和导出。

**剧本：** 文档详情 → 选择剧本拆解及关注点 → 读取完整权威正文 → 按实际源单元诊断 → 跨块回查 → 审阅问题及反证 → 优先修改、保留机制与原文定位 → 导出。

**翻译／配图：** 从已保存的文章显式启动。两者不会因运行拉片自动执行。需要用户补充或确认时，先显示具体稿件或方案，等待期间不继续消耗模型调用。

“一键”表示预先收齐必要输入后自动串联核心阶段，不表示跳过审校、默认发布或掩盖人工确认。

### 7.2 Skill 清单与版本

固定源码和许可只有[调研固定来源表](PRD-AI分析Skill选型.md#11-固定源码与许可)维护；实现从表中取得完整 commit，不使用浮动 main 或 latest。以下是产品范围和接入顺序。

| 编号 | Skill／资源 | 用途 | 优先级 | 依赖与接入条件 |
| --- | --- | --- | --- | --- |
| SK-01 | reelbench `video-shots` | 实测拉片、镜头表和交互 HTML | P0 | Node、FFmpeg／FFprobe、完整 scripts／references |
| SK-02 | ECC `article-writing` | 根据已验证的拉片材料写文章 | P0 | 默认文风；不自动接入 brand-voice |
| SK-03 | `baoyu-format-markdown` | 整理文章 Markdown | P0 | 固定 Bun/npm 依赖，保留事实与格式 |
| SK-04 | `baoyu-markdown-to-html` | 微信 HTML 与预览 | P0 | 包含所需 baoyu-md／浏览器资源；先验证普通文章 |
| SK-05 | screenwriting `sw-story-structure`、`sw-character-conflict`、`sw-scene-craft`、`sw-dialogue`、`sw-premise-theme` | 剧本结构、人物、场景、对白与主题诊断 | P0 | 完整对应参考资料和同级引用闭包 |
| SK-06 | drama `short-drama-review` | 审稿方法、位置／证据／影响／修订目标 | P0 | 剧本用完整文本；成片只能审实际观察或拉片材料，说明输入限制 |
| SK-07 | `baoyu-translate` | 文章翻译 | P1 | 独立验收原文事实、数字、链接和限定 |
| SK-08 | `baoyu-article-illustrator` | Codex 配图 | P1 | 验证 imagegen 或 codex-cli 包装器及其额外包；不能仅复制技能目录 |

P0 是三个核心任务的完整接入；P1 属于本计划的后续交付，独立通过门槛后启用。小说/IP 全量拆文、Humanizer-zh、中文公众号备选写作只作为对照或后续候选，不自动加入产品。

### 7.3 功能需求与验收条件

| 需求 | 要求 | 可观察验收 |
| --- | --- | --- |
| FR-01 上游包与目录 | 原样保存固定版本、资源闭包及许可；产品中文说明与适配在包外。目录说明用途、输入、来源、版本和产物 | AC-01：文件哈希与固定源码逐一一致；缺资源或依赖时不展示为可执行；历史缺失元数据不伪补 |
| FR-02 实测拉片 | 切点、时长、帧率和运动由脚本产生；模型仅填视觉字段。漏切／多切经受控 recut 复核，不允许直接改机器字段 | AC-02：至少 3 类真实视频；人工标注至少 20 镜；记录检测精确率、召回率和边界误差；可确认的硬切复核后误差不超过 2 帧，叠化单列不确定区间；全部必需质量门通过 |
| FR-03 视频写稿 | 正式提供视频到公众号文章的自动串联；材料、语言、目的、读者及篇幅固定。已有拉片只在来源、选段与版本一致时复用 | AC-03：3 条真实视频各完成 1 篇正文；逐项核对所有实质事实、数字和引语；不能从无声音证据的视频编造对白或外部经历 |
| FR-04 Markdown／微信 HTML | 保存上游完整正文与 HTML；预览、复制和导出不再次推理；保留标题、列表、表格、代码、链接和引用 | AC-04：至少 3 篇稿件与 1 篇复杂格式稿；微信编辑器真实粘贴／预览可读；不点击发布；图片依赖未满足时明确缺项 |
| FR-05 剧本拆解 | 读取完整来源；按文本实际结构选择方法，保持全文覆盖；问题包含原文位置、证据、影响与目标，同时检查后文反证 | AC-05：短剧单集、电影节选、跨单次上下文长剧本各 1 份；源单元覆盖与引用准确率 100%；人工逐条复核重要问题，不能用理论公式或无依据分数代替判断 |
| FR-06 独立审校与修订 | 初稿与审校分开调用；正文不包含内部审校记录；确认存在重大问题时只修相关位置并复审。无法独立审查时标注自检 | AC-06：人为植入事实、引用、结构、表达错误及有意创作选择；记录命中、漏报、误报及修改前后差异；未修复重大问题不显示“通过” |
| FR-07 阶段进度与恢复 | 每阶段先保存调用状态再执行，成果落盘后可查询。已知失败可明确恢复；未知回执先核对，不自动再调 | AC-07：脚本失败、模型超时、断连、取消、Worker 丢失、迟到结果均有真实状态；成功阶段不因下游失败被重做；未知调用没有第二次调用 |
| FR-08 原生产物与三端阅读 | 保存 MD／JSON／HTML／关键帧／联系表及可用配图，展示与导出同一成果版本。Web／Electron 支持交互报告，App 原生展示镜头表与正文 | AC-08：同身份、材料、任务和结果版本在三端阅读；实际保存并打开文件，字节／哈希一致；App 不使用 WebView；不能以 Web 截图代替原生验收 |
| FR-09 来源与历史 | 来源、Skill、模型与 CLI 版本可回查。新旧结果按生成时的真实类型与指纹读取；成功成果在失败重跑期间仍可看 | AC-09：变更来源或选段不能误复用；新版本不改旧报告元数据；默认不自动清理用户历史；任何存量删除另行列出影响并由用户明确授权 |
| FR-10 翻译 | 完整翻译所选文章；区分原文事实与译文表达，保留代码、链接、数字、引用和确定程度 | AC-10：中英两方向各 1 篇，包含表格、代码、数字和尾部标记；译文无遗漏、增造或限定强化；有独立复核 |
| FR-11 Codex 配图 | 用户选择配图目标并确认方案后才生成；保存每张图的提示词、结果和版本；能替换／移除单张图 | AC-11：真实宿主 Worker 给 1 篇文章生成至少 3 张图；来源与位置对应；取消／未知回执不重发；确认没有其他模型或图片 API 调用 |
| FR-12 样本对照与微调 | 用同材料对照上游原生输出与帧取接入结果；文章另与中文备选作受控 A/B。调整产品流程、配置和展示，不私改上游方法 | AC-12：基线、评分规则、比较结果、修改理由及复测齐全；不能以高星、页面好看或 schema 通过宣称内容更好 |

### 7.4 非功能需求

| 编号 | 要求 | 验证方式 |
| --- | --- | --- |
| NFR-01 执行边界 | 只接宿主已登录 Codex；上游声明的工具权限不自动继承。脚本只能访问授权输入／输出与固定依赖，网络按必要用途限制 | 测试越权路径、软链、私网请求、素材指令和临时依赖下载；凭据不进容器、普通日志或 History |
| NFR-02 资源与费用 | 单重任务；视频选段、文件、镜数、帧数、图片、调用次数、时长和字节都有明确预算 | 达上限拒绝或说明停止范围，不静默截断；记录实际调用及可获得的用量，无法取得的字段标为未知 |
| NFR-03 可靠性 | 复用既有执行所有权、持久 Step、取消及未知回执保护；输入和方法冻结后不被上游升级替换 | 已知／未知／取消／迟到／接管回归；升级只能影响新任务 |
| NFR-04 产物完整性 | 原生产物进私有存储，校验字节、类型、哈希、owner 和结果版本；不把大图片或 HTML 塞进普通 API 响应 | 越权、过期、损坏、部分发布、重复导出验证；导出不调用模型 |
| NFR-05 HTML 隔离 | 活动 HTML 与主应用身份隔离；预览不能读取 Cookie、Token 或主页面；禁止任意外链脚本和资源访问 | 恶意 HTML／脚本／跨源资源夹具及真实浏览器检查；安全方案在实现前写入系统设计 |
| NFR-06 界面 | 沿用唯一视觉标准，正文先于证据／审校元数据；桌面／390px、明暗主题、键盘焦点均可用 | agent-browser 实际操作、截图、无横向溢出；原生 App 另验窄宽屏和文字缩放 |
| NFR-07 可维护性 | 三仓按 Server → Frontend → Electron／App 顺序推进；生成客户端与锁文件只由工具更新，上游包字节不变 | 来源／版本／哈希检查、生成漂移检查、文档链接检查与各仓相关测试 |

### 7.5 技术约束与待设计项

当前系统规格见 [AI 分析](../design/09-AI分析.md)、[报告导出](../design/10-报告导出.md)、[工作流编排](../design/13-工作流编排.md)与[界面规范](../../design.md)。报告导出目前规定 MD／DOCX，Skill Loader 目前编译项目片段；本文要求的完整上游加载、HTML／图片产物与阶段等待需要先补系统设计，再实现。

实现者不得为省事把完整上游流程换成新的自写提示词，不允许只拷贝 SKILL.md 或只截参考章节宣称“原样接入”。同时不能把上游自动发布、下载依赖、创建故事或生产媒体等动作当作用户授权。

后端 OpenAPI 是唯一契约；App 冻结白名单快照，Electron 同步 Frontend。App 站内使用原生镜头表、Markdown 正文和图片；HTML 的文件交接边界需在客户端设计中明确。

| A-02 无声音材料也能写出有用的视听文章 | 未验证 | 3 条视频逐项核对；不足时限定文章类型，不补造剧情或台词 |
| A-03 完整 baoyu 脚本可在宿主受控运行 | 未验证 | 验证固定 Bun/npm、所需包和普通 HTML；复杂 Mermaid 单独验证 |
| A-04 Codex 生图可由现有 Worker 调起 | 未验证 | 真实出图与取消／回执测试；不成立时保持功能不可用，不切到其他付费 API |
| A-05 长剧本分块后仍能判断跨块因果 | 未验证 | 带前后呼应和反证的长样本；不能仅以覆盖 100% 算质量通过 |
| A-06 调用量与运行时间可接受 | 未建立基线 | 记录短视频、长片选段、长剧本和文章链路实际用量，再冻结默认预算 |
| A-07 独立调用能有效发现初稿问题 | 未验证 | 错误与正确控制样本对照；区分同模型独立上下文、自检和人工复核 |
| A-08 微信真实粘贴与图片处理可行 | 未验证 | 编辑器草稿预览；缺凭据时标 blocked，HTML 单独打开不替代微信验收 |

用户预算、默认片段长度、默认篇幅、默认配图数量与用量阈值在最小验证后填写。没有基线时不猜模型能力、Token 价格或交付性能；这些不阻止本次文档完成，但阻止对应能力宣称已验收。

### 7.7 范围外

本计划不接小说/IP 全量拆文、语音转写、平台字幕、影视资料爬取、自动发布、视频／配音／剪辑生成、用户自定义 Skill 或额外模型 API；不读取浏览器 Profile、钥匙串或平台 Cookie。保留已有产品入口与历史的读取能力，新增能力不能用删除现有数据来完成迁移。

## 8. 交付顺序与门槛

| 批次 | 内容 | 开启条件 |
| --- | --- | --- |
| 最小验证 | 固定来源、真实样本、受控脚本、上游产物、模型和依赖验证 | 形成有证据的技术结论与失败边界，系统设计足以指导编码 |
| 核心接入 | P0：拉片、文章／HTML、剧本拆解、审校与恢复 | 对应 AC／NFR 通过；Server／Web 先闭环，再完成三端接线 |
| 完整验收 | agent-browser 内容和界面审查、原生客户端、微信草稿及同材料对照 | 全部 P0 工作包与缺陷复测完成；缺少环境的项明确 blocked，不算通过 |
| 扩展交付 | P1：翻译、Codex 配图 | AC-10／11 分别通过；不阻塞核心任务，不默认开启未验证路线 |

调研估计 P0 为 13–23 人日，配图另计 2–4 人日；翻译及审校深度仍需拆包估计。计划预留 20% 不确定工作缓冲，工期是容量假设而非承诺；详细估计与关键路径只在[执行计划](../plan/PLAN-影视Skill接入.md)维护。
