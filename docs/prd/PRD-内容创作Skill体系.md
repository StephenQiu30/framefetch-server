## 1. 问题、用户与目标

创作者已有原著、剧本、视频、文章或笔记，却需要在多个工具间搬运材料、解释任务、核对引用，再手工整理可用文档。通用对话经常丢失版本、忽略部分章节，或把建议和未验证信息写成事实。图文作者也需要保护原稿、逐页调整、使用真实图片并取得实际文件。

本产品提供可单独选择的分析和整理任务。用户先确认材料，选择 Skill，再核查、编辑和确认候选版本，最后导出。无需强制依次计划、写作、审阅。影视侧服务剧情／剧本分析者与拉片学习者；文章侧服务作者、编辑、公众号与小红书图文作者。专业审阅质量需要独立评测，功能可运行不能替代结论正确。

本轮成功标准是 12 项任务共享完整的材料、执行、核查、人工版本、恢复和导出闭环，三端使用同一后端事实。目标包括减少重复整理、降低失实引用和遗漏输入的风险、提高确认稿复用效率。节省时间、专业满意度和传播效果没有历史基线，必须通过真实用户验证，不能编造提升百分比。

## 3. 当前范围

CAP 编号保留需求追踪含义，编号间隙不是未完成制作任务。当前能力共 12 项，影视 6 项、文章与图文 6 项。

| 编号／Skill | 必需材料与用户动作 | 可交付结果 |
| --- | --- | --- |
| CAP-01 script-diagnosis：Drama 剧情／剧本分析 | 确认原著或剧本；分析人物目标、阻力、行动因果、关系、伏笔、节奏与规则 | 按固定单元组织的分析、问题／建议、原文引用、待核事项；MD／DOCX |
| CAP-02 shot-study：镜头分析 | 已导入、归属当前用户的视频；核对切点和实际帧，补充观察／声音笔记 | 镜头候选、原源时间、真实帧预览、人工观察；MD／CSV |
| CAP-03 subtitle-edit：字幕校订 | 视频与用户提供的 SRT／VTT；修改文字和时间 | 保留合法重叠的字幕；SRT／VTT |
| CAP-06 script-cut-compare：剧本／成片对照 | 固定剧本和视频；核查原文与已采样画面之间的候选对应 | 对照问题、文本／帧依据、未知项；MD／CSV |
| CAP-07 continuity-review：画面连续性分析 | 视频；核查已提供真实帧中的人物、道具、服装、位置和视线 | 观察候选、反例与限制；MD／CSV |
| CAP-08 film-research：影视参考研究 | 用户提供的有权资料与研究目的 | 来源冲突、短引文、问题与参考笔记；MD／DOCX |
| CAP-12 article-write：文章策划／写作 | 作者观点、材料、受众与目的；选择提纲或正文 | 可编辑提纲／正文、引用、待补事实；MD／DOCX |
| CAP-13 article-edit：编辑／格式整理 | 确认原稿；选择仅格式或润色／重组／压缩 | 差异、人工版本；MD／DOCX；仅格式不推理 |
| CAP-14 wechat-package：公众号图文整理 | 已确认稿，按需选择原图；修改标题／摘要／图注 | 受限 HTML、本地预览、MD／DOCX、实际素材 ZIP |
| CAP-15 xhs-cards：小红书图文整理 | 已确认稿与可选原图；修改／调序页卡 | 可编辑页卡与实际 PNG 图卡 ZIP；文字整理与图片渲染分别显示状态 |
| CAP-16 visual-assets：原图素材整理 | 用户有权原图或稿件；确认素材来源与用途 | 原图、来源与权利清单、MD／ZIP |
| CAP-17 source-extract：参考摘录 | 提供实际正文或文档，可注明来源 URL；核查短引文 | 有范围和版本依据的本地摘录；MD／DOCX |

本轮不包含剪辑、时间线交换、成片渲染、分镜生产、故事开发、AI 媒体生成、影视宣传生产和自动发布。字幕仅校订用户提供的文字，不执行自动转录、听音或配乐识别。画面模型仅分析真实抽样帧，不能声称全片运动、声音或所有连续性问题已核查。

## 4. 用户故事与功能需求

| 编号 | 用户故事／功能要求 | 验收条件 |
| --- | --- | --- |
| FR-01 材料与权利 | 作为作者，我能建立作品、输入正文或导入文档／原图，并确认用途 | 六类材料均可保存；必填权利声明；视频来自当前用户可用制品；原文件、SHA 和提取正文可取回 |
| FR-02 原文索引 | 作为剧情分析者，我能知道哪些章节／场景进入分析 | 固定 Unicode 位置与单元 SHA；30,000 字符内全量建立索引；漏单元结果拒绝；结构齐全与语义正确分开 |
| FR-03 独立任务 | 我能只选本次需要的 Skill | 动态目录仅 12 项；缺材料或 Worker／模型时明确提示；提交前明示会调用模型，格式／打包不暗中推理 |
| FR-04 持久执行 | 我能离开页面后再查看进度，取消任务 | 幂等键、归属、固定材料／方法版本；排队、处理、待确认、完成、失败、取消、结果未知状态真实 |
| FR-05 依据回查 | 我能回查判断所用的原文和画面 | 引文准确匹配固定材料 SHA 与字符区间；帧必须对应真实源时间、材料、SHA；历史依据不替换成新正文 |
| FR-06 人工版本 | 我能修改正文／结构数据、比较、恢复、确认 | 新版本不覆盖旧版本；并发旧基线保存返回冲突；未保存改动有保护；候选不会自动成为确认稿 |
| FR-07 母稿复用 | 我能用确认稿生成公众号／小红书任务 | 固定 source_revision_id，准确复制原文／数据；上游新版本使下游 stale，不覆盖人工稿、不自动收费刷新 |
| FR-08 实际文件 | 我能导出所选确认版本，并在失败后单独重试 | 绑定 revision_id；真实 MD／DOCX／HTML／CSV／字幕／素材及卡图；旧导出字节与哈希不变，不重复模型调用 |
| FR-09 文章保护 | 我能区分仅格式和改变文意的操作 | 格式保留代码、链接、引文、表格及 Markdown 空白语义；润色等明确模型授权，修改可比较 |
| FR-10 渠道整理 | 我能直接交付已确认稿，而非被要求重新写稿 | 本地预览拒绝脚本／危险 URL／远程资源；缺图不伪报图片完成；账号编辑器实际兼容单独验证 |
| FR-11 原图与页卡 | 我能只用原图或逐页编辑并得到真实图片 | PNG／JPEG／WebP 实际文件；图卡中文字体、换行、页序、溢出及缺字校验；坏资源失败保留页卡源 |
| FR-12 三端闭环 | Web、Electron、App 都能使用同一作品和版本 | 原生鉴权、统一生成契约；材料确认→任务→编辑确认→导出完整；断网／刷新不重复创建 |
| FR-13 旧系统清退 | 维护者能切换而不丢失历史报告 | 关闭旧创建／重试／目录入口，排空执行，删除旧 Skill 与导入器；保留 owner 历史结果／文件，不新增旧 API 别名 |

## 5. 非功能需求与限制

| 编号 | 要求与可验证边界 |
| --- | --- |
| NFR-01 安全 | 每个材料、任务、版本与导出均 owner 校验；材料只当数据；模型无任意工具／浏览器权限；凭据不进客户端、普通日志与 Temporal History |
| NFR-02 资源 | 文档 ≤10 MiB、正文 ≤30,000 Unicode 字符、PDF ≤200 页、剧本 ≤60 场；图像 ≤10 MiB，任务 ≤20 图；视频 ≤2 GiB／30 分钟；帧证据 ≤12，预览每帧 ≤48 KB；导出 ≤64 MiB |
| NFR-03 执行预算 | 模型调用次数与任务期限是可执行硬边界；当前适配器无审计 Token／金额回执，Token 字段仅预留，不能声称硬费用封顶；金额上限无法执行时拒绝模型任务 |
| NFR-04 未知回执 | 调用前持久占用，回执未知保留占用；取消／Worker 丢失不自动重发；未知任务禁止盲重试；已知失败手动重试沿用累计次数 |
| NFR-05 一致性 | PostgreSQL 当前态 SQL、唯一约束、Outbox 事务、attempt fence；迟到结果不能覆盖取消或更新尝试 |
| NFR-06 可恢复 | 文本、原件、版本与导出独立于临时工作区；导出失败不使分析重新收费；客户端提交结果未知保留原幂等键 |
| NFR-07 使用体验 | 390px／桌面、亮暗色、键盘、焦点、错误与空态可用；候选、确认、stale 和未知费用可辨识；英文引用不混成错误中文 |
| NFR-08 质量 | 不造数字、引文、亲历、导演意图或图片；结构校验不替代事实支持；图卡与字幕的文件级检查、模型的专业质量分别评测 |

正文提取不含 OCR，扫描 PDF 明确拒绝；参考 URL 仅记录出处，不代表已获取页面。普通话 CER、全片声音／运动理解、专业审阅准确率、真实编辑器兼容、付费账单核对、App 真机体验均不能用单元测试替代。

## 6. 验收场景与发布

验收至少覆盖：原创两章 Drama、无标题正文、含冲突参考的文章；含代码／链接／引用的格式保护；DOCX 段落和表格顺序、可提取与扫描 PDF；真实硬切／起始偏移／VFR／无音轨／静默视频；字幕合法重叠与越界；图卡长中文／英文／emoji、原图／缺图／缺字体；注入文字、越权材料、旧版本冲突；取消、重复 ACK、丢失 Worker／未知回执；确认稿派生与 stale；每种实际文件取回及旧哈希保持。

发布分为工程闭环和外部产品质量两个门槛。前者要求当前开放功能真实端到端运行、必要检查通过、旧入口清退、历史资料保留；后者需要真实用户、专业评审、公众号编辑器和 App 真机的独立证据。未通过的门槛按执行计划公开保留，不以“已导入 Skill”或健康接口关闭。

## 7. 依赖与待验证事项

依赖现有 PostgreSQL、MinIO、Temporal、RabbitMQ、Redis、宿主 AI Worker、FFmpeg、受控模型线路及中文字体。公众号／小红书本地整理不依赖外部账号。没有活跃模型时，确认材料、读取历史、已保存版本与本地工具不应消失。

待验证：专业剧情分析的实际价值与事实支持、不同模型的结构遵循度／视觉能力、目标编辑器清洗 HTML 的影响、各端真实设备表现。任何扩展到自动转录、远程资料、出图或发布，都应另有明确授权、产品需求和真实验证，不能作为本轮未完成剪辑任务计入。
