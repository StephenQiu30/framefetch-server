# 046 容器自持平台会话 PRD

日期：2026-09-29。状态：按用户要求补充启动自动接入与失效自动重新获取。关联：[Design](../design/046-容器自持平台会话设计.md) · [Plan](../plan/046-容器自持平台会话Plan.md)。

本文取代 [044 PRD](044-开源部署无感解析PRD.md) 的 FR-17 与 AC-21（宿主浏览器会话自动复用），并取代 043（已删除，Git 历史可查） 中“来源由宿主进程取得和刷新”的部分。按用户最新决定，本文同时取代 044 FR-04／FR-05 的匿名／访客运行路线：在线解析统一要求部署会话。

## 1. 问题

### 1.1 现象

2026-09-28 本机冷启动后，YouTube、抖音解析频繁返回“平台要求额外验证”（`provider_verification_failed`）。

### 1.2 已核实的根因

| 事实 | 证据 |
| --- | --- |
| 匿名出口是机房 IP | 容器出口 34.104.254.238，AS396982 Google LLC（东京）；同一出口连续 3 个 YouTube 样本得到“Sign in to confirm you're not a bot”、“This video is unavailable”和成功各 1 次 |
| PO Token 与 JS 解密正常 | yt-dlp 2026.08.19、bgutil 1.3.2、node 24 均可用，失败不由组件缺失导致 |
| 账号路线依赖宿主进程 | Chrome 来源只由 `provider_startup start` 派生的宿主维护进程读取；它在 2026-09-25 后已退出，账号 Runner 中 `cookies.txt` 不存在 |
| 来源有效期只有 15 分钟 | `provider_source_host.SOURCE_VALID_FOR = 15 min`，宿主进程一停，数据库来源随即过期 |
| 路由由启动脚本在进程内计算 | 直接 `docker compose up` 时 API 的 `RUNNER_DEFAULT_ACCESS_POLICIES={}`，请求静默进入匿名路线 |
| 宿主读取需要钥匙串授权 | 从非交互进程启动得到 `browser_permission_denied`，只有用户 Terminal 能读取 |
| 宿主读取需要完全磁盘访问权限 | 2026-09-28 实测：本机 macOS 对未授权的应用返回 `Operation not permitted`；执行导入的应用（终端或 Claude）需在“隐私与安全性 → 完全磁盘访问权限”中授权一次并重新打开 |

结论：**账号会话的持有者是宿主机上的一个短命进程，而不是部署本身**。只要宿主进程不在，系统就退回匿名，匿名又撞上机房 IP 的 bot 墙。

### 1.3 目标

项目本机启动时自动发现并接入已启用站点的浏览器登录态，尽量减少人工干预。之后 `docker compose up`、重启、重建容器、宿主重启都不需要人参与，已登记会话的平台**永不静默进入匿名模式**。新站点必须有可验证的登录探针后才能开放；仅有 Cookie 不算登录验证。

## 2. 用户与成功条件

| 角色 | 成功条件 |
| --- | --- |
| 普通用户 | 只粘贴链接；已登记会话的平台稳定走账号路线，无需管理 Cookie；恢复等待与需要管理员操作有明确提示 |
| 部署者 | 启动自动接入、正常会话由容器维护、失效自动寻找新登录态；需要真实登录或验证码时提示，在 Chrome 完成后自动恢复，无需手工导入 |
| 管理员 | 平台状态页能看到每个会话的站点、状态、最近刷新和最近验证结果，看不到秘密 |

## 3. 范围

**范围内**：所有需要账号会话的平台，统一为一种“站点会话”机制，包括 YouTube、抖音（账号）、Reddit、视频号（元宝）、优酷、腾讯视频，以及后续具备有效登录探针的已适配站点。优酷、腾讯视频保留 032 的内容权益边界（账号可访问的完整非 DRM 单视频），该边界作为站点准入属性，不因机制统一而扩大到其他站点。

**范围外**：

- 匿名与访客解析路线已移除，不提供兼容开关或回退。
- 在容器内完成账号密码登录、扫码或短信验证。首次登录只来自部署者本机已有的浏览器登录态。
- 绕过 DRM、会员、付费、private 或地域权益。会话不扩大内容权限，AGENTS 的内容边界不变。
- 解决 yt-dlp 没有提取器的站点。会话只解决认证，不解决解析。

## 4. 用户流程

1. **项目启动**：执行 `./start`，系统按已启用站点读取本机 Chrome 登录态，加密登记，启动服务并等待平台验证。单一已登录 Profile 自动选定；多账号只需一次指定。
2. **容器维护**：会话浏览器验证后开放解析，自动保活、轮换并持久化。重启恢复不依赖宿主读取进程。
3. **失效自动恢复**：后台定期检查缺失或确认失效的会话；新的有效登录材料出现后自动接入。同一份被拒材料不循环导入，健康会话不被覆盖。
4. **必要交互**：没有登录态或平台强制验证时，由部署者在 Chrome 登录／验证，随后自动恢复。主动撤销不自动恢复；更换来源 Profile 必须显式管理。

## 5. 功能需求（FR）

| ID | 需求 | 验收 |
| --- | --- | --- |
| <a id="fr-01"></a>FR-01 | 项目启动与后台自动接入，并保留显式管理命令：从本机 Chrome 指定 Profile 读取指定站点（可注册域名及其子域）的 Cookie，校验后加密登记为该站点会话的种子。只读取该站点，不复制完整 Profile。多个 Profile 均已登录时要求显式选择，不擅自选账号 | AC-01、AC-07 |
| <a id="fr-02"></a>FR-02 | 会话以“站点”为唯一标识（可注册域名，按固定版本的 Public Suffix List 计算）。已知平台由注册表把平台映射到站点和附属域；未知平台直接用链接的可注册域名。私网、IP 字面量和公共后缀本身不能登记 | AC-02、AC-08 |
| <a id="fr-03"></a>FR-03 | 容器内会话浏览器服务持有每个站点独立的持久 Profile，从种子初始化，低频保活并采集轮换后的 Cookie，写回持久存储。宿主 LaunchAgent 仅自动获取缺失或失效的来源，正常保活不依赖宿主进程、心跳或来源 TTL | AC-03、AC-04 |
| <a id="fr-04"></a>FR-04 | 路由由持久存储中的站点会话记录决定：所有在线解析必须走会话路线；未配置、撤销、需要重新登录均明确阻止解析。不依赖环境变量或启动脚本计算。账号路线不可用时返回稳定错误 `provider_session_not_ready`，**禁止降级为匿名** | AC-05 |
| <a id="fr-05"></a>FR-05 | 每个站点会话有明确状态：`seeded → verifying → ready → degraded → reseed_required`，以及 `revoked`。状态、最近刷新、最近验证和失败原因对管理员可见；进入 `reseed_required` 时发出告警，展示自动恢复状态或必要的登录动作 | AC-06 |
| <a id="fr-06"></a>FR-06 | 执行任务时，Runner 从会话代理处取得一次性、绑定本任务和站点的加密租约，任务结束即销毁。Runner 不挂载任何站点的常驻凭据 | AC-09 |
| <a id="fr-07"></a>FR-07 | 同一站点会话的会话浏览器、Runner 和 PO Token 使用同一条按站点配置的出口，保证 Cookie、令牌与请求 IP 属于同一身份 | AC-10 |
| <a id="fr-08"></a>FR-08 | 视频号元宝的动态请求头由会话浏览器按任务生成，不再使用宿主专用元宝浏览器和本机加密队列 | AC-11 |
| <a id="fr-09"></a>FR-09 | 删除被替代的宿主链路和多 Runner 拓扑，不保留兼容开关（清单见 Design §8） | AC-12 |
| <a id="fr-10"></a>FR-10 | 部署者可以撤销任一站点会话。撤销后在途任务可以完成，新任务立即得到 `provider_configuration_missing`，持久 Profile 被清除 | AC-07 |

## 6. 非功能需求（NFR）

| ID | 要求 |
| --- | --- |
| <a id="nfr-01"></a>NFR-01 无人值守 | 完成一次导入后，仅执行 `docker compose up`（或宿主重启、容器重建）即可在 120 s 内让已登记且仍有效的站点进入 `ready`。其间命中这些站点的请求等待就绪或返回 `provider_session_not_ready`，不走匿名 |
| <a id="nfr-02"></a>NFR-02 最小权限 | 会话浏览器没有数据库凭据；会话代理不运行浏览器、不访问外网；Runner 只拿单任务租约。浏览器只允许访问已登记站点及其附属域，经受控出口 |
| <a id="nfr-03"></a>NFR-03 秘密处理 | Cookie 只在宿主来源进程内存、加密存储、浏览器 Profile 卷和单任务租约中出现，不进入环境变量、API 响应、日志、队列或 Git |
| <a id="nfr-04"></a>NFR-04 平台友好 | 正常保活间隔 30～35 min；恢复验证按 60 s 起步、最高 30 min 的退避执行，429 至少等待 5 min，只访问登录验证所需轻量页面或接口；单站点执行并发为 1（沿用凭据租约） |
| <a id="nfr-05"></a>NFR-05 可移植 | 除 macOS 自动接入与显式导入命令外，所有组件为 Linux amd64／arm64 容器。自动获取首期支持 macOS Chrome，其他宿主在 Plan 中列为后续项 |
| <a id="nfr-06"></a>NFR-06 故障隔离 | 单站点会话失效不影响其他站点和本地文件功能；会话浏览器崩溃后由持久 Profile 自动恢复，不需要重新导入 |

## 7. 验收标准（AC）

| ID | 场景 | 必须满足 |
| --- | --- | --- |
| <a id="ac-01"></a>AC-01 导入 | 单 Profile 已登录、多 Profile 均已登录、未登录、钥匙串拒绝 | 分别为成功登记、要求显式选择、报告未登录、报告权限不足；只读取目标站点 Cookie |
| <a id="ac-02"></a>AC-02 站点识别 | `youtu.be` 短链、`m.youtube.com`、`v.douyin.com`、`old.reddit.com`、未知站点子域、私网地址、`co.uk` 这类公共后缀 | 前四类映射到已知平台站点；未知站点按可注册域名识别；最后两类拒绝登记 |
| <a id="ac-03"></a>AC-03 冷启动 | 导入完成后 `docker compose down && up`，宿主不运行任何本项目进程 | 120 s 内 YouTube 等已登记站点进入 `ready`，并完成一次 metadata、media 和完整文件验证 |
| <a id="ac-04"></a>AC-04 长期运行 | 连续 7 天不人工介入，期间重启宿主一次 | 会话保持 `ready`，或在平台真实吊销时进入 `reseed_required`；不存在因“来源过期”导致的失败 |
| <a id="ac-05"></a>AC-05 禁止降级 | 会话代理、会话浏览器分别停止；站点处于 `degraded`、`reseed_required` 或 `revoked` | 恢复期间得到 `provider_session_not_ready` 并在原意图期限内等待；无会话、撤销、需要重登返回 `provider_configuration_missing`；匿名／访客服务不在部署拓扑中 |
| <a id="ac-06"></a>AC-06 状态与告警 | 人为让平台吊销 Cookie | 在一次保活或执行后进入 `reseed_required`，状态页展示原因，告警只出现一次且不含秘密 |
| <a id="ac-07"></a>AC-07 重新导入与撤销 | 对 `ready`、`reseed_required` 站点重新导入；撤销站点 | 重新导入以新修订原子替换，旧租约失效；撤销后新任务被拒绝，Profile 卷中的站点目录被删除 |
| <a id="ac-08"></a>AC-08 未知平台 | 导入一个项目没有显式适配、但 yt-dlp 能处理且需要登录的站点 | 没有可验证登录探针时拒绝开放；补充探针并通过完整文件验收后才允许开放 |
| <a id="ac-09"></a>AC-09 租约 | 任务完成、取消、Runner 崩溃、租约被重放到另一任务 | 租约只能解密一次且绑定任务与站点，重放被拒绝；Runner 文件系统中没有残留 |
| <a id="ac-10"></a>AC-10 出口一致 | 为 YouTube 配置独立出口 | 浏览器保活、PO Token 请求和 Runner 下载的出口 IP 相同（以出口日志证明） |
| <a id="ac-11"></a>AC-11 视频号 | 从本机导入元宝登录态后解析视频号样本 | 在不存在宿主元宝目录和 LaunchAgent 的情况下完成解析与完整文件 |
| <a id="ac-12"></a>AC-12 删除 | 代码与部署检查 | Design §8 列出的模块、配置键、服务和文档不再存在，测试与 Compose 配置通过 |

真实平台验收逐平台进行：本期优先 YouTube、抖音各 3 个有权使用的样本，记录冷／热／重启、出口和完整文件结果。其他站点在登录探针、账号及样本齐备后验收；不得将未适配或未验证平台标记为可用。7 天观察单独记录，短时测试不代表长期稳定性。


### 启动自动接入补充验收（2026-09-29）

- AC-01 增补：无会话但 Chrome 已登录时，统一启动入口无需 seed import；多账号歧义、系统权限不足必须明确报告。
- AC-03 增补：后台定期运行及宿主用户登录后自动恢复；已有健康会话不会反复读取或覆盖。平台就绪由当前 broker RPC 判断。
- AC-07 增补：主动撤销不自动复活；并发撤销／健康恢复阻止迟到导入。同一份失效认证材料在进程重启后仍不会循环导入；新登录材料自动接入。
- 首期自动发现范围为 YouTube、抖音。其他平台必须先具备真实登录探针及媒体验收，不能用无效 Cookie 保留替代验证。

## 8. 已知风险

| 风险 | 说明与处理 |
| --- | --- |
| 同一会话在两处并用 | 部署者的 Chrome 与容器会话共享同一登录。Google 等平台会轮换 Cookie，两端并用可能使一端被登出。建议用 Chrome 中单独的 Profile（小号）导入；检测到轮换失效时进入 `reseed_required`，不静默重试 |
| 出口不一致 | 本机浏览器所在 IP 与容器出口不同，平台可能要求验证。导入后的首次验证会暴露该问题，状态页提示配置按站点出口 |
| 账号风险 | 自动化访问可能使账号被平台标记。保活限频、单并发，文档提示部署者使用有权使用的非主力账号 |
| 登录不可在容器内完成 | 一次性导入是本方案唯一的人工步骤，也是外部前提；无登录态时平台只报告部署前提缺失 |
