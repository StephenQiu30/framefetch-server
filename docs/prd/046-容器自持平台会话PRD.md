# 046 容器自持平台会话 PRD

日期：2026-09-28。状态：需求基线，已评审（2026-09-28），实现中；2026-09-28 修订：登录态来源由宿主导入命令改为本机 Chrome 扩展（§1.2 末行、FR-01、FR-11）。关联：[Design](../design/046-容器自持平台会话设计.md) · [Plan](../plan/046-容器自持平台会话Plan.md)。

本文取代 [044 PRD](044-开源部署无感解析PRD.md) 的 FR-17 与 AC-21（宿主浏览器会话自动复用），并取代 043（已删除，Git 历史可查） 中“来源由宿主进程取得和刷新”的部分。044 的公开访客路线（FR-04／FR-05）不在本文范围，保持不变。

## 1. 问题

### 1.1 现象

2026-09-28 本机冷启动后，YouTube、抖音解析频繁返回“平台要求额外验证”（`provider_verification_failed`）。

### 1.2 已核实的根因

| 事实 | 证据 |
| --- | --- |
| 匿名出口是机房 IP | 容器出口 34.104.254.238，AS396982 Google LLC（东京）；同一出口连续 3 个 YouTube 样本得到“Sign in to confirm you're not a bot”、“This video is unavailable”和成功各 1 次 |
| PO Token 与 JS 解密正常 | yt-dlp 2026.08.19、bgutil 1.3.2、node 24 均可用，失败不由组件缺失导致 |
| 账号路线依赖宿主进程 | Chrome 来源只由 `provider_startup start` 派生的宿主维护进程读取；它在 2026-09-25 后已退出，账号 Runner 中 `cookies.txt` 不存在 |
| 来源有效期只有 15 分钟 | `provider_source_host.SOURCE_VALID_FOR = 15 min`，宿主进程一停，数据库来源随即过期 |
| 路由由启动脚本在进程内计算 | 直接 `docker compose up` 时 API 的 `RUNNER_DEFAULT_ACCESS_POLICIES={}`，请求静默进入匿名路线 |
| 宿主读取需要钥匙串授权 | 从非交互进程启动得到 `browser_permission_denied`，只有用户 Terminal 能读取 |
| 宿主进程无法读取 Chrome 数据目录（修订依据） | 2026-09-28 实测：本机 macOS 对 Terminal 与 Claude 均返回 `Operation not permitted`（钥匙串本身可读）。只有 Chrome 自身能打开其数据目录，任何宿主导入命令都需要部署者额外授予“完全磁盘访问权限” |

结论：**账号会话的持有者是宿主机上的一个短命进程，而不是部署本身**。只要宿主进程不在，系统就退回匿名，匿名又撞上机房 IP 的 bot 墙。

### 1.3 目标

部署者**一次性**把本机 Chrome 连接到部署，此后 Chrome 中已登录的平台状态由扩展自动交给部署，会话失效时自动补种。之后 `docker compose up`、重启、重建容器、宿主重启都不需要人参与，已登记会话的平台**永不静默进入匿名模式**。同一机制适用于项目当前没有显式适配的平台。

## 2. 用户与成功条件

| 角色 | 成功条件 |
| --- | --- |
| 普通用户 | 只粘贴链接；已登记会话的平台稳定走账号路线，不看到 Cookie、授权或“额外验证”提示 |
| 部署者 | 只做两件一次性的事：在 Chrome 加载帧取扩展、在帧取中批准连接；此后标准 Compose 启动即恢复全部会话；会话失效且 Chrome 仍登录时自动补种，Chrome 也已退出登录时收到明确提示 |
| 管理员 | 平台状态页能看到每个会话的站点、状态、最近刷新和最近验证结果，看不到秘密 |

## 3. 范围

**定位**：自托管部署，会话属于部署、由部署管理员连接，只供部署者和其授权的使用者处理有权处理的内容。不适用于面向公众的托管服务，也不收集终端用户个人的登录态（市面调研：公开托管服务无法以运营方账号稳定服务公众，收集用户 Cookie 与浏览器扩展政策和账号安全相冲突）。

**范围内**：所有需要账号会话的平台，统一为一种“站点会话”机制，包括 YouTube、抖音（账号）、Reddit、视频号（元宝）、优酷、腾讯视频，以及任意部署者显式导入的站点（按可注册域名识别）。优酷、腾讯视频保留 032 的内容权益边界（账号可访问的完整非 DRM 单视频），该边界作为站点准入属性，不因机制统一而扩大到其他站点。

**范围外**：

- 公开访客路线（044 FR-04／FR-05，抖音游客等），不做改动。
- 在容器内完成账号密码登录、扫码或短信验证。登录态只来自部署者本机 Chrome 已有的登录。
- 按用户隔离的个人会话、多租户托管。
- 绕过 DRM、会员、付费、private 或地域权益。会话不扩大内容权限，AGENTS 的内容边界不变。
- 解决 yt-dlp 没有提取器的站点。会话只解决认证，不解决解析。

## 4. 用户流程

1. **一次性连接（部署者，本机）**：在 Chrome（建议专用 Profile）加载帧取扩展，在扩展中填写帧取地址并点击连接；浏览器打开帧取确认页，管理员批准。扩展此后按部署下发的同步计划，把已知平台（以及部署者在扩展中为当前页面启用的站点）的登录 Cookie 交给部署。
2. **容器接管**：会话浏览器服务从数据库取得种子，把它载入该站点独立的持久浏览器 Profile，验证登录有效后标记为可用，此后自行保持和刷新。
3. **日常使用**：`docker compose up` 即可。解析请求命中已登记站点时，一律走该站点的账号路线。
4. **失效处理**：平台吊销、账号退出或连续验证失败时，该站点进入“需要补种”状态，解析返回明确原因；Chrome 在运行且仍登录时，扩展在下一次同步（≤ 5 min）自动补种，无人参与。Chrome 也已退出登录时，状态页提示在 Chrome 中重新登录。系统不会退回匿名。

## 5. 功能需求（FR）

| ID | 需求 | 验收 |
| --- | --- | --- |
| <a id="fr-01"></a>FR-01 | 提供帧取 Chrome 扩展：以设备授权（扩展发起、管理员在帧取中批准）取得可吊销的设备令牌；只读取同步计划中站点的 Cookie 域，交给部署后由 broker 校验、加密登记为种子。扩展只安装在一个 Profile，即以该 Profile 的账号为准，不在多个账号间猜测。Cookie 不在扩展中持久化，不发往帧取以外的地址 | AC-01、AC-07 |
| <a id="fr-02"></a>FR-02 | 会话以“站点”为唯一标识（可注册域名，按固定版本的 Public Suffix List 计算）。已知平台由注册表把平台映射到站点和附属域；未知平台直接用链接的可注册域名。私网、IP 字面量和公共后缀本身不能登记 | AC-02、AC-08 |
| <a id="fr-03"></a>FR-03 | 容器内会话浏览器服务持有每个站点独立的持久 Profile，从种子初始化，低频保活并采集轮换后的 Cookie，写回持久存储。宿主进程、钥匙串和 LaunchAgent 都不参与运行期 | AC-03、AC-04 |
| <a id="fr-04"></a>FR-04 | 路由由持久存储中的站点会话记录决定：站点存在会话记录即必须走账号路线，不存在才走公开或访客路线。不依赖环境变量或启动脚本计算。账号路线不可用时返回稳定错误 `provider_session_not_ready`，**禁止降级为匿名** | AC-05 |
| <a id="fr-05"></a>FR-05 | 每个站点会话有明确状态：`seeded → verifying → ready → degraded → reseed_required`，以及 `revoked`。状态、最近刷新、最近验证和失败原因对管理员可见；进入 `reseed_required` 时发出告警，给出唯一处理动作 | AC-06 |
| <a id="fr-06"></a>FR-06 | 执行任务时，Runner 从会话代理处取得一次性、绑定本任务和站点的加密租约，任务结束即销毁。Runner 不挂载任何站点的常驻凭据 | AC-09 |
| <a id="fr-07"></a>FR-07 | 同一站点会话的会话浏览器、Runner 和 PO Token 使用同一条按站点配置的出口，保证 Cookie、令牌与请求 IP 属于同一身份 | AC-10 |
| <a id="fr-08"></a>FR-08 | 视频号元宝的动态请求头由会话浏览器按任务生成，不再使用宿主专用元宝浏览器和本机加密队列 | AC-11 |
| <a id="fr-09"></a>FR-09 | 删除被替代的宿主链路和多 Runner 拓扑，不保留兼容开关（清单见 Design §8） | AC-12 |
| <a id="fr-11"></a>FR-11 | 自动补种：同步计划把“已知平台尚无记录”和 `reseed_required` 的站点标为需要种子；扩展检测到变化即提交，无需人工。管理员撤销的站点不自动补回，只有部署者在扩展中显式重新启用后才提交 | AC-06、AC-07 |
| <a id="fr-10"></a>FR-10 | 部署者可以撤销任一站点会话。撤销后在途任务可以完成，新任务立即得到 `provider_session_not_ready`，持久 Profile 被清除 | AC-07 |

## 6. 非功能需求（NFR）

| ID | 要求 |
| --- | --- |
| <a id="nfr-01"></a>NFR-01 无人值守 | 完成一次导入后，仅执行 `docker compose up`（或宿主重启、容器重建）即可在 120 s 内让已登记且仍有效的站点进入 `ready`。其间命中这些站点的请求等待就绪或返回 `provider_session_not_ready`，不走匿名 |
| <a id="nfr-02"></a>NFR-02 最小权限 | 会话浏览器没有数据库凭据；会话代理不运行浏览器、不访问外网；Runner 只拿单任务租约。浏览器只允许访问已登记站点及其附属域，经受控出口 |
| <a id="nfr-03"></a>NFR-03 秘密处理 | Cookie 只在扩展内存、到帧取的请求体（回环地址或 HTTPS）、API 与 broker 的进程内存、加密存储、浏览器 Profile 卷和单任务租约中出现，不进入环境变量、API 响应、日志、队列或 Git；API 不持有加密密钥、不落盘 |
| <a id="nfr-04"></a>NFR-04 平台友好 | 保活频率每站点不超过每 30 min 一次，只访问首页级轻量页面；单站点执行并发为 1（沿用凭据租约） |
| <a id="nfr-05"></a>NFR-05 可移植 | 服务端组件为 Linux amd64／arm64 容器；登录态来源是任意桌面系统上的 Chrome（含 Chromium 内核浏览器），不依赖宿主权限或钥匙串 |
| <a id="nfr-06"></a>NFR-06 故障隔离 | 单站点会话失效不影响其他站点和公开路线；会话浏览器崩溃后由持久 Profile 自动恢复，不需要重新导入 |

## 7. 验收标准（AC）

| ID | 场景 | 必须满足 |
| --- | --- | --- |
| <a id="ac-01"></a>AC-01 连接与同步 | 设备授权未批准、过期、批准；令牌吊销；站点已登录、未登录；Cookie 含其他域 | 未批准或过期不发令牌；吊销后同步被拒；已登录站点登记为种子、未登录站点不登记；其他域 Cookie 被拒绝；请求与日志不含 Cookie 值 |
| <a id="ac-02"></a>AC-02 站点识别 | `youtu.be` 短链、`m.youtube.com`、`v.douyin.com`、`old.reddit.com`、未知站点子域、私网地址、`co.uk` 这类公共后缀 | 前四类映射到已知平台站点；未知站点按可注册域名识别；最后两类拒绝登记 |
| <a id="ac-03"></a>AC-03 冷启动 | 导入完成后 `docker compose down && up`，宿主不运行任何本项目进程 | 120 s 内 YouTube 等已登记站点进入 `ready`，并完成一次 metadata、media 和完整文件验证 |
| <a id="ac-04"></a>AC-04 长期运行 | 连续 7 天不人工介入，期间重启宿主一次 | 会话保持 `ready`，或在平台真实吊销时进入 `reseed_required`；不存在因“来源过期”导致的失败 |
| <a id="ac-05"></a>AC-05 禁止降级 | 会话代理、会话浏览器分别停止；站点处于 `degraded`、`reseed_required` 或 `revoked` | 命中该站点的请求全部得到 `provider_session_not_ready`，匿名 Runner 零请求（以出口日志证明） |
| <a id="ac-06"></a>AC-06 状态与自动补种 | 人为让平台吊销容器中的会话，Chrome 仍登录；再让 Chrome 也退出登录 | 前者进入 `reseed_required` 后 10 min 内自动补种并回到 `ready`；后者停留在 `reseed_required`，状态页提示在 Chrome 重新登录，告警只出现一次且不含秘密 |
| <a id="ac-07"></a>AC-07 补种与撤销 | 对 `ready`、`reseed_required` 站点提交新种子；撤销站点；撤销后在扩展中重新启用 | 新种子以新修订原子替换，旧租约失效；撤销后新任务被拒绝、Profile 目录被删除、扩展不再自动提交；重新启用后恢复 |
| <a id="ac-08"></a>AC-08 未知平台 | 导入一个项目没有显式适配、但 yt-dlp 能处理且需要登录的站点 | 无需改代码即可走账号路线并完成真实文件下载 |
| <a id="ac-09"></a>AC-09 租约 | 任务完成、取消、Runner 崩溃、租约被重放到另一任务 | 租约只能解密一次且绑定任务与站点，重放被拒绝；Runner 文件系统中没有残留 |
| <a id="ac-10"></a>AC-10 出口一致 | 为 YouTube 配置独立出口 | 浏览器保活、PO Token 请求和 Runner 下载的出口 IP 相同（以出口日志证明） |
| <a id="ac-11"></a>AC-11 视频号 | 扩展同步元宝登录态后解析视频号样本 | 在不存在宿主元宝目录和 LaunchAgent 的情况下完成解析与完整文件 |
| <a id="ac-12"></a>AC-12 删除 | 代码与部署检查 | Design §8 列出的模块、配置键、服务和文档不再存在，测试与 Compose 配置通过 |

真实平台验收：YouTube、抖音（账号）、Reddit、视频号、优酷、腾讯视频各至少 3 个有权使用的公开样本，另加一个未显式适配的站点；逐条记录冷／热／重启、出口和完整文件结果。

## 8. 已知风险

| 风险 | 说明与处理 |
| --- | --- |
| 同一会话在两处并用 | 部署者的 Chrome 与容器会话共享同一登录。Google 等平台会轮换 Cookie，两端并用可能使一端被登出。建议扩展装在 Chrome 单独的 Profile（小号）；容器端失效时自动补种 |
| 设备绑定会话 | Google 推行设备绑定会话凭据（DBSC），导出的 Cookie 可能很快失效。自动补种可兜底；若失效周期短于保活周期，以 E0／S9 实测为准调整，并依赖出口改善 |
| Chrome 未运行 | 扩展只在 Chrome 运行时同步；期间 `ready` 会话由容器保活，只有补种会延后 |
| 出口不一致 | 本机浏览器所在 IP 与容器出口不同，平台可能要求验证。导入后的首次验证会暴露该问题，状态页提示配置按站点出口 |
| 账号风险 | 自动化访问可能使账号被平台标记。保活限频、单并发，文档提示部署者使用有权使用的非主力账号 |
| 登录不可在容器内完成 | 加载扩展与批准连接是本方案仅有的人工步骤；Chrome 中没有登录态时平台只报告部署前提缺失 |

## 9. 未决项

- 视频号：容器浏览器仅凭元宝 Cookie 能否在页面中恢复 `userId`／`token`，由 Plan E0 实测；若不能，扩展需额外取得元宝页面的身份字段。
- 扩展首期以“加载已解压的扩展程序”安装，不上架 Chrome 应用商店。
