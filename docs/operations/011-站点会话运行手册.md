# 站点会话运行手册

账号平台使用部署会话，固定公开平台使用原生公开接口，两者复用同一个 Runner；失败不切换路线。站点注册不等于已通过验收。适用机制包括：YouTube、抖音账号、Reddit、视频号、优酷、腾讯视频，以及已实现登录验证探针的站点。设计见 [046](../design/046-容器自持平台会话设计.md)。只处理你有权处理的内容；会话不扩大会员、付费、私密或地域权益，DRM 始终拒绝。

## 1. 组成

| 服务 | 作用 | 持有 |
| --- | --- | --- |
| `session-broker` | 状态机、调度保活、签发单任务租约 | `SITE_SESSION_ENCRYPTION_KEY`、数据库连接 |
| `session-browser` | 每站点一个持久 Chromium Profile，验证、保活、采集轮换后的 Cookie | Profile 卷 `site_session_profiles` |
| `session-runner` | 执行 yt-dlp；每次操作在 tmpfs 写入 `0600` Cookie jar，结束即删 | 无常驻凭据 |

三者随 Compose 启动并独立维护已有会话。macOS `./start` 还安装自动接入 LaunchAgent，负责初次获取与真失效后的重新获取。

## 2. 配置

根目录 `.env`（生产用 `.env.prod`）：

```dotenv
SITE_SESSION_ENCRYPTION_KEY=<Fernet 密钥，稳定，不进 Git>
SITE_SESSION_RPC_SECRET=<至少 32 字节>        # 生产必填
SITE_SESSION_BROWSER_SECRET=<至少 32 字节>    # 生产必填
```

生成密钥：`python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`。密钥与数据库备份分开保管；丢失后旧会话无法解密，需要重新导入。

## 3. 启动自动接入

本机已完成平台登录后，从仓库根目录运行：

```bash
./start
```

系统先应用当前 SQL 并构建／启动业务容器，再读取已启用站点、加密导入、安装当前用户 LaunchAgent 并等待平台验证。每次启动通过真实 LaunchAgent 做一次来源权限检查，结果写入 access-status.json；普通定时轮次不重复读取健康会话的 Chrome。所有启用站点、公开平台探测、后台读取任一未就绪均返回非零；核心业务服务继续运行，保留真实失败状态，不切换访问路线。默认自动接入全部 11 个已登记会话站点；公开平台另外执行真实 metadata 启动探测。可在 `.env` 一次配置仅接入指定站点（指定后只处理所列站点）：

```dotenv
SITE_SESSION_SOURCE_SITES=["youtube.com","douyin.com"]
SITE_SESSION_SOURCE_PROFILES={"youtube.com":"Default","douyin.com":"Profile 2"}
SITE_SESSION_SOURCE_INTERVAL_SECONDS=60
```

没有配置 Profile 时，只有一个已登录候选才自动选择。首次成功接入后绑定 Profile；需要换账号时显式执行下方 import。取消某平台自动获取可从 sites 移除；这不会撤销已经导入的会话。

macOS 首次可能要求“完全磁盘访问权限”与“Chrome Safe Storage”钥匙串授权；后台 Python 与交互终端的权限可能不同，不能用终端可读推断后台可读。启动输出会给出需要授权的 Python 绝对路径；解释器升级更换路径后可能需要再次授权。缺少授权或平台登录时不会绕过；在 Chrome 登录／处理验证后，后台自动发现，无需重新执行导入命令。来源最多 3 路并发，每个子进程最多 60 秒，整轮最多 90 秒；到期终止进程组并标记 source_timeout，等待下一轮。前台启动不消费后台权限检查请求。

健康、验证中和临时故障的会话均由容器处理；后台只处理缺失或 reseed_required。同一被拒认证材料不会重复导入；主动 revoked 绝不自动恢复。明确更换来源或恢复撤销时才使用：

```bash
cd backend
uv run python -m app.workers.session.seed import --site youtube.com --profile Default
```

自动接入状态保存在 `~/Library/Application Support/FrameFetch/<环境路径标识>/source-status.json`（0600），包括扫描时间和安全状态码。注册项为 `~/Library/LaunchAgents/com.framefetch.session-source.<环境路径标识>.plist`，不含密码、Cookie、密钥；使用该项目虚拟环境解释器。代码／虚拟环境路径改变后重新执行 `./start`。修改检查间隔后同样重跑启动入口。

- `ready`：数据库记录健康，实际运行期准入由 broker 再确认。
- `imported_pending_verification`：已自动导入，等待探针。
- `awaiting_new_login`：Chrome 仍是同一份被拒认证材料，需在 Chrome 重新登录。
- `login_or_profile_required`：没有有效登录或多个 Profile 存在歧义。
- `chrome_permission_required`：后台读取受系统权限限制。
- `profile_change_requires_import`：配置与已绑定 Profile 不同，需显式换账号。
- `source_timeout`／`source_unavailable`：读取超时或依赖不可用，下一轮重试。

停止自动获取（容器已有会话继续维护）：

```bash
cd backend
uv run python -m app.workers.session.startup uninstall-source
```

## 4. 查看与撤销

```bash
uv run python -m app.workers.session.seed status
uv run python -m app.workers.session.seed revoke --site youtube.com
```

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| `seeded`／`verifying` | 等待或正在验证 | 等待；浏览器不可达时会自动重试 |
| `ready` | 可用 | — |
| `degraded` | 暂时不可用，按持久化的退避时间复验 | 等待下次检查；只有认证失效计入 3 次／24 h 门限，限流与网络故障不要求重新登录 |
| `reseed_required` | 已登出、被平台拒绝或密钥无法解密 | 自动寻找新登录；必要时在 Chrome 重新登录 |
| `revoked` | 已撤销 | 需要时重新导入 |

进入 `reseed_required` 时 broker 输出一条 WARNING 日志（`docker compose logs session-broker`）。撤销后新任务不再使用该会话，浏览器中的 Profile 会被删除；新请求明确拒绝，不回退公开路线。

## 5. 重启与换机

- macOS 重启或更新：`./start`。会话状态在 PostgreSQL，浏览器 Profile 在命名卷；卷丢失时 broker 用数据库中的最新 Cookie 自动重建。
- 换机：恢复 PostgreSQL（或连接同一库）并沿用同一 `SITE_SESSION_ENCRYPTION_KEY`，然后执行上面的启动命令。无需再导入，除非新出口触发平台验证。

## 6. 故障定位

| 现象 | 检查 |
| --- | --- |
| 解析返回 `provider_session_not_ready` | `seed status` 查看状态；`docker compose ps session-broker session-browser session-runner` |
| `seed import` 退出码 3 | 按提示授予完全磁盘访问权限，或在钥匙串弹窗选“始终允许” |
| 一直停在 `verifying` | `docker compose logs session-browser`；确认 egress-proxy 健康 |
| `reseed_required`，原因 `session_logged_out` | 平台已登出该会话：在 Chrome 重新登录，等待自动接入 |
| `degraded`，原因 `egress_challenged` | 出口被平台挑战；检查当前出口与平台验证要求，不要反复重新导入 |
| `reseed_required`，原因 `session_undecryptable` | 密钥被更换；恢复原密钥，或重新导入 |

平台验证、出口信誉和账号风险由第三方决定；容器健康只代表服务在运行，真实可用性以解析和完整文件结果为准（见 [007 固定 Provider 探针](007-固定Provider探针运行手册.md)）。

## 7. 自动维护和冷启动

session-broker 的健康检查在冷启动后等待“库中 ready 的会话完成实时验证”才报告就绪（上限 60 秒且锁存，验证不了的站点不会长期阻塞启动），因此 `up --wait` 返回时这些平台已可解析。探针持续无法确认登录（`login_probe_inconclusive`）超过 30 分钟，会话转为 `reseed_required`，由自动接入服务重新读取 Chrome；Chrome 中仍是同一份材料则等待新登录。

正常验证间隔 30～35 分钟；临时故障退避最高 30 分钟，429 至少 5 分钟。管理员在“平台目录 → 平台会话”查看下次检查与恢复动作。数据库 ready 在 broker／browser 重启后仍需重新验证，原解析任务在 180 秒期限内等待；正常保活期间站点持续可用，仅在保活失败或未能重新验证时撤回准入；Runner 对同一站点的并发操作最多排队 30 秒，而不是立即失败；未配置、撤销、需要重登则明确失败。Cookie 仍存在但探针无法确认登录，不会被显示为可用。

发布本版本需同时替换会话内部 RPC 的两端。匿名与访客服务已退出 Compose。运行中部署的旧容器应在确认无活跃任务后停止，不能保留为回退。

生产 `.env.prod` 必须显式设置两个会话 RPC Secret；本机默认开发值不能作为生产配置。配置中的浏览器、Runner、POT 出口映射需一致，变更后同时重建三方。
