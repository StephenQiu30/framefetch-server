# 站点会话运行手册

适用于需要登录态的平台：YouTube、抖音账号、Reddit、视频号、优酷、腾讯视频，以及任何管理员登录过的站点。设计见 [046](../design/046-容器自持平台会话设计.md)。只处理你有权处理的内容；会话不扩大会员、付费、私密或地域权益，DRM 始终拒绝。

## 1. 组成

| 服务 | 作用 | 持有 |
| --- | --- | --- |
| `session-broker` | 状态机、调度保活、签发单任务租约 | `SITE_SESSION_ENCRYPTION_KEY`、数据库连接 |
| `session-browser` | 每站点一个持久 Chromium Profile，验证、保活、采集轮换后的 Cookie | Profile 卷 `site_session_profiles` |
| `session-runner` | 执行 yt-dlp；每次操作在 tmpfs 写入 `0600` Cookie jar，结束即删 | 无常驻凭据 |

三者都随 `docker compose up` 启动，不需要任何宿主进程。

## 2. 配置

根目录 `.env`（生产用 `.env.prod`）：

```dotenv
SITE_SESSION_ENCRYPTION_KEY=<Fernet 密钥，稳定，不进 Git>
SITE_SESSION_RPC_SECRET=<至少 32 字节>        # 生产必填：Runner → broker
SITE_SESSION_BROWSER_SECRET=<至少 32 字节>    # 生产必填：broker → 浏览器
SITE_SESSION_ADMIN_SECRET=<至少 32 字节>      # 生产必填：API → broker（远程登录）
```

生成密钥：`python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`。密钥与数据库备份分开保管；丢失后旧会话无法解密，需要重新登录。

## 3. 登录（每个平台一次）

1. 以管理员登录帧取，打开「平台状态」页的“站点会话”区块。
2. 在需要的平台行点击“登录”；未适配的站点在输入框粘贴该站点任意 https 链接后点击“登录”。
3. 弹窗显示容器内会话浏览器的实时画面。在画面中操作：
   - 视频号：页面打开即显示微信二维码，用手机微信扫码并确认。
   - 抖音：可能先出现滑块，按住拖动完成后再扫码。
   - 其他平台：按页面提示扫码或输入账号密码（键盘输入会转发到画面）。
4. 画面检测到已登录后，“保存登录”按钮可用，点击保存。15 秒内状态从 `seeded` 变为 `ready`。

注意：

- 验证码、滑块、短信由你本人完成，系统不自动处理。
- 同一站点同时只能有一个登录；5 分钟无操作自动放弃。放弃或失败不会影响该站点原有的可用会话。
- 建议使用非主力账号。Google 可能拒绝在自动化浏览器中登录；YouTube 公开视频优先依赖出口质量，而不是账号。

## 4. 状态与撤销

「平台状态」页的“站点会话”列出每个平台的状态、最近验证与原因，并提供“重新登录”和“撤销”。

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| 未登录 | 该平台尚无会话 | 需要时登录 |
| `seeded`／`verifying` | 等待或正在验证 | 等待；浏览器不可达时会自动重试 |
| `ready` | 可用 | — |
| `degraded` | 最近一次保活或执行遇到认证类挑战，正在复验 | 等待；连续 3 次或持续 24 h 会转为 `reseed_required` |
| `reseed_required` | 已登出、被平台拒绝或密钥无法解密 | 重新登录 |
| `revoked` | 已撤销 | 需要时重新登录 |

进入 `reseed_required` 时 broker 输出一条 WARNING 日志（`docker compose logs session-broker`）。撤销后新任务不再使用该会话，浏览器中的 Profile 会被删除；站点回到公开路线。

## 5. 重启与换机

- 重启或更新：`docker compose --env-file .env -f docker-compose.yml up -d --build --wait`。会话状态在 PostgreSQL，浏览器 Profile 在命名卷；卷丢失时 broker 用数据库中的最新 Cookie 自动重建（依赖 localStorage 的视频号需重新登录）。
- 换机：恢复 PostgreSQL（或连接同一库）并沿用同一 `SITE_SESSION_ENCRYPTION_KEY`，然后执行上面的启动命令。无需重新登录，除非新出口触发平台验证。

## 6. 故障定位

| 现象 | 检查 |
| --- | --- |
| 解析返回 `provider_session_not_ready` | 「平台状态」页查看该站点：未登录则登录；其他状态见 §4；`docker compose ps session-broker session-browser session-runner` |
| 登录弹窗提示“会话浏览器暂时不可用” | `docker compose logs session-browser session-broker`；确认两者健康且 API 配置了 `SITE_SESSION_ADMIN_SECRET` |
| 保存时提示“没有得到可长期使用的登录 Cookie” | 页面登录了但平台只给了会话级 Cookie：重新登录并勾选“保持登录” |
| 一直停在 `verifying` | `docker compose logs session-browser`；确认 egress-proxy 健康 |
| `reseed_required`，原因 `session_logged_out` | 平台已登出该会话：重新登录 |
| `reseed_required`，原因 `egress_challenged` | 出口 IP 被平台挑战；更换受控出口后重新登录 |
| `reseed_required`，原因 `session_undecryptable` | 密钥被更换；恢复原密钥，或重新登录 |

平台验证、出口信誉和账号风险由第三方决定；容器健康只代表服务在运行，真实可用性以解析和完整文件结果为准（见 [007 固定 Provider 探针](007-固定Provider探针运行手册.md)）。
