# 站点会话运行手册

所有在线解析统一使用部署会话；首批验证重点是 YouTube、抖音。站点注册不等于已通过验收。适用机制包括：YouTube、抖音账号、Reddit、视频号、优酷、腾讯视频，以及已实现登录验证探针的站点。设计见 [046](../design/046-容器自持平台会话设计.md)。只处理你有权处理的内容；会话不扩大会员、付费、私密或地域权益，DRM 始终拒绝。

## 1. 组成

| 服务 | 作用 | 持有 |
| --- | --- | --- |
| `session-broker` | 状态机、调度保活、签发单任务租约 | `SITE_SESSION_ENCRYPTION_KEY`、数据库连接 |
| `session-browser` | 每站点一个持久 Chromium Profile，验证、保活、采集轮换后的 Cookie | Profile 卷 `site_session_profiles` |
| `session-runner` | 执行 yt-dlp；每次操作在 tmpfs 写入 `0600` Cookie jar，结束即删 | 无常驻凭据 |

三者都随 `docker compose up` 启动，不需要任何宿主进程。

## 2. 配置

根目录 `.env`（生产用 `.env.prod`）：

```dotenv
SITE_SESSION_ENCRYPTION_KEY=<Fernet 密钥，稳定，不进 Git>
SITE_SESSION_RPC_SECRET=<至少 32 字节>        # 生产必填
SITE_SESSION_BROWSER_SECRET=<至少 32 字节>    # 生产必填
```

生成密钥：`python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`。密钥与数据库备份分开保管；丢失后旧会话无法解密，需要重新导入。

## 3. 导入（每个账号一次）

在本机执行。首次使用前需要两项 macOS 授权，各一次：“系统设置 → 隐私与安全性 → 完全磁盘访问权限”中允许执行命令的应用（终端或 Claude），以及“Chrome Safe Storage”钥匙串弹窗选择“始终允许”。之后导入不再需要人工操作：

```bash
cd backend
uv run python -m app.workers.session.seed import --site youtube.com
```

- `--site` 可以是站点或任意链接主机：`youtu.be`、`v.douyin.com`、`weixin.qq.com`、`example.com` 都可以。
- 多个 Chrome Profile 都登录了该站点时，命令列出它们并退出，用 `--profile "Profile 2"` 指定。
- 建议在 Chrome 中为此单独建一个 Profile 并登录非主力账号。同一登录态在你的 Chrome 与部署中同时使用时，平台轮换 Cookie 可能让其中一端被登出。
- 视频号：在 Chrome 中登录腾讯元宝（`yuanbao.tencent.com`）后导入 `--site weixin.qq.com`。

退出码：`0` 成功；`2` 需要你处理（未登录、多账号、站点无效、未配置密钥）；`3` 系统拒绝读取（请在本机终端 App 运行并允许钥匙串）；`4` 数据库不可用或并发冲突（重试）。

导入后下一次扫描（通常 15 秒内）broker 会开始浏览器验证；成功时间取决于真实站点响应，状态从 `seeded` → `verifying` → `ready`。

## 4. 查看与撤销

```bash
uv run python -m app.workers.session.seed status
uv run python -m app.workers.session.seed revoke --site youtube.com
```

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| `seeded`／`verifying` | 等待或正在验证 | 等待；浏览器不可达时会自动重试 |
| `ready` | 可用 | — |
| `degraded` | 暂时不可用，按持久化的退避时间复验 | 等待下次检查；只有认证失效计入 3 次／24 h 门限，限流与网络故障不要求重新登录 |
| `reseed_required` | 已登出、被平台拒绝或密钥无法解密 | 重新导入 |
| `revoked` | 已撤销 | 需要时重新导入 |

进入 `reseed_required` 时 broker 输出一条 WARNING 日志（`docker compose logs session-broker`）。撤销后新任务不再使用该会话，浏览器中的 Profile 会被删除；新请求明确拒绝，不回退公开路线。

## 5. 重启与换机

- 重启或更新：`docker compose --env-file .env -f docker-compose.yml up -d --build --wait`。会话状态在 PostgreSQL，浏览器 Profile 在命名卷；卷丢失时 broker 用数据库中的最新 Cookie 自动重建。
- 换机：恢复 PostgreSQL（或连接同一库）并沿用同一 `SITE_SESSION_ENCRYPTION_KEY`，然后执行上面的启动命令。无需再导入，除非新出口触发平台验证。

## 6. 故障定位

| 现象 | 检查 |
| --- | --- |
| 解析返回 `provider_session_not_ready` | `seed status` 查看状态；`docker compose ps session-broker session-browser session-runner` |
| `seed import` 退出码 3 | 按提示授予完全磁盘访问权限，或在钥匙串弹窗选“始终允许” |
| 一直停在 `verifying` | `docker compose logs session-browser`；确认 egress-proxy 健康 |
| `reseed_required`，原因 `session_logged_out` | 平台已登出该会话：在 Chrome 重新登录后重新导入 |
| `degraded`，原因 `egress_challenged` | 出口被平台挑战；检查当前出口与平台验证要求，不要反复重新导入 |
| `reseed_required`，原因 `session_undecryptable` | 密钥被更换；恢复原密钥，或重新导入 |

平台验证、出口信誉和账号风险由第三方决定；容器健康只代表服务在运行，真实可用性以解析和完整文件结果为准（见 [007 固定 Provider 探针](007-固定Provider探针运行手册.md)）。

## 7. 自动维护和冷启动

正常验证间隔 30～35 分钟；临时故障退避最高 30 分钟，429 至少 5 分钟。管理员在“平台目录 → 平台会话”查看下次检查与恢复动作。数据库 ready 在 broker／browser 重启后仍需重新验证，原解析任务在 180 秒期限内等待；未配置、撤销、需要重登则明确失败。Cookie 仍存在但探针无法确认登录，不会被显示为可用。

发布本版本需同时替换会话内部 RPC 的两端。匿名与访客服务已退出 Compose。运行中部署的旧容器应在确认无活跃任务后停止，不能保留为回退。

生产 `.env.prod` 必须显式设置两个会话 RPC Secret；本机默认开发值不能作为生产配置。配置中的浏览器、Runner、POT 出口映射需一致，变更后同时重建三方。
