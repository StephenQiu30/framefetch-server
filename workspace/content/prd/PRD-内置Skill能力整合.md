## 1. 概述

用户在原有视频、剧本／文档页面选择 Skill，设置输出语言和提示词，提交任务并查看原有报告。优化发生在调用、内置方法和结果内容中，页面结构、导航、配置表单及报告阅读布局沿用任务开始前的产品。

此前把需求扩大为新创作工作台及新的十项能力页面，偏离了用户目标。本规格替代这些方案；其测试、截图和客户端包不能证明此次需求完成。产品不增加作品、材料库、母稿、版本编辑、预算确认或双源工作台。依据用户此前明确的“内容创作不是当前项目需要的能力”，旧写作入口保持停用，历史只读报告和导出保留；视频、剧本和分析报告恢复原页面，文章整理接原文档分析表单。

## 3. 背景与调研判断

用户需要在现有产品中获得更可靠的分析与整理结果。重新设计页面或增加 Skill 名称不能解决方法不完整、输入覆盖不足、结论缺乏依据、输出难以使用的问题。

任务开始前有七个顶层 Skill 入口、十五个专业模块及六种结果契约。这是兼容性和方法审计基线，不是必须重新开放所有写作能力或凑齐数量的验收目标。清退本轮过度设计时，保存历史报告与业务数据。

| 调研来源 | 可用方法 |
| --- | --- |
| [drama-skills 原著分析](https://github.com/zenstory-ai/drama-skills/blob/c2426e03c0e7722bebcc6a488b6658dc38c65ac3/skills/short-drama-novel-analyze/SKILL.md)、[审阅](https://github.com/zenstory-ai/drama-skills/blob/c2426e03c0e7722bebcc6a488b6658dc38c65ac3/skills/short-drama-review/SKILL.md)、[许可](https://github.com/zenstory-ai/drama-skills/blob/c2426e03c0e7722bebcc6a488b6658dc38c65ac3/LICENSE) | 人物目标、冲突、关系、行动因果、节奏及原文依据，用于分析已有材料 |
| [baoyu Markdown 整理](https://github.com/JimLiu/baoyu-skills/blob/1567581c26ec29f4216c6e6835415bf30343b0e3/skills/baoyu-format-markdown/SKILL.md)、[许可](https://github.com/JimLiu/baoyu-skills/blob/1567581c26ec29f4216c6e6835415bf30343b0e3/LICENSE) | 已有正文的层级、段落、引用、列表与排版，保护事实和原始内容 |
| [Agent Skills 规范](https://agentskills.io/specification) | 清晰声明方法、适用场景、资源与约束，工具权限由项目控制 |

专业模块应真正参与任务方法组装，有固定版本、来源、SHA 和许可；参考知识不等于执行第三方脚本或引入通用 Agent 平台。

## 4. 目标与成功标准

原页面继续可用；调用完整、稳定且不会因异常盲目重复推理；结果有实质分析／整理价值，依据可回查，文件可阅读。三端保留原 Skill 选择、语言、可编辑默认提示词、恢复默认、执行提示、状态和报告操作。

真实分析至少取得成功模型结果并核对内容。静态检查、目录数量、结构合法不能替代专业质量验收。暂无效率或准确率基线，不编造提升数字。

## 5. 用户任务

| 用户任务 | 期望结果 |
| --- | --- |
| 分析视频 | 从实际采样画面分析表达、结构和镜头，结论连接源时间与可见依据 |
| 拆解镜头／段落 | 清晰分段、实际时间和观察内容，区分可见信息与推测 |
| 分析剧本／原著 | 覆盖完整材料，分析人物目标、冲突、因果、节奏，问题有原文依据与具体建议 |
| 整理文章 | 按已有论点、论据和说明分组阅读，指出具体结构问题和缺项；原正文、事实、引文、链接和代码保持 |
| 整理公众号／小红书文档 | 分析已有内容的连续阅读与信息组织，说明各组作用、条件和缺项；保留作者表达及已有标签 |
| 阅读与导出 | 在原报告页读到有用结果，取得与保存结果一致的 MD／DOCX |

## 6. 价值

用户保留熟悉的使用方式，项目将专业方法嵌入现有分析链路。Skill 按任务加载所需模块并使用真实来源；报告说明发现、依据、影响和建议，避免空泛评价或机械包装。

## 7. 方案与需求

### 7.1 流程与边界

原视频或剧本／文档详情 → 原 Skill 选择器 → 原输出语言与可编辑提示词 → 原执行提示与提交 → 原状态／历史／报告 → 原导出。Skill 名称、说明、默认提示词和结果内容可以优化，不借此重排页面或加入新流程。

影视优先覆盖既有视频审阅、视频拆解、剧本分析。文章／公众号／小红书整理通过现有适合的表单与结果契约接入，不能把文章伪装为有场景剧本或带时长视频。依赖第二来源的工具只在实际材料可用时内部使用，不增加双源表单。剪辑、写稿、故事开发、图卡、图片生成和发布不在本轮范围。

### 7.2 功能需求

| 编号 | 要求 | 可验证条件 |
| --- | --- | --- |
| FR-01 页面保留 | 恢复任务开始前页面与表单 | 原布局、导航、语言、提示词编辑／重置、执行提示、报告操作逐项比对，无新工作台 |
| FR-02 正式调用 | 沿用原业务分析入口和生成契约 | 目录含 display_name、description、default_prompt、input_kinds、result_contract；请求支持 zh-CN／en-US、4000 字 custom_prompt |
| FR-03 完整来源 | 完整持久化正文和真实视频制品 | owner 校验；不用 preview 代替全文；原件／正文 SHA 和方法固定 |
| FR-04 Skill 方法 | 按任务加载内置方法及专业模块 | 实际组装可审计；模块有版本／来源／许可；无任意外部脚本执行 |
| FR-05 影视质量 | 分析完整材料或实际采样范围 | 人物／因果／冲突／节奏或镜头／结构有实质内容；发现有准确依据、影响与具体建议；未知范围明确 |
| FR-06 文档整理 | 已有文章和渠道文档的分组阅读与结构诊断 | 每组有结合实际论点／信息及渠道阅读的具体说明和可回查范围；缺项与限定明确，全文、事实、引文、链接、代码、表格及有意义空白保持；空泛分组、机械包装或截取开头不计完成。正文原样保留，不冒称重新排版或改写 |
| FR-07 结果兼容 | 保留原结果类型与阅读布局 | 使用适合任务的正式契约；历史按真实类型阅读，不将新旧结果强行转换 |
| FR-08 任务可靠 | 原查询、历史、取消及执行日志 | 幂等不重复创建；轮询不清空输入；取消与迟到保护；未知回执不自动重发 |
| FR-09 文件交付 | 原 MD／DOCX 导出使用已保存结果 | 实际字节可打开、正文与依据可理解；导出重做不再次推理 |
| FR-10 范围清退 | 撤本轮页面改造及创作域扩张 | 无新作品／母稿／版本／预算流程；原用户修改、历史报告和业务记录保持 |

### 7.3 非功能需求

| 编号 | 要求 |
| --- | --- |
| NFR-01 安全 | 来源、任务、报告校验 owner；材料作数据；凭据、全文及原始模型响应不进普通日志／Temporal History |
| NFR-02 资源 | 文件、正文、视频、抽帧与执行有实际上限；超限明确拒绝；保留原4000字提示词能力 |
| NFR-03 恢复 | 模型调用前持久登记；结果不明不自动重发；心跳／租约失败及时停止失去所有权的执行 |
| NFR-04 一致性 | 沿用 AnalysisJob／Run／Step／Report、事务 Outbox、Temporal 与报告发布；数据库验证所有权和迟到保护 |
| NFR-05 三端 | 正式 OpenAPI 生成 SDK，无平行 DTO、第二业务引擎或本地业务库；保护客户端既有改动 |
| NFR-06 体验 | 原布局在桌面、390px、亮暗色及键盘下可用；长文本、代码、表格和 SHA 无页面横向溢出 |
| NFR-07 质量诚实 | 不造引文、帧、事实、亲历或导演意图；抽样不代表全片运动／声音；结构合格不代表专业结论正确 |

## 8. 发布与验收

先恢复页面和正式调用，再优化 Skill 方法及输出，最后验证实际服务、浏览器与原生客户端。比对原表单行为、完整输入、成功模型报告、依据匹配、实质内容与文件；必要的显示缺陷修复可保留，不新增报告工作流。

执行计划分别记录工程检查、实际调用、内容质量和平台交付。失败模型任务保持失败及未知回执事实，不自动重发制造通过记录。恢复完成前，不宣称用户目标已完成。
