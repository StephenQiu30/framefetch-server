# 平台身份

平台账号材料的唯一来源是用户普通 Chrome Profile 中的扩展 `FrameFetch`。Cookie 身份通过 `chrome.cookies` 提供；视频号使用第 6 节的元宝 HTTP 解析，两者不得混用。不读取 Profile 文件、不访问钥匙串、不需要完全磁盘访问，也不解密 Cookie 或媒体。帧取自身的登录会话见[身份与会话](04-身份与会话.md)。

## 1. 组成

**扩展 `FrameFetch`（MV3，源码 `extension/`）**

- 权限：`cookies`、`alarms`、`declarativeNetRequestWithHostAccess`。`host_permissions` 只包含 Registry 中需要身份的平台所声明的 Cookie 域与页面身份 origin、`ws://127.0.0.1:<端口>/`，以及视频号所需的 `https://yuanbao.tencent.com/*`。不申请 `scripting`、广泛 `tabs`、历史、`webRequest` 或 `storage` 权限。
- manifest 带固定 `key` 以稳定扩展 ID；`minimum_chrome_version` 为 120。
- 事件监听器在 service worker 顶层同步注册；每次 worker 启动都检查并补建 alarm；连接初始化幂等。
- 面板只接受同扩展 popup 来源的“状态”“登录元宝”“重新连接”消息；返回版本、已认证的宿主连接、忙碌状态、登录材料是否可用与最近一次子因，不返回账号或 Cookie，不执行解析。“材料可用”只表示当前 Cookie 结构可用，账号是否有效由服务端在实际请求中判定。最近子因只存在 worker 内存。

**宿主 `cookie-source`（普通用户 LaunchAgent，不需要系统特权）**

- 只监听 `127.0.0.1:19101`，提供三个入口：面向扩展的 WebSocket `/extension`；面向 Runner 的 `POST /cookies`；面向 Runner 的固定 `POST /yuanbao-parse`。
- 不保存账号材料，不维护材料库；每次请求实时向扩展索取。

## 2. 扩展连接与认证

- 扩展 service worker 主动连接 `ws://127.0.0.1:<端口>/extension`，双方用配对密钥做**双向**挑战应答：各自发送随机 nonce，再以 `HMAC(配对密钥, 角色标签 ‖ 对方 nonce ‖ 己方 nonce)` 回应，角色标签区分 `server` 与 `extension`；原始密钥不在连接中传输。
- 扩展只有在验证服务端应答后才处理身份请求；cookie-source 同时校验 Origin（`chrome-extension://<固定 ID>`）与扩展应答。任一方认证失败或超时（5 秒）即断开，防止 cookie-source 停止期间其他本机进程抢占端口冒充服务端。
- 只绑定一个普通 Profile：已认证连接只能有一条，第二个连接不能替换已有身份。
- cookie-source 限制连接数、消息大小与并发请求，用 `request_id` 关联响应。
- **保活**：连接期间每 20 秒互发心跳；断开后立即重连，失败指数退避，上限 30 秒；`chrome.alarms` 每 30 秒检查连接，并在 `runtime.onStartup` 与 `runtime.onInstalled` 时触发连接。

## 3. Cookie 请求

1. Runner 调用 `POST /cookies {site, task_id, deadline}`。
2. cookie-source 经 WebSocket 发送 `{request_id, domains}`；`domains` 由服务端按 Registry 中该 site 的声明确定，扩展不接受任意域。
3. 扩展调用 `chrome.cookies.getAll({domain})`，按声明域规则（含子域）过滤；只读取非分区 Cookie，不读 CHIPS 分区 Cookie。
4. cookie-source 去除过期项，基于必要 Cookie 计算稳定 HMAC 作为材料摘要，返回 Cookie 与摘要。

- 单次请求上限 5 秒，并受操作 UTC 截止时间约束；截止后不再导出材料。
- 扩展未连接、超时或结果为空时返回 `identity_unavailable`，子因分别为 `extension_disconnected`、`extension_timeout`、`credential_missing`。不尝试其他读取方式。
- Cookie API 停滞或迟到时返回固定的 `extension_timeout`（不带 Cookie 字段）并释放串行读取占用；宿主只接受该固定超时响应，按请求关联与来源核对，忽略已取消或已过期请求的迟到响应。

## 4. 传递到 Runner

- 只有 Runner 持有访问 cookie-source 的 Bearer 令牌（类型化配置，与扩展配对密钥分开）；未认证请求返回 401。
- Runner 网络没有直接出网能力，经 egress-proxy 访问 cookie-source：squid 精确放行 `host.docker.internal` 与该端口的组合，规则位于私网／`.internal` 拒绝规则之前；其他私网、IP 字面量与宿主其他端口仍然拒绝。该路由由 squid 直连（`always_direct`），不经 Clash 或住宅上游；squid 不记录该路由的请求头与响应体。Runner 的身份客户端显式指定代理并禁止跟随重定向。
- egress-proxy 因此是敏感传输组件：明文 HTTP 下它能看到令牌与 Cookie。
- Runner 把 Cookie 写入本次操作的私有 tmpfs 文件，操作结束（含异常与取消）时删除；Runner 启动时清空整个 tmpfs 目录。
- Cookie 不进入业务数据库、队列、Temporal、API 响应、日志或 AI。不做密封、不维护会话代账本、不发租约。

## 5. 身份策略

| identity | 行为 |
| --- | --- |
| `required` | 每次进入阶梯前取得必要材料，只在声明的域与 origin 对应阶段使用；不可用则终止为 `identity_unavailable` |
| `prefer` | 扩展已连接且读到必要 Cookie 时每次注入；不可用时按匿名继续，记录 `identity_used=false` 与子因 |
| `optional` | 出现登录要求的证据后，在同一任务内注入并重试一次 |
| `none` | 永不注入；遇到登录要求直接终止为 `login_required` |

身份读取失败不反复重试。

## 6. 视频号元宝解析

视频号以 `official_share` 交付，`identity=required`、`identity_source=yuanbao_http`，复用 L3、Runner、统一下载与[冷启动矩阵](14-解析引擎.md#12-冷启动矩阵)的文件校验。视频号凭据不经通用 Cookie 入口导出；解析阶段不查询、创建或执行元宝页面。

1. **固定作品**：规范化 `https://weixin.qq.com/sph/<shortUri>`，读取对应的微信官方分享页与匿名 feed（不携带元宝身份）。明确的限制、删除或保护信号直接终止；扫码、封面与成功码不能冒充媒体。
2. **读取认证**：扩展在同一 Profile 中用 `chrome.cookies.get({url: parse_url, name})` 逐一读取非分区的 `hy_user`／`hy_token`，采用 Chrome 对该精确 URL 的 Cookie 优先级，核对来源、路径、有效期与认证头值，读取 token 后再次读取账号确认一致。不用 `getAll`（它按 Cookie 自身域名筛选权限，会隐藏 `.tencent.com` 父域认证 Cookie），也不扩大到腾讯父域或全部子域权限。读取受 5 秒与共享任务期限约束。
3. **发送请求**：只构造固定 `POST https://yuanbao.tencent.com/api/weixin/get_parse_result`，请求体 `{type: "video_channel_url", url: canonical_share_url, scene: 1}`，按官方 Web 2.87.2 协议发送 `Accept` 与 `X-WebVersion`；认证头 `X-ID`／`X-Token` 在扩展内由 Cookie 生成，`credentials=include`。不复制网页运行时，不加载远端脚本，不导出 Cookie 或认证头，不缓存凭据。该解析路径不触发网页的设备签名路径。
4. **Origin 规则**：扩展打包静态规则集 `yuanbao-http`，仅匹配本扩展发起的、完整解析 URL 的 POST／xmlhttprequest 请求，将 Origin 设为 `https://yuanbao.tencent.com`；不修改认证、Cookie 或响应头，不匹配网页、其他扩展、其他接口、查询串与方法。请求前检查规则集已启用，缺失权限或规则被禁用时在读取凭据前返回 `yuanbao_request_rule_unavailable`。规则只随扩展安装与升级加载，不创建动态规则，没有去掉来源校验的回退路径。参考 [declarativeNetRequest](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest)。
5. **响应约束**：请求最长 30 秒并受操作截止时间约束；使用 AbortController、`redirect=error` 与有界流读取。核对实际 Request 的方法、URL、请求体与 Response 的最终 URL、状态，只接受固定接口的对象 JSON；网络响应与返回捕获上限 4 MiB。畸形 JSON 或 UTF-8、超限、认证 token 回显与重定向一律终止，子因分别标识来源、大小、编码、JSON 与认证回显，不导出原始失败响应。监听账号 Cookie 变化并取消请求；由于该事件不覆盖父域 Cookie，请求前后都重新读取 Cookie 核对账号，允许同账号的正常 token 更新，不发布账号变化后的结果。迟到的 Cookie、HTTP 或流读取结果不得跨越已过期的协议响应继续执行。
6. **官方 feed**：解析结果只接受精确的微信官方 HTTPS 预览引用与唯一 `token`／`eid`，按官方规则解码一次；`wx_export_id` 不作为 feed 票据；只允许四个唯一、有界的数字呈现场景参数。向固定官方 feed 接口提交 `{baseReq: {generalToken: token}, exportId: eid}`。匿名分享、元宝与官方 feed 的非空标题与作者须一致；封面须为相同的 HTTPS 来源与路径（查询票据可变）。票据绑定与元数据对应不证明平台作品 ID 回显。
7. **交付**：拒绝明确的私密、付费、删除、试看或保护信号；只接受固定微信官方媒体域与路径的 clear 文件。候选经 ffprobe 核验后交给统一下载器。下载前重新解析，比较执行上下文中的账号摘要与语义规格；最终文件执行 ffprobe、SHA-256、候选时长一致性与严格全片解码，再发布 Artifact。候选时长只证明传输一致，不证明原作品完整性。

**宿主接口**：`POST /yuanbao-parse` 与扩展消息 `yuanbao_parse` 只接受 `wechat_channels`、规范化分享 URL、任务 ID 与 UTC 截止时间；宿主与扩展共享有效截止时间，取操作截止与“当前时间加 30 秒”中的较小值。沿用固定扩展 Origin、双向 HMAC、单连接、Runner 独占 Bearer 与受控代理；耗时解析不阻塞已认证心跳。JSON 消息上限 4 MiB 加 4 KiB，拒绝额外字段、重复字段、非有限数字与来源不匹配。宿主对 `yuanbao_http` 来源、固定 origin、平台与账号标识计算 HMAC 摘要后立即丢弃标识。Runner 的 `YuanbaoRequestIdentity` 只有摘要，没有 Cookie、token、Profile 或凭据文件；普通操作浏览器不接受该身份。

**响应适配**：`wechat_channels_response.py` 只适配捕获对象。成功码只接受整数 `0` 或字符串 `"0"`；拒绝布尔或浮点成功码、别名冲突、畸形地址或编码、控制字符与歧义的 token／eid。保护字段遍历上限 10,000 个节点，超限明确失败。缺少三方元数据对应、合法 clear 候选或候选文件时长时拒绝。

**登录**：首次登录或登录过期时，用户在扩展面板点击“登录元宝”，在打开的固定官网正常登录后关闭页面即可。解析不会自动打开页面，元宝页面不存在、被关闭或打开多个都不影响解析。

## 7. 安装与升级

- 扩展从主工作区的 `video-server/extension/` 加载（不从 git worktree 加载），只加载到日常登录的一个普通 Profile。
- `cookie-source install`：生成扩展配对密钥并与端口写入 `extension/config.local.json`（0600，当前用户所有，已 gitignore，不列入 `web_accessible_resources`，不进入日志或发行包）；按 Registry 生成 manifest 的 `host_permissions`（同样 gitignore，源码只保留模板）；安装 LaunchAgent。`install` 与测试检查这两个文件未被 Git 跟踪。
- 首次安装：在 `chrome://extensions` 开启开发者模式，加载已解压的扩展程序，选择上述目录。
- 升级：更新代码后运行一次 `install`，再在扩展页点“重新加载”；Chrome 中记录的加载路径与上述目录不一致时，通过“加载已解压的扩展程序”重新选择 `extension/`。`cookie-source check` 报告扩展连接状态与版本；Chrome 未运行或扩展未加载时显示 `connected=false`、`version=null`。
- 信任边界：配置文件能挡住网页与其他用户，挡不住同一用户下能读写项目目录的恶意进程。

## 8. 就绪条件

Chrome 正在运行，扩展已加载且已连接，目标平台已在 Chrome 中登录。服务重启后扩展自动重连；Chrome 未运行时，登录平台返回 `identity_unavailable`（`extension_disconnected`），匿名平台不受影响。
